# 比对与定位说明（任务 08：亚像素对齐与差异定位）

> 说明：本文档里的本机实测路径已占位化（`<LOCAL_APP_DIR>` = 本机软件安装目录，`<REPO>` = 仓库根），复现时请改成你自己的安装路径与仓库路径。

> 适用范围：PS / Krita 双端基准图的逐像素比对（tests/baselines/）。
> 相关代码：tools/align.py（对齐）、tools/diff_report.py（定位与判定）、tests/test_align.py（行为锁定）。
> 本文只讲「怎么用、为什么这样做、数字怎么读」；具体数字见 docs/验收报告/08-报告.md。

## 1. 一图流：先对齐，再比对，最后定位

~~~text
PS 图 (a) ─┐
           ├─ 1. 对齐：只平移 b，求 (dx,dy)        -> tools/align.py
Krita 图(b)┘
           ├─ 2. 比对：只比 Alpha、tol=2、分母 W*H  -> tools/imgdiff.diff_alpha
           ├─ 3. 判定：after ≤2% ok / ≤10% suspect / >10% fail
           └─ 4. 定位：把差异归到 模式+深度+亮度+对比度 + 差异外接框
~~~

为什么必须先对齐：两张图整体差 1~2 像素时，逐像素相减会沿着所有边缘形成一条「红边」，
差异比例可以从 1% 直接涨到 30% 以上——这时报出来的不是参数问题，而是「相机没摆正」。
对齐只负责把这一层噪声摘掉，**不允许**顺手改缩放/旋转（见第 3 节）。

## 2. 对齐算法（一句话 + 细节）

**一句话**：把两张图 Alpha > 10 的区域分别求「外接框中心」（默认）或「Alpha 加权质心」，
两个中心之差取整就是平移量 (dx, dy)；把 b 平移 (dx, dy)、画布外填 0，再比对。

### 2.1 接口

~~~python
from tools.align import align_translate

b_aligned, (dx, dy), meta = align_translate(a, b, tol=2, method="bbox")
# a, b 可以是文件路径 / PIL.Image / ndarray（二维 Alpha 或 HxWx4 RGBA）
# method: "bbox"（默认）| "centroid"
# 还支持两个关键字参数：noise_threshold=10、max_shift=None
~~~

meta 至少包含任务书要求的五个键，另有辅助字段：

| 字段 | 含义 |
|---|---|
| dx / dy | 实际应用的整数平移量（把 b 平移 (dx,dy) 即与 a 对齐） |
| method | 本次用的位置统计方法（bbox / centroid） |
| clipped_pixels | 原本 Alpha>0、平移后落到画布外被丢掉的像素数 |
| aligned_ratio | 对齐后的差异比例（= imgdiff 口径的 diff_ratio） |
| dx_raw / dy_raw | 未取整的浮点平移量（亚像素信息，仅记录、不应用） |
| diff_ratio_before | 对齐前的差异比例（必须与 after 一起给） |
| max_delta_before / max_delta_after | 对齐前 / 后的最大 Alpha 差值 |
| diff_bbox_before / diff_bbox_after | 差异像素的外接框（定位差异落在哪一块） |
| shift_limited | 是否因超过 max_shift 而放弃平移 |
| note | 无法定位 / 超上限时的中文说明 |

### 2.2 三个写死的细节

1. **先滤噪再定位**：Alpha ≤ noise_threshold（默认 10）的像素不参与外接框/质心计算。
   PNG 量化与抗锯齿会在边缘留下 1~9 的淡影，不滤掉就会把外接框撑大、对齐量偏移
   （任务书「常见问题」第 1 条）。低于阈值的淡影**不会**被丢掉，只是不参与「定位」。
2. **画布外填 0 并记账**：平移后落到画布外的部分不存在，按 Alpha=0 填充，
   clipped_pixels 只统计「原本非零」的像素（Alpha=0 的像素丢掉没有信息损失）。
   平移量大于画布时返回全 0 图，不抛异常。
3. **只做整数平移**：不插值、不缩放、不旋转。所以标题里的「亚像素」指的是
   **浮点中心差**（dx_raw/dy_raw 会落在 0.01~0.5 像素量级），应用的位移是取整后的整数。
   测试图（人工平移整数像素）能精确归零；真实基准图的亚像素偏差只能被记录，不能被插值抹平——
   这是任务的边界，不是实现缺陷。

### 2.3 bbox 与 centroid 怎么选

| 方法 | 依据 | 适合 | 已知退化 |
|---|---|---|---|
| bbox（默认） | 非零区域外接框的中心 | 笔迹集中、四边有透明边距的图 | **整张画布都不透明时外接框 = 全图，中心恒定，dx=dy=0**（本项目 7 对真实基准全是这种情况，见第 9 节） |
| centroid | Alpha>阈值的像素按 Alpha 值加权 | 有明显灰度分布差异、内容不对称的图 | 权重被大面积平坦区主导时几乎不动；本例真实基准对原始偏移仅 0.01~0.06 像素，取整后同样为 0 |

### 2.4 最大位移上限（max_shift）

默认 max_shift=10 像素：算出来的平移量超过上限时**不做平移**（dx=dy=0）并置
shift_limited=True。理由：不设上限时，两张无关的图也可能被「拉」到某个相似位置，
差异被吃小、假通过（任务书「常见问题」第 3 条说的过度收敛）。
上限只约束「平移多大」，不引入新的几何变换。工具层面可用 --max-shift -1 关闭，用于排查。

## 3. 为什么不做穷举搜索 / 缩放 / 旋转

使用者已明确否掉（任务书「硬性要求 1」与「已知现场」）：

1. **穷举搜索（互相关）会把真问题对齐掉**。只要允许在更大范围里找「最像」的位置，
   总能把差异比例压到一个更好看的数字，而那个数字已经不代表「同一个笔刷画出来像不像」。
2. **缩放/旋转同理，且更危险**：笔刷尺寸映射对不对，正是本阶段要验的东西；
   允许缩放就等于允许「用几何变换把尺寸错误吸收掉」。
3. **本任务只回答一个问题**：扣掉「整体错位」之后，剩下多少真实差异。
   整体错位本身要不要报？——dx/dy 会原样写进定位记录，读者自己看得到。

## 4. verdict 三档是什么意思

判定只看**对齐后**的差异比例（after = diff_pixels / (W*H)，diff 像素 = abs(ΔAlpha) > 2）：

| 档位 | 判据（写死） | 含义 | 后续用途 |
|---|---|---|---|
| ok | after ≤ 2% | 可以认为「扣掉错位后基本一致」 | 任务 15 全量验收的通过线 |
| suspect | 2% < after ≤ 10% | 有可见差异，需人看一眼是不是参数问题 | 人工抽查名单 |
| fail | after > 10% | 明显不一致（或跨引擎基线差异） | 阻断项 |

阈值常量：tools/diff_report.py 的 **THRESHOLD_OK = 0.02**、**THRESHOLD_SUSPECT = 0.10**。
这两个值是后续任务 09/15 的判据，**不许私下改**；要改必须改常量并在报告里写清理由。

注意：**verdict 不参与排序、不取平均**。一组里只要有一张 fail，这组就不能算过
（与任务 10 的口径一致：以最差图为准，不用平均值掩盖失败）。

## 5. 定位记录字段（固定）

~~~python
from tools.diff_report import build_record, RECORD_FIELDS

record = build_record(
    ps_png, krita_png,
    brush="定量测试v2", mode="正片叠底", depth=100,
    brightness=0.1, contrast=1.0,     # Krita 侧参数
    ps_brightness=0, ps_contrast=0,   # PS 侧原始参数
)
~~~

任务书要求的 12 个必填字段（顺序固定）：

| 字段 | 含义 |
|---|---|
| pair | 一对图的标识（默认「A 文件名 ↔ B 文件名」） |
| brush | 笔刷名或基准标识（baselines 场景用 PS 的标识段，如 定量测试v2） |
| mode | 纹理混合模式（中文名，与 docs/parameter-mapping.md 第 7 节一致） |
| depth | 纹理深度（PS 与 Krita 同值，1..100） |
| brightness | **Krita 侧**亮度（-1..1） |
| contrast | **Krita 侧**对比度（0..2） |
| dx / dy | 实际应用的平移量 |
| diff_ratio_before | 对齐前差异比例（0..1） |
| diff_ratio_after | 对齐后差异比例（0..1） |
| max_delta | 对齐后最大 Alpha 差值（0..255） |
| verdict | ok / suspect / fail |

附加字段（集合同样固定）：ps_brightness、ps_contrast、clipped_pixels、method、
max_delta_before、diff_bbox_after、shift_limited。

> 为什么 brightness/contrast 记 Krita 侧：定位表回答的是「设了这组 Krita 参数后，
> 和 PS 真值差多少」。PS 侧原始值放 ps_* 字段，两套单位绝不混进同一个字段。

## 6. PS ↔ Krita 怎么配对（四元组：模式 + 深度 + 亮度 + 对比度）

PS 与 Krita 的文件名规范不同（PS 把深度写进参数段，Krita 把深度写进标识段），
本工具用同一套解析函数把两侧都还原成四元组，再按**换算后相等**配对：

1. 模式名相同、深度相同；
2. 把 PS 的 (b, c) 按 convert.py 的换算公式映射到 Krita 域：
   - Brightness = round(0.10 - PS_b / 250, 2)，clamp [-1, 1]
   - Contrast = round(factor, 2)，clamp [0, 2]；
     factor = 1 + c/100（c<0）、1/(1-c/100)（0≤c<100）、c≥100 时取大值后夹到 2
   - 换算值必须与 Krita 侧登记值相等（容差 0.005，远小于网格间距）
3. **只允许同源纹理的 PS 图参与**：自动纹理A 用的是另一张 64×64 噪点纹理，
   与 Krita 历史真值图（research/测试结果2 同一张 research/测试用纹理.png）不同源，
   混进来比出来的差异全是纹理噪声（依据 docs/PS真值自动化说明.md 第 185 条）。

当前可配对组（详见报告第 4 节）：
正片叠底_d100 配 3 对、线性高度_d10 配 4 对，共 **7 对**。
未配上的 Krita 图与原因（参数在 PS 侧没有对应点）会列在配对表里，不猜、不补。

## 7. 怎么读定位表

~~~bash
"<LOCAL_APP_DIR>/anaconda3/envs/brushConverter/python.exe" tools/diff_report.py --markdown
~~~

表头 12 列：序号、组（模式_深度）、笔刷/标识、Krita（B,C）、PS（b,c）、平移 (dx,dy)、
越界像素、对齐前差异、对齐后差异、最大差值、差异外接框、verdict。

读法：

1. **先看「对齐前差异 → 对齐后差异」**：两列都必须在。只给 after 等于隐藏了「本来差多少」；
   after 明显小于 before 说明差异主要来自整体错位；两列几乎一样说明错位不是主因。
2. **再看 verdict**：ok 表示扣掉错位后一致；fail 要么是参数真不一致，要么是跨引擎基线差异
   （PS 与 Krita 两套引擎，同样 0/0 参数下基线差异本来就有 22%~100%，见报告遗留 1）。
3. **最后看「差异外接框」**：整幅 100×100 说明差异遍布全图（通常是引擎/参数层问题）；
   局限在某个角落说明可能是边缘裁切、抗锯齿或局部纹理错位。
4. 平移列带「超上限未平」标记时，表示算出来的位移超过 max_shift，本次没有平移——
   这时 before 与 after 相同是预期行为。

示例（第 1 行）：

~~~text
| 1 | 正片叠底_d100 | 定量测试v2 | (-0.1, 1) | (50, 0) | (0,0) | 0 | 73.13% | 73.13% | 24 | 0,0 100×100 | fail |
~~~

解读：PS 参数 (b=50, c=0) 换算成 Krita (B=-0.1, C=1) 后与 Krita 真值配对；
两张图外接框退化（全画布不透明）⇒ 不平移；扣掉对齐这一层后仍有 73.13% 的像素差超过 2 个灰度级，
最大差值 24，差异铺满全图 ⇒ fail。这是**跨引擎基线差异**，不是对齐失败。

## 9. 已知现象与限制（读数字前必看）

1. **全画布不透明的图，bbox 法退化为「不平移」**。tests/baselines 里 7 对基准图
   Alpha 几乎铺满整幅（非零像素 9533~10000/10000），外接框就是整张画布，两侧中心恒等，
   于是 dx=dy=0。质心法给出的原始偏移也只有 0.01~0.06 像素，取整后仍是 0。
   ⇒ 「对齐前后数字相同」在这 7 对上是**真实结果**，不是没生效。
2. **对齐能力的直接证据**：取真实 Krita 基准图，先清 6 像素边框（避免人为平移丢内容），
   再人为平移 (3,-2)/(-2,3)/(4,1)，6 对全部从 71%~80% 的差异降到 **0.00%**，
   还原平移量与人为平移严格相反（报告第 5 节）。
3. **PS↔Krita 的 7 对全部 fail 是预期**：任务 10 已实测「同一纹理、同样 0/0 参数下，
   Krita 算法复刻与 PS 真值的差异比例 22.36%~100.00%」——跨引擎基线差异本身超过 10% 判据。
   所以本报告里 fail 的含义是「两套引擎画出来不一样」，不是「对齐算法坏了」。
4. **整数平移、不做插值**：亚像素信息只记录在 dx_raw/dy_raw，不参与像素重采样。
5. **配对公式是 src 的副本**：diff_report.ps_to_krita_params() 复刻了
   src/brush_converter/convert.py::_texture_xml 的换算（本任务不许改 src/）。
   若将来任务 13 改了公式，配对表会立刻对不上——这是有意的「双保险」，需同步更新本文件第 6 节。
