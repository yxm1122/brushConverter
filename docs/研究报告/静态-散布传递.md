## 一、结论速览（先看这一段）

1. **散布域结构完全定位**：PS 把散布放在预设对象里一个 **0x50 字节的散布子对象**（预设对象 + 0xd8）里，7 个键各有偏移、类型与 clamp（§3.1）；
   新增发现：scatter 与 scatterDynamics.jitter **落在同一个 int32 槽位（+0x2c）**，后者覆盖前者（§3.2）。
2. **传递域结构定位到动态子结构一级**：opVr / prVr / mxVr / wtVr 是 4 个 **0x14 字节的动态子结构**，紧密排列在预设对象 +0x1e8 / +0x1fc / +0x210 / +0x224（§4.1）；
   每个子结构布局统一为 {bVTy:int32, fStp:int32, jitter:int32, 上界:int32, minimum:int32}（§3.3，读写两侧互证）。
   这些键的**序列化容器**是 4CC **brVr**（本任务新发现，ps_keys.json 的 125 条里没有，§3.4）。
3. **三条经验值**：ScatterValue=jitter/400 → **不成立（作为 PS 内部关系）**（§5.1）；PressureScatter 只是散布启用开关 → **成立**（§5.2）；bVTy 0=关/2=压力/6=初始方向 → **0 与 2 成立，6 不成立：6=Direction（笔迹方向），初始方向是 5**（§5.3，9 值枚举全部落实）。
4. **散布与间距**：静态证据支持**分别作用**（两个独立键、独立槽位、独立 clamp，读写链路中无相互乘除），但**画刷引擎（消费端）未定位**（§6）。
5. **压感曲线**：.rdata 内**没有** 256 点等距递增浮点表（0 命中）；唯一的 1024 点递增数列**无任何 rip 相对引用**；动态子结构里只有 4 个标量 + 1 个上界，**没有曲线对象/LUT 指针** ⇒ 倾向解析式，但求值点未定位，判 **无法判定**（§7）。
6. **一条框架级事实**：PS 的**参数 IO 层（描述符 ↔ 内存对象）集中在 0x141a8b4xx–0x141a96xxx 与 0x141ef1xxx–0x141efdxxx**，与**画刷引擎（算像素/摆笔迹）不在同一区域**；本任务把 IO 层钉死，引擎层只做到「未搜到」（§2.3 说明原因与边界）。

## 二、方法与它的边界

### 2.1 用的方法（与任务 21 同一套，可复现）

| 步骤 | 做法 | 本次实现 |
|---|---|---|
| ① 键名位置 | 在**非可执行区段**按 ASCII/UTF-16LE 扫键名，得字符串 VA | 自写 find_strings()（§10.1） |
| ② 引用点 | **只信指令级**：在 .text 里按机器码预筛 REX(48/4C)+8D/8B+ModRM(rip)+disp32，再**交给 capstone 逐条验证**有效地址是否等于目标 VA | 自写 find_refs()/rip_refs()（numpy 向量化，全 .text 一次扫完约 30 s） |
| ③ 函数归属 | 直接读 PE 的 **.pdata（RUNTIME_FUNCTION 表）** 当函数边界表；不做 Ghidra 自动分析 | 复用仓库 tools/re_pipeline/native_xref.py 的 FunctionTable（**只读导入，未修改**） |
| ④ 字段偏移/clamp | 对目标函数**整函数线性反汇编**（capstone），逐条读 [reg+disp] 读写、cmp/cmovg/test-jns 的 clamp、mov reg,imm32 的 4CC 键 | 自写 disasm()（§10.1） |
| ⑤ 4CC 键 | 键名不是字符串而是 **32 位立即数**（大端字符序，如 bVTy = 0x62565479），在 .text 里搜 mov r32,imm32 | 直接用 docs/数据/ps_keys.json 里任务 21 已登记的 imm32 站点，再反汇编验证 |
| ⑥ 类型交叉验证 | 描述符侧是 **double**（带 #Prc 等 unit tag）、内存对象侧是 **int32** | 用「取 double 紧跟 double→int 取整」指令对确认：0x142c4d220 → 0x140c532a0 → mov [rbx+N],eax |

### 2.2 为什么本任务**没有**用 Ghidra（也没有抢 Ghidra 锁）

- 上游硬事实：Ghidra 工程 ps_re 是**单实例共享资源**、**全量分析未跑完**（16/18 analyzer，卡 Constant Propagation）。
- 本次要回答的全部是「某函数第 N 条指令读了哪个偏移、clamp 是多少」这类**局部逐指令**问题；capstone 直接给的是**同一份机器码**，比等 Ghidra 反编译更快且不受分析状态影响。
- 因此本任务**没有开 JVM**，也就**没有抢** %TEMP%/brushconverter-team/locks/ghidra.lock（不存在未释放的锁问题）。
- **代价（如实登记）**：没有伪代码，跨函数的**数据流**只能靠「谁引用了这张表/这个字段」间接推，做不出 Ghidra 那种成片语义。§7 的无法判定正是这个代价。

### 2.3 方法边界（决定「未搜到」不写成「不存在」）

1. Ghidra 引用图对键名不可用（任务 20 实测：12 个地址 capstone 扫到 49 条引用指令，getReferencesTo 只有 1 条）→ 本文所有引用点来自**机器码扫描**，不来自 xref 图。
2. 只做**线性反汇编 + 单函数**，**没有**过程间数据流分析，**没有**扫间接调用（call [reg] / vtable）。
3. **全量分析未跑完** → 凡写「未定位 / 未搜到」，一律指**在当前分析状态（capstone 线性反汇编 + .pdata 边界 + 机器码预筛）下未搜到**，不表示 PS 里不存在。
4. 未运行 PS（无动态证据）：所有「内部公式」结论只能到「代码里有没有这个常量/这一步运算」的粒度。

## 三、散布域：结构、字段、clamp（主表）

### 3.1 散布子对象（预设对象 + 0xd8，大小 0x50）

**读取器**：0x141a930b0–0x141a932a7（503 B，.pdata 内）；由批量读函数 0x141a8f520 在 **0x141a8f899 lea rcx,[rsi+0xd8] + 0x141a8f8a3 call 0x141a930b0** 调用。
（rsi = 解析后的**预设对象**，见 §4.1；0x88 + 0x50 = 0xd8 正好接上笔尖动态子结构尾部，偏移链自洽。）

| # | 键名（形态） | 偏移 | 类型 | 取值/clamp（原文级证据） | 读取指令 |
|---:|---|---|---|---|---|
| 1 | useScatter（字符串 @0x148590788） | **+0x00** | bool(byte) | 无 clamp；**键缺失时按 (散布量≠0) 或 (count>1) 推出** | 0x141a93230 判有无 → 0x141a93252 取 bool 到 [rbx]；推出式 0x141a93272–0x141a93286 |
| 2 | Spcn（4CC 0x5370636e） | **+0x04** | int32 | **clamp [1, 1000]**（mov ebp,1；mov r14d,0x3e8；cmp eax,ebp/jge；cmp esi,r14d/cmovg） | 0x141a93136 判有无 → 0x141a9315d 取 double → 0x141a93162 取整 → 0x141a93187 mov [rbx+rax],esi（rax=4） |
| 3 | count（字符串 @0x1483e4ad4） | **+0x08** | int32 | **clamp [1, 10]**（mov ecx,0xa；cmp eax,ebp(1)/jl 走默认 1；cmp eax,ecx/cmovg ebp,ecx） | 0x141a93180 取键 id → 0x141a931b9 → 0x141a931c3–0x141a931d3 |
| 4 | bothAxes（字符串 @0x148590798） | **+0x0c** | bool(byte) | 无 clamp | 0x141a931e2 lea r8,[rbx+0xc] → 0x141a931ed call 0x142c4a8f0（取 bool） |
| 5 | countDynamics（字符串 @0x1485907a8） | **+0x10** | **dynamics 子结构（0x14）** | 见 §3.3 | 0x141a931f2 取键 id → 0x141a93201 lea rcx,[rbx+0x10] → 0x141a93208 call 0x141a93ea0 |
| 6 | scatterDynamics（字符串 @0x1485907b8） | **+0x24** | **dynamics 子结构（0x14）** | 见 §3.3（其 jitter 与本对象 **+0x2c** 同槽位） | 0x141a9320d 取键 id → 0x141a9321c lea rcx,[rbx+0x24] → 0x141a93223 call 0x141a93ea0 |
| 7 | scatter（字符串 @0x148590ae8） | **+0x2c** | int32 | **clamp [0, 1000]**（test eax,eax/jns；cmp eax,r14d(0x3e8)/cmovg） | 0x141a930d0 取键 id → 0x141a9310e 取 double → 0x141a93113 取整 → 0x141a93127 mov [rbx+0x2c],eax |

**结构自洽校验**：+0x24（scatterDynamics）+ 0x14 = +0x38，而 +0x2c（scatter）正落在 scatterDynamics 的第 3 个 dword 上 —— 见 §3.2。

**类型链证据**（为什么敢说描述符里 double、内存里 int）：0x141a9310e call 0x142c4d220（按 4CC 取 double）→ 0x141a93113 call 0x140c532a0（addsd 0.5 + 边界饱和 + cvttsd2si 的取整助手，函数体 64 B：0x140c532a0–0x140c532e0）→ 0x141a93127 mov [rbx+0x2c],eax。同一模式在 Spcn（0x141a9315d/0x141a93162）、count（0x141a931b9/0x141a931be）重复出现。

### 3.2 新发现：scatter 与 scatterDynamics.jitter 是**同一槽位的旧键/新键**

- 0x141a93127 mov dword ptr [rbx+0x2c], eax ← 键 **scatter**（@0x148590ae8，取整后 clamp[0,1000]）
- 0x141a9321c lea rcx,[rbx+0x24] + 0x141a93f97 mov dword ptr [rbx+8], eax ← 键 **scatterDynamics.jitter**，rbx+0x24+8 = **+0x2c 同一地址**
- 执行顺序：**先**读 scatter（0x141a93127），**后**读 scatterDynamics（0x141a93223）；后者只在嵌套对象里存在 jitter 子键时才写（0x141a93f46 判有无 → 0x141a93f97 写）。

⇒ 两者同时存在时 **scatterDynamics.jitter 覆盖 scatter**。与 ABR 实测吻合：scatter 键在 42 MB 样本里**一次都没出现**（ps_keys.json 该条 in_abr_samples=false），scatterDynamics 出现（in_abr_samples=true）。
⇒ **对矩阵/文档的含义**：scatter 与 scatterDynamics.jitter **不是两个独立参数**，而是「同一散布量槽位」的两种键名（旧/新），与任务 24 不一致清单 I-3「同一参数两行」同类。**本任务未改矩阵**，登记在 §11。

### 3.3 dynamics 子结构的统一布局（散布/传递/形状全部共用）

**读取器** 0x141a93ea0–0x141a9408d（493 B）：rcx=输出结构、rdx=描述符对象、r8d=外层键 id；先用 0x142c4f200 取出**嵌套描述符对象**（0x141a93ef7），再逐个 4CC/字符串键填 5 个字段。
**写入器** 0x141a96730–0x141a968ae（382 B）是严格对偶：先 0x142c55500 **新建类型 id = 0x62725672（brVr）的嵌套描述符**（0x141a9674d–0x141a96757），写入 5 个字段，再挂到父描述符（0x142c5c010 @0x141a9684c）。

| 偏移 | 字段 | 类型 | 取值方式 / clamp | 读侧证据 | 写侧证据 |
|---:|---|---|---|---|---|
| **+0x00** | bVTy（4CC 0x62565479，**整数字面量键**） | int32 | 无 clamp，直接取值；语义 = 控制源枚举（§5.3 的 0..8） | 0x141a93f0e mov edx,0x62565479 → 0x141a93f13 call 0x142c4e7c0 → 0x141a93f18 mov [rbx],eax | 0x141a96774 mov r8d,[rbx] → 0x141a96781 call 0x142c5b390 |
| **+0x04** | fStp（4CC 0x66537470） | int32 | 无 clamp | 0x141a93f2b mov edx,0x66537470 → 0x141a93f35 mov [rbx+4],eax | 0x141a9679d mov r8d,[rbx+4] → 0x141a967ab |
| **+0x08** | jitter（字符串 @0x148590ad4） | int32（描述符侧 **double**） | **clamp [0, 本结构+0xc]**：负数归 0（0x141a93f8a test/jns，0x141a93f8e mov eax,edi，edi=0）；上界 0x141a93f5e mov esi,[rbx+0xc] + 0x141a93f94 cmovg eax,esi | 0x141a93f46 判有无 → 0x141a93f72 lea rdx,"jitter" → 0x141a93f79 call 0x142c4d280（取 double）→ 0x141a93f7e mulsd/0x141a93f82 divsd → 0x141a93f86 cvttsd2si → 0x141a93f97 mov [rbx+8],eax | 0x141a967c7 cvtdq2pd([rbx+8]) → 0x141a967e0 mov r8d,0x23507263（unit = **#Prc**）→ 0x141a967f2 call 0x142c5ed90（写 double） |
| **+0x0c** | （无键名）**jitter 的 clamp 上界** | int32 | 只被**读**作上界；读写两侧都**不写**它 → **赋值点未定位**（§8-U1） | 0x141a93f5e、0x141a93f94 | 不存在 |
| **+0x10** | minimum（字符串 @0x1484c7750） | int32 | **clamp [0, 100]**（0x141a93fe8 mov ecx,0x64 + cmovg） | 0x141a93fab 判有无 → 0x141a93fd3 call 0x142c4d280 → 0x141a93fe0 cvttsd2si → 0x141a93ff4 mov [rbx+0x10],edi | 0x141a9680e cvtdq2pd([rbx+0x10]) → 0x141a96831 call 0x142c5ed90 |

**关键细节（对判定 §5.1 有用）**：jitter 读侧是 mulsd 紧跟 divsd，而 xmm6 是 **0x1483d7978 处的 double = 100.0**（0x141a93f52 movsd xmm6,[rip+0x6943a1e]）——乘 100 又除 100，**数学恒等**。同样的「×100 ÷100 恒等组」在 minimum（0x141a93fd8/0x141a93fdc）、minimumDiameter（0x141a93320/0x141a93324）、minimumRoundness（0x141a93448/0x141a9344c）反复出现 ⇒ **PS 在这条链路上没有任何有效换算**。

### 3.4 新发现：dynamics 的序列化容器是 4CC brVr

0x141a9674d mov edx, 0x62725672 → 0x141a96757 call 0x142c55500（新建描述符对象）。
0x62 0x72 0x56 0x72 = b r V r ⇒ **brVr**。写入器随后把该对象挂在父描述符的 esi 键下。
ps_keys.json 的 32 个 4CC 键里**没有 brVr**（有 Brsh、Brgh、BlnM…但无 brVr）⇒ 本任务新增一条键。
它解释了一件事：描述符里 opVr / prVr / szVr / mxVr / wtVr / scatterDynamics / countDynamics / angleDynamics / roundnessDynamics **都是「值 = 一个 brVr 类型子描述符」的容器键**，子描述符里才是 bVTy / fStp / jitter / minimum。

### 4.2 opVr / prVr 字段表（沿 §3.3 布局展开）

| 键（4CC） | 基址（预设对象） | bVTy | fStp | jitter | jitter 上界 | minimum |
|---|---:|---:|---:|---:|---:|---:|
| prVr（0x70725672，流量） | **+0x1e8** | +0x1e8 | +0x1ec | +0x1f0 | +0x1f4 | +0x1f8 |
| opVr（0x6f705672，不透明度） | **+0x1fc** | +0x1fc | +0x200 | +0x204 | +0x208 | +0x20c |

| wtVr（0x77745672） | +0x224 | +0x224 | +0x228 | +0x22c | +0x230 | +0x234 |

**类型与 clamp**：与 §3.3 同一份代码（同一读取器 0x141a93ea0），因此 bVTy/fStp = int32 无 clamp；jitter = int32（描述符 double，unit #Prc），clamp [0, 本结构+0xc]；minimum = int32 clamp [0,100]。
**没有找到** opVr/prVr 专属的额外字段（如不透明度上限）：这四个键的子结构只有上述 5 个 dword。

### 4.3 不透明度/流量**基值**（Opct / flow）：只到写出侧级别

| 键 | 出现点（4CC 立即数站点，来自 ps_keys.json） | 本任务读到的上下文 | 结论 |
|---|---|---|---|
| Opct（0x4f706374） | 0x140f01dc5、0x140f020e3、0x140f06ade、0x140f06af7 | 0x140f01d85 call 0x140efb620 取一个 word → 0x140f01db5 mulsd ×100.0 → 0x140f01dbd mulsd ×3.051757812e-05(=1/32768) → 0x140f01dcf call 0x142c59640（按 4CC 写 double）⇒ **把内部 16 位量归一化后写成描述符 double** | 属**ABR 4CC 笔尖描述符的写出侧**；**未定位**其内存对象偏移（§8-U2） |

## 五、三条经验值逐条复核

### 5.1 ScatterValue = jitter / 400 → **不成立（作为 PS 内部关系）；作为跨引擎标定「无法判定」**

**复核对象**：src/brush_converter/kpp/preset_xml.py:484-487（注释「PS jitter(0..1000%) → Krita ScatterValue(0..5.0=500%)」「实测锚点：PS 145% ≈ Krita 35%，系数 ≈ 1/4」；代码 set_internal("ScatterValue", f"{scatter_amount / 400.0:g}")）。

**证据 1（PS 侧量纲）**：scatter 槽位 clamp ** [0, 1000]**（0x141a93120 cmp eax,r14d，r14d=0x3e8），Spcn 是 **[1,1000]** —— 都是百分数，与 ABR 实测 jitter 的 0..533（docs/研究报告/abr-键实测.md:290）量纲一致。**PS 侧没有 0..5 这种量纲。**
**证据 2（PS 侧没有 400）**：把散布/传递链路的**全部 5 个函数**整函数反汇编（0x141a930b0、0x141a93ea0、0x141a96730、0x141a932b0、0x141a8f520 的 0x141a8f820–0x141a8fa30 段），**没有**任何 ÷400 / ×0.0025 / ×2.5 / ÷1000 的运算；jitter 的 double 换算只有 ×100.0 ÷100.0（恒等，0x141a93f7e / 0x141a93f82）。
**证据 3（全二进制常量普查）**：.rdata（50,608,082 B）里 400.0 只有 **float32×2 / double×9**，0.0025 只有 **float32×3 / double×2**，且这 11 处 float 双字里**没有任何一处被上述 5 个函数引用**（§10.3 可复现）。
**证据 4（Krita 侧量纲）**：docs/数据/krita_caps.json → ScatterValue {min:0, max:5, default:5}。

**判定**：
- 说它是「PS 内部换算」→ **不成立**：PS 参数层既没有 400，也没有 0..1000 → 0..5 的换算；jitter 到内存对象是**原值取整**（只有 ×100÷100 恒等）。
- 说它是「PS→Krita 的经验标定」→ **无法判定（静态不可判定）**：两端口径差 200 倍（1000/5），仓库取 400（源于 145%≈0.35 的单点锚点），**静态无法证明 400 比 200 或 250 更对**；只有 v0.3 用真图量测「同一 PS 散布量下实际笔迹离散半径」才能定标定系数。
- **顺带一条可用推论**：既然 PS 是 0..1000 百分数、Krita 是 0..5，**全量程线性映射应是 ÷200**（1000%→5.0）；仓库的 ÷400 相当于「PS 1000% 只到 Krita 2.5」，属**压缩一半**的标定。这条给 v0.3 当待验假设。

### 5.2 PressureScatter 只是散布启用开关 → **成立**（附一条必须一起看的限定）

**证据（Krita 侧）**：src/brush_converter/kpp/preset_xml.py:475-483 —— PressureScatter 被写成 true 表示散布选项启用，压感来源另由 ScatterSensor 承载；docs/数据/krita_caps.json 里 ScatterValue / Scattering/Amount / AxisX / AxisY 的 range 与它分开，PressureScatter 本身不在能力表的数值型参数里。

**证据（PS 侧，本任务新增部分）**：PS 把「散布是否生效」和「散布由什么驱动」**拆成两个独立字段**：
1. **启用位** = useScatter（散布子对象 +0x00，bool），**键缺失时 PS 自己推导**：
   0x141a93272 cmp dword ptr [rbx+0x2c],0 / jne → al=1（散布量≠0 即启用）；
   0x141a93278 cmp dword ptr [rbx+8],1 / jg → al=1（count>1 即启用）；0x141a93280 mov [rbx],al。
   ⇒ 「启用」在 PS 里确实只是一个**布尔位 + 推导式**，不承载任何压感语义。
2. **控制源** = scatterDynamics.bVTy（+0x24，int32，§5.3 的 0..8 枚举），bVTy==2 即 Pen Pressure。
   ⇒ 压感信息**不在** useScatter 里而在 bVTy 里；仓库 mapping.py:268（scatter_pressure = sct.get("bVTy")==2）与 preset_xml.py:479-480（ScatterSensor）正是照这个结构做的。

**判定：成立** —— PressureScatter 只承担「散布启用」这一位。**限定**：不能因此认为「PS 的散布没有压感」——压感在 bVTy；若只写 PressureScatter 而不写 ScatterSensor，Krita 侧会变成「散布恒定量、不随压感」，与 PS 观感不一致（v0.3 要验）。

**证据 A：控件名表（.rdata，9 条 $$$/BrushDynamics/... 本地化键，连续排列）**

| 名称键 VA | 名称 | 语义 |

**证据 B：枚举值绑定**（函数 0x141fac800–0x141facab1，689 B）：把 9 条字符串逐个 lea 出来取**本地化字符串对象**存进 9 个栈槽（0x141fac83f → [rbp+0x40]=Off、0x141fac85e → [rbp+0x20]=Fade、0x141fac87d → [rbp]=PenPressure、0x141fac89c → [rbp-0x20]=PenTilt、0x141fac8bb → [rbp-0x40]=StylusWheel、0x141fac8da → [rbp-0x60]=InitialDirection、0x141fac8f9 → [rbp-0x80]=Direction、0x141fac918 → [rsp+0x60]=Speed、0x141fac938 → [rsp+0x40]=Rotation），再遍历组合框条目做**指针级比较**，命中即赋枚举号：

## 六、散布与间距在消费端：相乘还是分别作用

**静态证据支持分别作用，但消费端函数未定位。**

**证据（结构层，硬）**：
1. 二者是**两个独立键、两个独立槽位**：Spcn（4CC 0x5370636e）→ 散布子对象 **+0x04**；散布量 → **+0x2c**（scatter / scatterDynamics.jitter）。
2. 有**各自的独立 clamp**：Spcn = [1,1000]（0x141a93169 / 0x141a93171），散布量 = [0,1000]（0x141a93118–0x141a93123）；**clamp 之间没有引用关系**。
3. 读侧（0x141a930b0）与写侧（0x141a8e060 一带）在填/取这两个字段之间**没有任何算术指令**：Spcn 只被 mov [rbx+4],esi 存下，散布量只被 mov [rbx+0x2c],eax 存下；**没有** spacing×scatter、spacing+scatter、有效间距=f(scatter) 这类合成。
4. 散布子对象**不含**合成后的间距字段：0x50 字节被 §3.1 的 7 个字段全部占满（0x10+0x14=0x24，0x24+0x14=0x38，0x38..0x4f 空 24 字节），没有留给有效步距的槽位。

**未做的部分（如实）**：**画刷引擎（把 stamp 摆到画布上的那段代码）没有定位**。尝试过的方法与结果：
- 以「预设对象的散布量绝对位移 +0x104(=0xd8+0x2c)、间距 +0xdc、count +0x108、scatterDynamics.bVTy +0xfc」为键，在 .text 里按 mod=10 的 [reg+disp32] 机器码扫描并逐条 capstone 校验：命中 583–14,216 条/键，绝大多数是**栈访问**（[rbp+0x104] 等），无法区分；**没有一个**能归到「读预设对象」的候选。原因：引擎里更可能是 lea reg,[obj+0xd8] 之后再 [reg+0x2c]（**小位移**），而 disp8 小位移在 136 MB 代码里无法用机器码预筛区分。
- ⇒ 按规矩写成：**在当前分析状态下未定位到散布/间距的消费端**；「分别作用」是**结构层结论**（字段独立、clamp 独立、链路无合成），**不是**已证实的引擎行为。

## 七、压感曲线：查表还是解析式

**倾向解析式；静态不足以判定，登记为「无法判定（未定位求值点）」。**

**证据 1（没有 256 点等距表）**：把 .rdata（50,608,082 B）当 float32 数组，用「斜率 1/255 的 256 点单调递增数列」滑窗匹配（容差 2e-3）⇒ **0 处命中**。同法匹配 1024 点（斜率 1/1023）⇒ 3 处命中，但地址 0x14a2ceaa8 / 0x14a2ceaac / 0x14a2ceab0 **相差 4 字节**，实际是**同一段长递增数列的 3 个重叠窗口**；对这 3 个地址做 rip 相对引用扫描 ⇒ **0 条代码引用**（§10.4 可复现）。
**证据 2（动态子结构里没有曲线对象/LUT 指针）**：散布/传递的每个子结构只有 {bVTy, fStp, jitter, 上界, minimum} 五个 **int32**（§3.3），**没有**指针字段、没有内嵌 float[256]、没有曲线句柄；读写两侧都只碰这 5 个 dword（0x141a93ea0 / 0x141a96730 全文可见）。
**证据 3（没有任何缩放因子）**：所有「描述符 double ↔ 内存 int」换算都是 ×100.0 ÷100.0 恒等（0x141a93f7e/0x141a93f82、0x141a93fd8/0x141a93fdc、0x141a93320/0x141a93324、0x141a93448/0x141a9344c），minimum 上界硬编码 100（0x141a93fe8 mov ecx,0x64）⇒ 参数层**不做任何曲线化/查表**。

**判定**：给定「参数层只有 minimum 一个标量 + bVTy 一个控制源」，PS 的「压感→值」最可能是**逐标记的解析式**（典型形如 v = min/100 + (1-min/100)·p），**而不是 256/1024 点查表**；但**求值点（消费端函数）未定位**，所以严格结论是 **无法判定**，具体形式留给 v0.3（§9）。
附一条排除性证据：任务书 §五 提示「曲线可能被内联成查表，先找 256/1024 常量表」——本任务按这条做了，**两张表都不存在/无引用**，因此可排除「PS 用一张 256/1024 点静态压感 LUT」这一形态。

### 10.1 基础工具（re26.py 节选，功能与完整版一致）

~~~python
import sys
sys.path.insert(0, r'<REPO>/tools/re_pipeline')
from pe_scan import PeImage
from native_xref import FunctionTable, read_sec
from capstone import Cs, CS_ARCH_X86, CS_MODE_64
from capstone.x86 import X86_OP_MEM, X86_REG_RIP

EXE = r'<LOCAL_APP_DIR>/PS2025/Adobe Photoshop 2025/Photoshop.exe'
pe = PeImage(EXE); ft = FunctionTable(pe)
MD = Cs(CS_ARCH_X86, CS_MODE_64); MD.detail = True
ZERO = bytes([0])

def cfunc(va):
    c = ft.containing(va)
    return (hex(c[0]), hex(c[1]), c[1]-c[0]) if c else None

def cstr(va, n=96):
    off = pe.va_to_offset(va)
    if off is None: return None
    with open(EXE,'rb') as f:
        f.seek(off); b = f.read(n)
    z = b.find(ZERO)
    return b[:z].decode('latin1') if 0 < z and all(0x20 <= c <= 0x7e for c in b[:z]) else None

def disasm(start_va, end_va=None):
    text, text_va = read_sec(pe, '.text')
    if end_va is None: end_va = ft.containing(start_va)[1]
    off = start_va - text_va
    out = []
    for ins in MD.disasm(text[off:off+end_va-start_va], start_va):
        note = ''
        for op in ins.operands:
            if op.type == X86_OP_MEM and op.mem.base == X86_REG_RIP:
                eff = ins.address + ins.size + op.mem.disp
                s = cstr(eff)
                note = '   ; "' + s + '" @' + hex(eff) if s else '   ; -> ' + hex(eff)
        out.append((ins.address, ins.mnemonic + ' ' + ins.op_str + note))
    return out
~~~

### 10.4 压感曲线查表扫描（§7 证据 1）

~~~python
def scan_lut(n, tol=2e-3):
    exp = (np.arange(n) / np.float32(n-1)).astype(np.float32)
    win = np.lib.stride_tricks.sliding_window_view(fa, n)
    m = (np.abs(win[:, -1] - 1.0) < tol) & (np.abs(win[:, 0]) < tol)
    return [int(i) for i in np.nonzero(m)[0] if np.all(np.abs(win[i] - exp) < tol)]
print(len(scan_lut(256)), len(scan_lut(1024)))   # 实测输出：0 3（3 处相差 4 字节 = 同一段）
~~~
