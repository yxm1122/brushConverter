### 0.3 本任务的两个方法性收获（后面反复用到）

1. **PS 的 4CC 键是长名的压缩形态，两者由一张 .rdata 注册表绑定**（§1，E2 直证）。这张表在 PS 文件偏移 `0x88ef360..0x88f6d40`，**1950 条**，每条 16 字节：`[4CC 倒序 u32][00000000][指向长名字符串的 VA(8B)]`，按长名字典序排列。
   → 有了它，`Wtdg`/`Nose`/`Rpt ` 这类「只在 .abr 里出现、代码里搜不到」的 4CC 才能被**确定**地绑回 PS 的字符串参数，而不是靠名字猜。
2. **同一支笔刷的结构体里并存两套键空间**：字符串键（`wetEdges`/`noise`/`useDualBrush`/`brushPoseAngle`…）与 4CC 键（`prVr`/`opVr`/`wtVr`/`mxVr`…）。证据：同一个函数 `0x141a8f520` 里，既有 4CC 立即数读取（`0x141a8f996: mov r8d,0x70725672`("prVr")、`0x141a8f9a4`("opVr")、`0x141a8f9c0`("wtVr")、`0x141a8f9ce`("mxVr")），也有字符串键读取（`0x141a8f9f5` 起读 `wetEdges`/`noise`/`repeat`），而两者写的都是**同一个对象**（基址 `rsi`，见 §2.2 反汇编）。

## 一、重大副产物：PS 4CC ↔ 长名注册表（1950 条）

### 1.1 表结构（E2）
- 位置：`Photoshop.exe` 文件偏移 `0x88ef360` … `0x88f6d40`（`.rdata`），条目 16 字节，共 **1950** 条。
- 条目格式（实测逐条验证：第 4..8 字节恒为 `00000000`，第 9..16 字节恒为指向 `.rdata` 内以 \0 结尾名字的 VA）：`u32 id（字符倒序存）` + `u32 0` + `u64 name_ptr`。
- 表按**长名**字典序排（前 3 条长名：`128BitFloatingPoint`/`16BitsPerPixel`/`1BitPerPixel`）。

### 1.2 与本任务四类相关的条目（逐条给地址，可直接复核）

| 条目文件偏移 | 4CC（正常字符序） | 指向的长名（读出原文） | 表项 VA（指向名字） |
|---|---|---|---|
| `0x88f6a70` | `Wtdg` | **`wetEdges`** | `0x1485908e0` |
| `0x88f3c60` | `Nose` | **`noise`** | `0x1483d054c` |
| `0x88f4e10` | `Rpt ` | **`repeat`** | `0x1485908ec` |

即：**`Wtdg` = wetEdges（湿边）、`Nose` = noise（噪点）、`Rpt ` = repeat（重复）**，三者都是 **bool**。这是本轮对第一轮「不映射」清单的**两处语义纠正**：

- 任务 21 报告（`docs/研究报告/ps-键名全集.md:158`）把 `Wtdg` 注为「宽度抖动」→ **不成立**，应为湿边（与 `docs/parameter-mapping.md:81` 一致）。
- 任务 23 矩阵把 `Nose` 注为「喷嘴（喷枪特性）」（`docs/参数矩阵.json` 中 `{"key":"Nose","semantics":"喷嘴（喷枪特性）"}`）→ **不成立**，应为**噪点**；`Rpt ` = 重复（不是「喷嘴」的第二个字段）。

### 1.3 顺带解决的一组别名（供任务 29 使用，E2）
同一张表还给出 25/91 个 ABR 4CC 键的长名，其中与 24-报告 I-3「一名两行」直接相关的有：

| 4CC | 长名 | 矩阵现状（`docs/参数矩阵.json`） |
|---|---|---|
| `Wtdg` | `wetEdges` | 两行，均「无对应」，未声明同参数（I-3 组 4） |
| `Nose` | `noise` | 两行：`Nose`「喷嘴（喷枪特性）」/ `noise`「噪点（喷枪特性）」→ **同一参数，语义写法还互相矛盾** |
| `Rpt ` | `repeat` | 两行：`Rpt `「重复（喷枪特性…）」/ `repeat`「重复（喷枪特性）」→ 同一参数 |
| `TxtC` | **`textureCoverage`** | `TxtC` 在矩阵/全集里被注为「纹理对比度」，与本表冲突（任务 21/23 的产物，本任务不改，登记见 §10-D-5） |

**全部 25 条 ABR 4CC → 长名（供任务 23/29 直接对照；上面 4 行是其中与本任务最相关的 4 条）**：

```text
Angl -> angle          BlnM -> blendMode      Brgh -> brightness    Brsh -> brushes
Cnt  -> count          Dmtr -> diameter       Flip -> flip          H    -> hue
Hrdn -> hardness       Idnt -> ID             Intr -> intersect     InvT -> invertTexture
Md   -> mode           Mnm  -> minimum        Nm   -> name          Nose -> noise
Opct -> opacity        Rndn -> roundness      Rpt  -> repeat        Smoo -> smooth
Spcn -> spacing        Strt -> start          TxtC -> textureCoverage   Txtr -> texture
Wtdg -> wetEdges
```

（> 这一段就是全部 25 条；完整 CSV（含表项文件偏移）由 §9 命令 4 现场打印。）

**明确边界**：66/91 个 ABR 键**不在**这张表里（例如 `dualBrush`、`brushProjection`、`useBrushPose`、`jitter`、`bVTy`、`clVr`、`fStp`、`flow`、`wtVr`…）。这些键 PS 直接以**长字符串**为键（`dualBrush` 等的字符串在 `.rdata` 键名池里，见 §3.2），也就是 **ABR 里写 4CC、PS 内部用长名**的映射只在「有 4CC 缩写的那一批」存在。

## 二、第①类：湿边（`Wtdg` / `wetEdges`）

### 2.1 结论（一句话）
**判「不可映射」**（Krita 5.3.3 无此能力，且语义上无可等价替代）；ABR 侧确实落盘（`Wtdg` bool，27/27 支样本都写了，值全 false）。

### 2.2 PS 侧定位（E1，逐条可复核）

| 项 | 值 | 证据 |
|---|---|---|
| 字符串键名 | `wetEdges` | `ps_keys.json` 该条 `form=string`；字符串 VA `0x1485908e0`（与 §1.2 的 4CC 表项互指） |
| 结构体偏移 | **`+0x292`**（"批量IO结构"，`type=bool`, `width=byte`） | 写点指令 `0x141a8f9f5`：`lea r8,[rsi+0x292]` / `mov byte ptr [r8],0` / `lea rdx,"wetEdges"` / `call 0x142c4a8f0` |
| 同结构体邻居 | `usePaintDynamics=+0x290`、`noise=+0x293`、`repeat=+0x294`、`useBrushSize=+0x295` | 同一函数内的连续读序列（下方反汇编） |
| 第二处写点 | `0x141a907bb`：`lea r8,[rbx+0x292]` / `mov byte ptr [r8],0` / `lea rdx,"wetEdges"` / `call 0x142c4a8f0` | 同上（另一份拷贝代码路径，基址 rbx） |
| 锁定标志 | `wetEdgesLock` `+0x442`（"笔刷预设标志块"） | `ps_keys.json` `offset_candidates`：store 指令 `0x141ef9714` `disp=0x442 base=rbx` |
| 键引用指令 | 8 条 | `0x141a8b67c` / `0x141a8e967` / `0x141a8fa0c` / `0x141a907d2` / `0x141ef18da` / `0x141ef2349` / `0x141ef973a` / `0x141efd1bf` |
| 所属函数（8 个不同函数，区间取自 PE `.pdata`） | `141a8b470-141a8b809`、`141a8e060-141a8ec55`、`141a8f520-141a8fe0e`、`141a90410-141a90b05`、`141ef15c0-141ef1ee3`、`141ef1f90-141ef2817`、`141ef92e0-141ef9ca6`、`141efd020-141efd80a` | `ps_keys.json` `evidence[].detail`（函数区间取自 PE `.pdata`） |
| 键消费者函数 | `0x142c90190` / `0x142c57a90` / `0x142c4a8f0` / `0x142c528d0` | 同上 |

**反汇编原文（`0x141a8f520` 内，三个 bool 连续读，这是我判「0x292/0x293/0x294 = wetEdges/noise/repeat」的直证）**：

```text
0x141a8f9f5  lea  r8, [rsi + 0x292]        ; &wetEdges
0x141a8f9fc  mov  byte ptr [r8], 0
0x141a8fa00  mov  rcx, qword ptr [rdi]
0x141a8fa03  test rcx, rcx
0x141a8fa06  je   0x141a8fdf1
0x141a8fa0c  lea  rdx, [rip + 0x6b00ecd]   ; "wetEdges"   (→ 0x1485908e0)
0x141a8fa13  call 0x142c4a8f0
0x141a8fa18  lea  r8, [rsi + 0x293]        ; &noise
0x141a8fa1f  mov  byte ptr [r8], 0
0x141a8fa2f  lea  rdx, [rip + 0x6940b16]   ; "noise"
0x141a8fa36  call 0x142c4a8f0
0x141a8fa3b  lea  r8, [rsi + 0x294]        ; &repeat
0x141a8fa42  mov  byte ptr [r8], 0
0x141a8fa52  lea  rdx, [rip + 0x6b00e93]   ; "repeat"
0x141a8fa59  call 0x142c4a8f0
```

> 读数助手 `0x142c4a8f0` 的形态（E1）：`mov rbx,r8` → `call 0x142c49f20` → `mov rdx,rbx` → `jmp qword ptr [rip+…]`（`[rcx+0x108]` 虚表槽）。即「取上下文 → 按键名把值写进调用方给的 out 指针」，与本行 `r8=&结构体字段` 的用法一致。**属观察推断（函数无符号名），但「写哪个偏移」是直证。**

### 2.3 ABR 侧落盘情况（E3，27 支样本实测）

命令见 §9-命令 2。结果：

- `Wtdg` 在 **27/27** 支预设的 `Brsh` 块里都写了（`abr_keys.json`：`count=79`、`type=bool`、`paths=["Brsh[].Wtdg (×79)"]`，6 个文件）；

### 2.4 Krita 侧能力核查（E4）

（1）**键级：没有这个键。** 对 Krita 安装目录 **410 个** `.dll/.exe` 全量扫描（§9-命令 3）：

```text
scanned files: 410
== wetEdges files: 0        （ASCII "wetEdges" / "wet_edges" / "WetEdges" 三种写法）
== Wetness  files: 0
```

（2）**「Krita 也有 Wet 相关选项」到底指什么 —— 已查清。** Krita 里带 Wet 字样的**只有 MyPaint 引擎的预设名/参数**，不是画笔选项开关：

- 文件：`<LOCAL_APP_DIR>\Krita (x64)\share\krita\paintoppresets\i)_Wet_Paint_Plus_(mypaint).myb`、`i)_Wet_Knife_Plus_(mypaint).myb`（`glob *Wet*.myb` 命中 2 个）；
- 其 `settings` 里的湿参数是 **MyPaint 的 smudge 家族**：`smudge`、`smudge_length`、`smudge_radius_log`、`smudge_transparency`、`smudge_length_multiplier`、`smudge_bucket`（类名证据：`lib\kritaplugins\kritamypaintop.dll` 内 `MyPaintSmudgeData`/`MyPaintSmudgeLengthData`/`MyPaintSmudgeRadiusLogData`/`MyPaintSmudgeTransparencyData`/`MyPaintSmudgeBucketData`… 实测串）。

（3）**语义差异点（判「不可映射」的依据，逐条具体）**：

| # | PS 湿边 | Krita「最近邻」 | 差异 |
|---|---|---|---|
| 1 | 在**一支笔画内部**，笔尖足迹的**边缘不透明度被提高**（颜料向边缘聚集，形成深色边/水彩边），中心反而可能更透 | MyPaint `smudge*`：笔刷**从画布采样已有颜色**再抹开（沾色/拖尾），改变的是「带入什么颜色」 | 作用对象不同：PS 改同一次落笔的 alpha 分布；Krita 改颜色来源与拖尾 |
| 2 | 是**布尔开关**，无强度参数（PS 侧 `wetEdges` 只有 `byte` 0/1，无配套 0..100 数值键） | `smudge_length`/`smudge_transparency` 是 0..1 连续量，无「开/关」语义 | 参数量纲与可调维度都不同 |
| 3 | 与**纹理/双重画笔无关**，纯像素累积效应 | `smudge` 家族**强依赖画布内容**（空白画布上无效果） | 同一笔刷在空白 vs 有底色的画布上结果不同，转换后必然走样 |

（4）**能力表引用**：`docs/数据/krita_caps.json` 的 `notes[0]` 原文：

> 「本表只收录「有源码依据」的键与范围；**Krita 明确没有对应实现的 PS 参数（湿边/混合/双笔刷/颜色动态等）不放进 params**，交叉验证见 docs/研究报告/krita-能力表.md。」

→ 即 `krita_caps.json` **没有** `wetEdges` 条目，且**明确说明这是「Krita 没有对应实现」而不是「漏登记」**。加上（1）的 410 文件实扫 0 命中，本条属于「Krita 侧不存在该能力」的**双证据**。

### 2.5 遗留的「可改造」候选（**不改变本轮结论**，交 v0.4 评估）
理论上可用 Krita 的 **masking brush + 环形（中空）子笔尖**近似「边缘加浓」：主笔尖照常画，mask 子笔尖用一圈环形遮罩把中心扣掉。**但**：① 该做法会同时改变笔刷的覆盖形状（不再等价于 PS 的实心+深边）；② masking brush 是 5.2 之后的新机制，Krita 版本门槛高；③ 未经任何像素验证。→ 本条**只是候选**，见 §7 待验清单 V-1-1。

### 3.3 `dBrush` / `dTips` 的真实身份：**不是参数，是描述符类名**（E1）
`ps_keys.json` 把 `dBrush`/`dTips` 放在「预设/元数据」组、`offset=null`，任务 23 矩阵把它们写成「动态笔刷元数据（预设元数据）」「未见类型证据」。本轮定位到它们的消费者是一个**按类名分派的工厂函数 `0x141a9f8a0`**：

```text
0x141a9f8d9  lea rcx, "computedBrush" ; call 0x142c90280 ; cmp esi,eax ; je → 0x142022ed0
0x141a9f8ed  lea rcx, "dBrush"        ; call 0x142c90280 ; cmp esi,eax ; je → 0x14254ad00
0x141a9f8fd  lea rcx, "dTips"         ; call 0x142c90280 ; cmp esi,eax ; je → 0x1425401b0
0x141a9f90d  lea rcx, "sampledBrush"  ; call 0x142c90280 ; cmp esi,eax ; jne → 0x141a9f9f8
```

`0x142c90280` 的行为（观察推断）：入参是类名字符串，返回该类的 32 位 id（`cmp esi,eax` 就是在比 id）。四个分支各调一个不同的构造器。
→ **`dBrush`/`dTips` 是「笔刷子对象的类名」（brush class id），不是一个可映射的画笔参数**；它们与主笔尖的 `computedBrush`/`sampledBrush` 同层级。建议任务 29 把矩阵这两行 `verdict: 未定` 改为「非参数（类标识）」——本任务不改矩阵。

### 3.6 「需改造」要改什么（4 条，逐条说清）

| # | 改造点 | 具体做法 | 风险/待验 |
|---|---|---|---|
| 1 | **子笔尖要变成一支完整 Krita 预设** | `dualBrush.Brsh` 的 `Dmtr/Hrdn/Angl/Rndn/Spcn/flipX/flipY` → 单独生成一支 Krita 预设（`brush_definition` 里给这些值），再作为 `MaskingBrush/Preset/...` 嵌入主预设 | Krita 掩码子预设是**整份预设**（含引擎/曲线），PS 的 dual brush 子笔尖**只有形状** → 需要给子预设补默认曲线 |
| 2 | **混合模式要查表** | `dualBrush.BlnM` → `MaskingBrush/MaskingCompositeOp`。PS 的 `BlnM` 枚举值与 Krita 合成算子 id **不是同一套**，必须建映射表（本轮**未**枚举取值，样本里 5 支的取值尚未展开） | 未知取值必须回退 + 告警，不许静默 |
| 3 | **尺寸关系要换算** | `dualBrush.Brsh.Dmtr / 主笔尖 Dmtr` → `MaskingBrush/MasterSizeCoeff` + `UseMasterSize=true` | PS 允许子笔尖比主笔尖大（样本子笔尖 Dmtr 到 1920）；Krita 掩码有最大尺寸限制（`KisImageConfig::maxMaskingBrushSize` 实测符号存在），**超限必须降级并告警** |
| 4 | **散布/数量语义不同，不能直搬** | `dualBrush.Cnt`/`Spcn`/`scatterDynamics`/`countDynamics` 在 PS 是「第二笔尖在每个 dab 内的重复次数与散布」；Krita masking brush **没有「Dab 内重复」概念**，只能在子预设里用 Krita 的 scatter（`ScatterValue`/`AxisX`/`AxisY`，见 `krita_caps.json` 条目 33/35/36）近似 | 转出来必然走样；建议：`Cnt`>1 时降级为「子预设 scatter+多次落点」或直接告警不转 |

**参考公式骨架（本轮只给关系，不给数值系数——系数必须 v0.3 实测标定）**：

```text
MaskingBrush/Enabled          = useDualBrush
MaskingBrush/Preset/<子预设>  = build_preset(Dmtr, Hrdn, Angl, Rndn, Spcn, flipX, flipY)
MaskingBrush/MasterSizeCoeff  = clamp(dualBrush.Brsh.Dmtr / main.Dmtr, 下限, 上限)   # 上下限待 v0.3 标定
MaskingBrush/UseMasterSize    = true
MaskingBrush/MaskingCompositeOp = TABLE[BlnM]        # 表待建；未知 → 回退 + 告警
子预设 ScatterValue           = f(dualBrush.scatterDynamics.jitter)   # f 待标定，禁止照抄 ÷400（那是主笔尖的经验系数）
```

> **为什么不能直接判「可映射」**：① 上表 4 条里有 3 条需要新建映射表/系数；② Krita masking brush 的正确性（是否真的等价于 PS 的第二笔尖调制）**没有任何像素证据**，只有键名证据。按铁律 19/20，只到「需改造」。

## 四、第③类：喷嘴（`Nose` / `Rpt `）——本轮最大的一处语义纠正

### 4.1 结论（一句话）
第一轮的「喷嘴（`Nose`/`Rpt `）」**读法不成立**：`Nose` = **噪点 noise**、`Rpt ` = **重复 repeat**（两者都是 bool、都落盘）。
拆成两个子结论：
- **`Nose`（噪点）→ 不可映射**（Krita 无噪点能力，410 文件实扫 0 命中）；
- **`Rpt `（重复）→ 需改造（候选映射到 Krita Airbrush）**，因为样本证据强烈指向「喷枪」，而 Krita 有 `PaintOpSettings/isAirbrushing` + `rate`；但「`Rpt ` = PS 喷枪开关」尚未直证，列 v0.3 待验。

### 4.2 证据链（三条独立证据同时指向同一结论）

**证据 A（E2，注册表直证）**：§1.2 的 4CC 表 `0x88f3c60 → "noise"`、`0x88f4e10 → "repeat"`。

**证据 B（E1，指令级）**：`Noise`/`Rpt` 在 PS 代码里另有 4CC 立即数读点（我独立重扫确认任务 21 的数字）：

```text
# 'Nose' = 0x4e6f7365，10 处 mov edx,imm32
0x143465f85  mov edx,0x4e6f7365 ; mov r8d,0x23507263("#Prc") ; call 0x142c5ed20
0x14347c724  mov edx,0x4e6f7365 ; call 0x142c4d220 ; movsd xmm1,[rip+..] ; comisd …
# 'Rpt ' = 0x52707420，3 处（1 处 mov ebx）
0x14346731a  mov ebx,0x52707420 ; jmp … ; (else) mov ebx,0x42636b67
# 'Wtdg' = 0x57746467：0 处（.text 内两种字节序都扫过）
```

→ `Nose` 与 `Rpt ` 在 PS 代码里**被当 4CC id 使用**（`0x142c4d220` 的行为是「按 u32 键做有序表查找」：`cmp dword ptr [rax+0x20], edx` + 红黑树式的左/右走，属观察推断）；`Wtdg` **在代码里一次都没有**，只在 `.abr`/注册表里出现——与任务 21「Wtdg 立即数扫不到」的结论一致，但现在有了注册表解释。

**证据 C（E3，样本共现，最直观）**：27 支样本里只有 2 支把这两个开关打开，且笔刷名字与开关一一对上：

| 文件 | 笔刷名 | `Nose` | `Rpt ` |
|---|---|---|---|
| `tests/测试用.abr` #2 | KYLE 终极炭笔 25 像素中等 2 | **true** | **true** |
| `tests/海怪笔刷…` #13 | 大怪兽-**喷枪**【用数位板】 | false | **true** |
| `tests/海怪笔刷…` #14 | **杂点**喷枪【用数位板】 | **true** | false |
| 其余 24 支 | — | false | false |

→ 「杂点」笔刷 = `Nose`（噪点）；「喷枪」笔刷 = `Rpt `（重复）。炭笔两个都开（炭笔既带颗粒又要连续堆积）也说得通。

### 4.3 PS 侧偏移/类型/消费者（E1）

| 键 | 类型/宽度 | 偏移 | 锁定标志 | 键引用指令 |
|---|---|---|---|---|
| `noise` | bool / byte | **`+0x293`**（批量IO结构） | `noiseLock +0x444` | 8 条（`0x141a8fa2f` 等，函数 `141a8f520-141a8fe0e`/`141ef92e0-141ef9ca6`/`141efd020-141efd80a`） |
| `repeat` | bool / byte | **`+0x294`**（批量IO结构） | `repeatLock +0x443` | 8 条（`0x141a8fa52` 等，同上三个函数） |
| `Nose`(4CC) | 数值（带 `#Prc` 单位）/ 也作 bool 落盘 | 未定 | — | 10 处立即数（见证据 B） |
| `Rpt `(4CC) | 落盘为 bool | 未定 | — | 3 处立即数 |

> ⚠️ **一处必须诚实登记的冲突**：ABR 里 `Nose` 是 **bool**（`abr_keys.json`: `type=bool`，样本值 `false/true`），但 PS 代码里有把它当**百分比数值**读的路径（`0x143465f85` 带 `"#Prc"` 单位；`0x143489f75` 读出后 `mulsd` 缩放）。两者是否同一字段的不同层（内部数值 → ABR 落盘压缩成开关），本轮**没有找到直证**，登记为待验 V-3-2。**不影响结论**（无论噪声是 bool 还是百分比，Krita 都没有对应能力）。

### 4.4 Krita 侧核查（E4）

| 能力 | Krita 5.3.3 实测 | 结论 |
|---|---|---|
| 噪点/noise | 410 文件内**无** `noise` 的画笔选项键（`Noise`/`noise` 在 `libkritalibpaintop.dll` 命中 0）；`krita_caps.json` 无条目 | `Nose` → **不可映射**（能力表未覆盖，且二进制实扫为 0；建议 22 补登一行「Krita 无噪点能力」显式化） |
| 重复/repeat | 只有 UI 控件名 `checkBoxRepeat`（`libkritalibpaintop.dll`），**无对应预设键** | `Rpt ` 的「重复」本身 → 不可映射 |
| 喷枪/Airbrush | **有**：`KisAirbrushOptionData`/`KisAirbrushOptionModel`/`KisAirbrushWidget`/`Ui_WdgAirbrush`（`libkritalibpaintop.dll`，250 条相关串）；序列化键 **`PaintOpSettings/isAirbrushing`** 与 **`PaintOpSettings/rate`**（同时在 `kritadefaultpaintops.dll`/`kritacolorsmudgepaintop.dll` 出现） | 若 `Rpt ` = PS 喷枪开关 → **可映射候选** |

**候选映射（需改造，待 v0.3 定语义）**：

```text
if Rpt == true:  PaintOpSettings/isAirbrushing = true
                 PaintOpSettings/rate          = g(PS 喷枪流量)   # g 未知：PS 侧 ABR 只落 bool，没有数值
```

### 4.5 「喷嘴」这个词从哪来、要不要保留
- PS 画笔预设里**没有**「喷嘴」这个可调项（ABR 里 `Nose`/`Rpt ` 都是 bool，没有喷嘴类型枚举、没有喷嘴图像引用；`sampledData` 才是图像数据，且在 `Brsh` 子笔尖里）。
- 第一轮把「喷枪特性」笼统写成「喷嘴」，是把 **Airbrush（喷枪）** 译成了「喷嘴」。→ **建议统一改称「喷枪/噪点」**，不要再写「喷嘴」（影响 `docs/parameter-mapping.md:82`、矩阵 `Nose` 行、`src/brush_converter/mapping.py:326-327` 的告警文案「喷嘴」——后者属 v0.4 才可改，见 §8）。

## 五、第④类：画笔姿态（`brushProjection` / `useBrushPose`）

### 5.1 结论（一句话）
拆成两条：
- **`useBrushPose`（及其 `pose` 子对象 4 个值 + 4 个 override）→ 需改造**：Krita 没有「姿态」概念，但有等效的**传感器**（`xtilt`/`ytilt`/`ascension`/`declination`/`rotation`）+ 旋转/圆度/大小曲线，可承接「倾斜驱动」这一半，**固定姿态值**则只能用「无传感器的常量值」近似。
- **`brushProjection` → 不可映射**：ABR 里只是一个 bool 开关、语义未能确定，Krita 无对应；登记待验。

### 5.2 PS 侧定位（E1，pose 子对象是一块连续结构）

### 5.5 「需改造」要改什么

| # | PS 侧 | → Krita 键 | 换算 | 风险 |
|---|---|---|---|---|
| 1 | `useBrushPose=true`（倾斜驱动笔尖） | `RotationSensor` = `ascension`（或 `xtilt`/`ytilt`）+ `RotationValue`/`RotationUseCurve=true` | `RotationValue` 是 0..1 坐标，UI 显示 ±180°：`value = (angle_deg + 180) / 360`（**待标定**） | Krita 的 `ascension/declination` 是「倾斜方向/倾角」两个量，PS 是 `TiltX/TiltY` 两个分量 → **两套表示要互转**（极坐标 ↔ 笛卡尔），本轮未验证换算精度 |
| 2 | `brushPoseTiltX/Y`（固定倾斜值） | 无直接对应；只能退化成「无传感器的常量」 | 无法表达「固定倾斜」——Krita 的倾斜只能来自真实设备 | **必须改造**：要么忽略（告警），要么改成「常量旋转/圆度」近似 |
| 3 | `brushPoseAngle/Pressure` + `overridePose*` | `<Id>Value` + 无 `<Id>Sensor`（即固定值） | `override=true` → 写常量值；`override=false` → 交给传感器 | PS 的 `Pressure=100` 是「姿态压力」，与 Krita 的 `pressure` 传感器**不是同一个量**，直接赋值会误伤大小/不透明度曲线 |
| 4 | `brushProjection=true` | — | 无 | **不可映射**（语义本身未定，见 §7 V-4-1） |
