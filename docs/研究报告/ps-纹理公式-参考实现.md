## 0. 一句话结论

## 3. 参考实现的像素层结构（任务 12 拟合结构，逐行落地）

```text
q = round(depth × 255 / 100)                        # 深度先按 8bit percentUnit 量化，0..255
p = 127.0                                            # 对比度中心（拟合值；不是 127.5）
k = K_TABLE[c] 或 contrast_factor(c)                 # 对比度因子表

C >= 0（顺序 M1：先亮度、后对比度；亮度步先截断）
    u = clip(p + (clip(t + b, 0, 255) - p) × k, 0, 255)
C <  0（顺序 M2：先对比度、后亮度）
    u = clip(clip(p + (t - p) × k, 0, 255) + b, 0, 255)

正片叠底   out = clip(255 + (u - 255) × q/255, 0, 255)
减去       out = clip(255 - u × q/255, 0, 255)
高度       out = clip(12 × q - u, 0, 255)
线性高度   out = clip(max((255 - u) × 12 × q / 255, 12 × q - u), 0, 255)

Alpha(0..1) = round(out) / 255                       # PS 输出是 8bit，参考实现同样量化
```

**对比度因子表**（取自 tests/baselines/ps/_work/lut_fit_result.json 的 params.k_fitted 原值）：

| PS 对比度 C | −50 | −25 | −10 | 0 | +10 | +25 | +50 | +75 | +100 |
|---|---|---|---|---|---|---|---|---|---|
| k（拟合表） | 0.502947 | 0.753296 | 0.900000 | 1.000000 | 1.111111 | 1.328681 | 2.000000 | 4.000000 | 1e6（二值化） |

表外取值回落到经验式 C<0 → 1+C/100、0≤C<100 → 1/(1−C/100)、C≥100 → 1e6（任务 12 的既定做法）。

**三处「不是 Krita」的关键差别**（tools/texture_mask.py 是 Krita 语义，混用会得到假结果）：

| 维度 | PS（本参考实现） | Krita（tools/texture_mask.py） |
|---|---|---|
| 对比度中心 | **127**（0..255 整数域） | 0.5（=127.5/255，浮点域） |
| 高度/线性高度权重 | **W = 12·q**（q=round(2.55d)） | **10·s**（s=round(strength·255)/255） |
| 深度进入方式的模式覆盖 | 乘/减：255+(u−255)s、255−us（向 255 插值） | 乘/减：src·dst·s（与上式仅 s=1 时同构） |

因此 tools/ps_texture_reference.py **不 import、不调用** tools/texture_mask.py；两者只在报告里做对照。

**接口与校验行为**（与 texture_mask.py 风格一致，但语义按 PS）：

- 输入输出：ps_mask(tex255, brightness, contrast, mode, depth) -> float32 ndarray，值域 0..1，纯函数，无文件 IO；
- tex255：0..255（越界 clip，NaN/Inf 抛 ValueError）；
- brightness/contrast：只接受范围内**整数**，**不 clamp**；范围外/小数/布尔/NaN 抛 ValueError（范围外无观测，拒绝比猜安全）；
- depth：任意实数，先 clamp 0..100，再 q=round(2.55·d)；
- mode：PS 运行期号与 Krita 号两套并收，未知号抛 NotImplementedError（消息带号）。

## 6. 结论：新参考实现是否更好、好多少

- **达标**：参考实现 0.01%（全量 201 张）、0.00%（18 张 4 模式子集），远低于 2% 判据。
- **比 legacy 好多少**：
  - 18 张子集：74.79% → 0.00%（差异像素 134,617 → 0），最大差值 235 → 1；
  - 全量 201 张：73.46% → 0.01%（738,262 → 108 个像素），最大差值 250 → 128（仅 C=100 边界）。
- **比 LUT 差在哪**：整体 0.01% vs 0.00%，差的正是那 108 个 C=100 二值化边界像素；LUT 因为直接存实测中位数所以没有这个边界效应。
  工程上参数化形态更可移植（可对 Krita 求逆），这也是任务 13 已选择的路。
- **与 legacy 的差距来源**：旧公式 round(0.10 − b/250, 2) 把 PS 亮度映射成 Krita 亮度，等价于无条件 −25.5 灰度再叠加对比度，
  中心也不是 127 → 即使 b=0、c=0 也整体偏移（正片叠底/减去恒等图 legacy 误差 98.75% 就是这么来的）。

## 7. 与 src 现状（任务 13 已转正）的对照

任务 13 已把 calibrated 公式设为默认（src/brush_converter/kpp/preset_xml.py 的 _TEXTURE_FORMULA_DEFAULT = "calibrated"，
旧公式可用 BRUSHCONVERTER_TEXTURE_FORMULA=legacy 回退）。两者的关系是：

1. **同一套拟合结构的两种表达**：src 的 calibrated 是「PS 前置掩版的闭式逆」——它把 PS 的 b/c 反解成 Krita 的
   Brightness/Contrast 两个参数，让 Krita 的掩码公式（亮度减法 + 中心 0.5 对比度）输出等于 PS 的前置掩版 u。
   本参考实现则直接按 PS 语义算 u 与合成。二者在**b/c 掩码层**一致：18 张表里 d100 的正片叠底/减去共 5 张，
   src calibrated 全为 0.00%（见 §4 表），说明转正后的映射在这些组合上与参考实现逐像素一致。
2. **覆盖范围差异（如实报告，不在本任务改 src）**：
   - src 的 _texture_contrast_factor() 把 C 夹在 **[−50, 100]**（preset_xml.py 第 270 行 c = max(-50.0, min(100.0, ps_contrast))），
     因此 PS 允许的 **C ∈ [−100, −50)** 在 src 里无法表达；本参考实现按 11A 观测覆盖到 −100（k=0，整幅压到中心）。
     这是移植侧的表达限制（任务 12 的拟合网格最负只到 −50），不是 PS 语义；若要覆盖需补拟合，属新任务。
   - 全链路 Alpha（含模式/深度合成）上，src calibrated 在 18 张合计 60.24%、legacy 74.79%。这个差异**不在 b/c 映射层**，
     而在 Krita 侧的模式/深度合成语义：
     - 高度/线性高度：Krita 权重是 10·s，PS 实测是 12·q，任务 12 §6.2 已明确记录并建议 strength ≈ 1.2×depth/100；
       src 目前仍写 strength = depth/100（preset_xml.py 的 _apply_texture），所以高度系差距大（表中 35%~100%）；
     - 乘/减且 depth<100：PS 律是 255+(u−255)s / 255−us（向 255 插值），而 tools/texture_mask.py 复刻的 Krita 乘/减是
       src·dst·s，两者只在 s=1 时同构 → depth<100 的乘/减图全部差异（100%）。
       注意：src·dst·s 这个式子在任务 07 只用 **s=1（depth 100%）** 的 Krita 真值图验证过；s<1 的乘/减语义没有 Krita 真值证据，
       因此本报告**不判定**是 src 的错还是 Krita 复刻的错，只登记为遗留（§9、§11），并建议用 Krita 实机深度<100 的乘/减真值图确认。
3. **结论**：本参考实现与 src 转正后的 b/c 掩码映射一致；两者在全链路 Alpha 上的剩余差异全部来自 Krita 侧模式/深度合成，
   属任务 12 §6/§7 已记录的表达限制，不在 11B 范围，**本任务不改 src**（团队规则）。

## 9. 已知不适用情形与局限（不许当「全覆盖」用）

1. **口径范围**：单笔尖铺满 100×100、纹理 scale=100%、画笔 300px/硬度 100%/间距 1000%、无传递/散布/平滑。
   本实现只覆盖「纹理值 → 亮度/对比度 → 模式合成 → 深度」这一层，不含笔划搭接、压力、动态与笔尖覆盖度（base 恒为 1）。
2. **输入形态**：ps_mask 吃的是**已折好的 8bit 纹理灰度值**；RGBA→灰度的整数公式与 alpha 合成属于 Krita 复刻侧
   （tools/texture_mask.py::texture_mask_from_rgba），不在本模块。PS 侧纹理位图的折灰规则本轮未单独实测。
3. **版本锁定**：只对 Photoshop 2025（26.9.0.15）有效；换版本必须整批重出基准。
4. **C=+100 二值化边界**：数学上是无穷大，参考实现用 1e6 逼近，边界像素可能整体翻转一个 8bit 级（最大差 128）；
   全量核验的 108 个差异像素全部来自这里。可接受，但必须写进文档（同任务 12 §5.4）。
5. **高度/线性高度高深度饱和**：12q > 255 后整张饱和（d≥~7 起开始全 255），这些深度没有曲线信息可核验（任务 12 §7.4）。
6. **模式覆盖只有 4 个**：hardMix / linearDodge 的运行期模式号 11A 未测（§8.5），本实现按「未知号抛错」处理，不猜。
7. **像素层来源不是逆向**：本实现全量误差 0.01% 说明它与真值一致，但**不能**据此反推「PS 内部就是这么算的」——
   11A 的像素消费端仍未定位（§5.1）。若未来装上 x64dbg 拿到真硬件断点，可能发现等价但形式不同的实现。
8. **最小深度（minimumDepth）归一化**（11A §3.6）未纳入：它可能只影响 UI/预设回写，是否影响像素未验证。
9. **与 Krita 全链路不可直接互换**：本模块是 PS 侧参考实现，转成 Krita 参数要重新求逆（任务 13 已做 b/c 部分）；
   深度/模式的 Krita 表达限制见 §7.2。
