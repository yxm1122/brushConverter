## 0. 一句话结论

**在 depth=100、scale=100% 的纹理掩码层上，PS 与 Krita 逐像素完全一致（0/10000）**，因为转换链给 multiply 开了
`UseSoftTexturing=true`，恰好抵消了两侧「透明端是 255 还是 0」的语义差；
**multiply 的缩小（50%）准（mean|ΔR|=0.05–0.50，max 1）；放大（150%/200%）只判「部分」**（multiply d100：15.12/22.53 灰度级，
max 91/93），原因是**重采样口径不同**（相对残差在 S=150 固定 22.2–22.3%、S=200 固定 32.4%，与 depth 无关）；
**深度：multiply 准（d10/d60 均为 0.00，逐像素相同），linearHeight 不准**（d10：mean|ΔR|=43.31、max=52、95.36% 像素相差），
偏差**精确等于 2q**（q=round(2.55d)=26，2q=52），根因是高度系权重 **PS W=12 vs Krita W=10**，不是 8-bit 量化（两侧 q 完全相同）。

### 2.2 为什么 d100 的 2×2 表是退化的（方法学要点，必须写明）

multiply 在 depth=100 时 PS 的 8bit 量化深度 `q = round(2.55×100) = 255`，于是 PS 公式里的
「透明端补偿项」`255×(1−s) = 0`（s=q/255=1）。这一项一旦为 0：

- PS 的 `out = 255 + (u−255)·s` 退化为 `out = u`；
- Krita 的 `out = u·s` 也退化为 `out = u`；
- 两侧**机制不同但取值相同**，(a)(b)(c) 必然全 0。

所以「d100 全 0」**不能**解读为「两侧引擎本来就一致」；真正的引擎差要 d<100 才暴露（见 2.3）。
同理 linearHeight 在 d100 两侧都饱和成 255，四格全 0 没有任何信息量。

**归因读法**：

1. (a) 引擎/几何差 = 常数 `255(1−s)`（229 / 102），std=0.00、偏离常数最大值=0.00（见 §2.5 结构方程核验）——
   这是「PS 的 alpha 合成以 255（不透明）为透明端，Krita 的 multiply 直接乘掩码」这一语义差的精确值；
2. (b) 换算带来的变化 = **同一个常数的反面**（−229 / −102），来源是转换链对 multiply 写入的
   `UseSoftTexturing=true`（`Alpha_soft = Alpha_hard + 255(1−s)`，Krita 侧报告 §10.2 已实测该公式）；
3. (c) 端到端差 = **0.00%** —— 换算恰好把 (a) 完全抵消，这是转换链「刻意设计」的结果，不是巧合；
4. (d) 语义层与 (a) 数值一致（229.00 / 102.00），说明 (a) 的差异**完全来自公式**，与平铺/重采样/几何无关；
5. linearHeight：(b)=0（转换链对高度系关软纹理），(c) 原样继承 (a) 的 43.31 → **端到端不准**。

**(b) 的非零范围与 Krita 侧报告吻合**：(b) 只在 multiply 的 d10/d60 出现（s=50/100/150/200 × d=10/60，共 **8 张**），
d100 与 linearHeight 全为 0。这正是 Krita 侧报告 §10.2 的「conv 与 raw 在 A 组 16/24 张 sha 相同、8 张不同」——
本报告把该差异量化成单一常数 `255(1−s)`（229 / 102），并证明它在 (c) 端到端里被完全抵消。

### 2.4 语义层（d）的独立性证明

语义层在 64×64 上直接算，没有 100×100 平铺、没有缩放；它与 (a) 的一致性（multiply d10：229.00 vs 229.00；
linearHeight d10：43.17 vs 43.31）说明**归因结论不依赖任何几何假设**。0.14 的微小差来自加权口径：
100 不是 64 的整数倍，平铺到 100×100 后各纹理值的出现频次不均，而 64×64 是等权平均，两者不是同一个权重分布。

另外核验了预测器本身：`ps_mask` 预测 vs PS 实测图、`compute_mask` 预测 vs Krita raw 实测图，
在 scale=100 的全部 multiply 深度与 linearHeight d10 上都是 `mean|Δ|=0.00、差异比例=0.00%、max=0`
（第 [六] 节 `predPs-vs-PSimg` / `predK-vs-KrawImg`），说明两侧公式复刻在 scale=100 是逐像素精确的。

在 scale=100（避开重采样）上直接核对两条结构假设，数据来自第 [六] 节：

### 4.1 偏差来源（精确对上，不是统计巧合）

- 两侧 8-bit 量化**完全相同**：PS `q = round(2.55×d)`，Krita `strength = round(d/100×255)`，d=10 时同为 **26**，d=60 时同为 **153**。
  所以深度偏差**不是**量化造成的。
- linearHeight 实测最大差 **52 = 2q = 2×26**；PS 的 Alpha 范围 57..255、Krita 5..255，
  两端差同为 52（`57−5=52`）；平均差 43.31 是 52 在整幅纹理上的加权。
- 公式源头：PS 高度系 `out = max((255−u)·Wq/255, Wq−u)`，**W=12**；
  Krita 高度系 `out = max((1−t)·10s, 10s−t)`，**W=10**（`tools/texture_mask.py` 从源码抄的 10）。
  归一化后 `PS = 12q − u`、`Krita = 10q − u`，差 `2q = 52` —— 与实测逐位吻合。
- 语义层 64×64 独立复核：`ps_mask` 与 `compute_mask` 的差 mean|Δ|=43.17、max=52（表 1 补充行 (d)），
  与 100×100 实测的 43.31/52 一致 → 确认是公式常数差，不是平铺/几何/量化。

### 4.2 从哪个 depth 开始偏差超阈

- **multiply**：d10、d60 全部 0.00（逐像素相同），**没有任何深度超阈**；d100 是基准点。
- **linearHeight**：偏差**从 d>0 起就存在**（=2q，随 d 线性增长，d10 时已达 52 灰度级，远超 25 的「不准」阈），
  而不是「从某个深度开始」；只是 **d≥60 两侧同时饱和到 255**，把偏差推到不可观测区间。
  因此可判读窗口只有 d10，且 d10 已超阈。
- 补充：PS 的深度量化在 d=10 出现 `2.55×10=25.5 → qRound=26`（不是 25），这一级 1/255 的量化差
  带来的最大偏差是 **2 灰度级**（修法验证里实测 max=2），远小于 W 差带来的 52 —— 再次证明主因不是量化。

## 5. 最小改动与预期收益

### 5.1 深度（linearHeight / height 系）——值得改，1 个常数

**改法**：转换链对 Height/LinearHeight 写 Krita `Texture/Strength/Value` 时，把
`strength = depth/100` 改为 `strength = min(1.0, 1.2 × depth/100)`（12/10 = 1.2），
即 8bit 强度 `q' = min(255, round(1.2·q))`。实现上只动 `src/brush_converter/kpp/preset_xml.py`
的高度系分支一个常数（本次任务不改 src，仅建议）。

**预期收益（`tools/exp_analyze.py` 第 [七] 节，用两侧公式预测、scale=100 可预测区）**：

| 模式 | D | q8 | 现状 conv vs PS | 修法后 vs PS |
|---|---|---|---|---|
| linearHeight | 10 | 26 → 31 | mean\|Δ\|=**43.31**、95.36% 像素差、max 52 | mean\|Δ\|=**1.39**、**0.00%** 像素差、max **2** |
| linearHeight | 60 | 153 → 184 | 0.00（两侧饱和） | 0.00（不变） |
| linearHeight | 100 | 255 → 255 | 0.00（两侧饱和） | 0.00（不变） |
| multiply | 10/60/100 | 不变 | 0.00 | 0.00（不动） |

即：**偏差从 43.31 降到 1.39 灰度级（−96.8%），超阈像素从 95.36% 降到 0.00%**，且对已饱和档零副作用。
残余 1.39 来自 8-bit 量化（max 2），属不可再消除的部分。

### 5.2 缩放（150%/200%）——不建议用常数修，属重采样口径问题

- 机制对：幅度比 1.019（150%）/1.054（200%），若机制反了（PS 按 1/scale、Krita 按 scale）该比值为
  ~1/1.5=0.67 或 ~2.25 这种量级，实测远离此区间；r=0.974/0.946、同号率 0.93/0.90 也说明方向一致。
- 差异正比于「图案自身变化幅度」：**相对残差在 S=150 恒为 22.2–22.3%、在 S=200 恒为 32.4%，
  对 d10/d60/d100 三个深度几乎完全一致**；若是深度映射错，残差应表现为与深度相关的近似常量偏移，而不是恒定百分比。
- 残差与 PS 局部梯度正相关（0.370–0.400 @150%，0.276–0.286 @200%），且 S=50% 时仅 0.8%、max=1
  （缩小方向两侧算法近似一致，放大方向插值核不同）→ 归因为 **Krita Qt 平滑重采样 vs PS 缩放算法**。
- 结论：**转换侧没有可用参数修正**。可选口径（未验证、本次不做）：转换时按预设自身的 texture scale
  预缩放内嵌图案并把 `Pattern/Scale` 写 1.0，用我们自己的重采样替换 Qt 的；但这会改纹理像素字节，
  且需要先用 PS 采样核定标，属后续工作。

### 5.3 multiply 深度/缩放：保持现状

现状 conv 在 scale=100 的全部深度上 mean|Δ|=0.00，任何改动都是倒退；唯一注意点是
`UseSoftTexturing=true` 是「承重墙」，删掉会立刻退回 229/102 常量偏差。

## 6. 产品级 bug：Krita 5.3.3 纹理 md5/文件名撞车（引用既有证据，未重跑）

证据来自 `docs/验收报告/实验-Krita侧-报告.md` §8（全部为真实渲染对照）：

| 实验 | 结果 |
|---|---|
| 源纹理逐字节内嵌（md5 `5e748763…`），任意文件名 | **纹理静默禁用**：预设照常加载、Enabled=true、字段回读全对，但 Alpha 恒 255（首轮 52 张全废） |
| 同像素、只改 pHYs 数值（md5 `3863a554…`） | 正常生效，且与 `texture_mask.py` 预测逐像素一致（mean\|Δ\|=0） |
| 用户 Krita 图案库中的 `测试用纹理.png` | 与实验源文件 **md5 完全相同** |
| 图案名用转换链默认的 `tex_<uuid8>.png`（如 `tex_66e2987f.png`） | **串用资源库同名图案**：不同字节渲染出同一张错图（Alpha 均值 211.6）；换唯一名后正常 |

**判定**：Krita 5.3.3 处理内嵌纹理时按 md5 与已安装图案去重；md5 撞车 → 解析失败 → 静默禁用（无报错无警告）；
文件名撞车 → 图案被遮蔽 → 串用别人的图案。这是用户会遇到的真 bug（「纹理明明开着却不生效 / 用错图案」）。

**建议修法（转换链侧，二选一或并用）**：

1. 图案资源名加唯一后缀：`tex_<内容哈希前8>.png`（现状是 `tex_<uuid8>.png`，与内容无关，必然可能撞名）；
2. 加载前校验像素哈希：把内嵌纹理的 md5/像素哈希写进 `PatternMD5Sum` 之外的元数据，并在写出 .kpp 前与
   本机图案库（`%APPDATA%/krita/patterns`）做一次 md5 比对，命中则改写内嵌字节（如追加一个 tEXt 块，像素不动）
   或直接改用唯一文件名 + 唯一资源名。

本实验为规避该 bug，内嵌纹理 = 源文件字节 + 1 个 tEXt 块（md5 `552a2ae2…`、13433 字节，像素未动），
因此 53 张图里的纹理**不是**与源文件逐字节相同，引用时需注意（Krita 侧报告 §8.3、§13 已登记）。

## 7. 本实验不覆盖的边界（引用前必读）

1. **单 dab、无笔划搭接**：两侧都是单笔尖（间距 1000% → dab 间距 2000px），没有 dab 重叠、没有笔划叠压；
2. **无压感、无动态**：压感恒 1.0；PS 侧 `useTipDynamics=false / useScatter=false / smoothing=false`；
3. **不覆盖模式算子与笔刷引擎的交互**：只测了纹理掩码层（multiply / linearHeight），
   没测 subtract / height / hardMix 的端到端像素，也没测混合模式与笔刷引擎（间距、软硬边、流量）的耦合；
4. **不覆盖 B 组（亮度/对比度）的归因**：B 组只有 conv，无 raw 对照；且两侧 b/c 量纲不同（calibrated 逆公式），
   本次不给 B 组的 2×2 归因；
5. **不覆盖 scale≠100% 的相位/采样核**：只用响应曲线与相关性做「机制判决」，没有逐像素复刻 PS 的缩放算法，
   也没有做 sub-pixel 相位搜索；
6. **版本锁**：PS 2025 / 26.9.0.15、Krita 5.3.3；换版本必须整批重出。
