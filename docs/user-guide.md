# 用户指南：从 ABR 到 Krita

This guide covers the published v1.5.0 Windows GUI and CLI workflow: download, convert, and import into Krita. Unpublished candidate changes and planned features are listed separately; conversion does not guarantee identical Photoshop rendering.

[返回首页](<../README.md>) · [按现象排错](<troubleshooting.md>) · [版本说明](<../releases/RELEASE_NOTES.md>)

## 一、先选对版本和文件

- **已发布 v1.5.0**：从[正式版下载页](https://github.com/yxm1122/brushConverter/releases/tag/v1.5.0)获取 Windows 64 位压缩包；新手选 GUI 包，只有需要输入命令时才选 CLI 包。
- 原始 `.abr` 是给本工具的**输入**；`.bundle` 是适合一次导入多支笔刷的资源包（resource pack）；`.kpp` 是一支笔刷的预设（preset）。PNG 笔尖图片不是完整预设。
- 先完整解压到自己的工作目录，不要在压缩包中运行，也不要只复制其中的 exe。正式版 exe 不要求另装 Python；源码入口和诊断脚本另见[源码运行](<#source-run>)。
- 保留原始 ABR 与旧产物的备份，**每次转换选新的空输出目录**；不要将输出目录设成原始素材目录或已有资源库。
- 本文参考 Windows 64 位与 Krita 5.3.3 既有记录，其他环境未验证。Krita 菜单/按钮的确切名称与本轮候选的真实导入、重启效果**待回填**，不把说明文字当成本轮实机验收。
- 素材的作者、版权、许可由你确认；项目 MIT 许可不会自动授权第三方笔刷的分享。

<a id="gui-convert"></a>
## 二、图形界面转换（新手推荐）

1. 下载 GUI 包 `brushConverter-v1.5.0-win64.zip`，完整解压后双击其中的 `brushConverter.exe`。
2. 用“打开”选择原始 ABR。等解析结束，核对笔刷名称与笔尖缩略图；如果报错，先记录原文，不继续尝试导入半成品。
3. 勾选要转换的笔刷。可用“全选/全不选”；只想要部分笔刷时逐支勾选。
4. 选产物格式：**GUI 一次二选一**。默认 `.bundle` 便于整包导入；选 `.kpp` 会把独立预设放在输出目录的 `kpp/` 子目录。不会同时得到两种独立输出。
5. 选一个新输出目录，点击“开始转换”。如出现未映射参数或纹理提示，先读[转换取舍](<#tradeoffs>)：选“是”表示接受所列限制后继续；选“否”在开始写出前退出这次确认，可改选笔刷再试。
6. 完成后记录预设数、真实纹理数和输出位置。有资源包时还会显示文件名及短哈希。出现“产物回读校验失败”就按[校验失败](<troubleshooting.md#conversion-error>)处理，不能因为对话框标题是“完成”就导入。
7. 进入[导入 Krita](<#import-krita>)。预设数为 0、提示跳过或没有生成文件时，不算完成了转换闭环。

**当前没有整批安全取消按钮。** 转换期间不要用强杀进程代替取消，也不要把关窗理解为“不会留下输出”。搜索筛选、逐支可编辑性开关等见[计划状态](<#candidate-status>)，不在本节虚构操作。

<a id="cli-convert"></a>
## 三、命令行转换（可选）

CLI（command-line interface）适合重复批量操作；不会替你启动 Krita 或导入资源。
在 CLI 包的完整解压目录打开 PowerShell，先把自己的 ABR 放入该目录下的 `input/` 文件夹，再按实际文件名修改下面示例。**示例不是仓库自带素材，不要原样运行找不到的文件名。**

```powershell
# 先看真实帮助，选项以当前程序为准。
.\brushconverter-cli.exe convert --help

# 不加两个 --no-* 开关时，默认同时生成 bundle 与独立 kpp。
.\brushconverter-cli.exe convert ".\input\我的笔刷.abr" -o ".\output\run-01"
$LASTEXITCODE
```

- `-o` 指定输出目录；请用一个未使用过的目录。省略时会写入当前目录下的 `converted/`，不推荐与旧产物混放。
- CLI 当前会转换该 ABR 中全部可转换预设；**没有逐支筛选参数**，需要子集请用 GUI。
- 正常资源包输出会列出“转换完成：N 个预设（含真实纹理 M 个）”和“输出校验：OK（…）”。核对 **N>0、文件存在、无失败或跳过提示**；退出码 0 只代表命令正常结束，不代表与 PS 外观一致。
- 退出码与警告的区别见[排错手册](<troubleshooting.md#conversion-error>)。只导出独立 KPP 时没有同样的资源包回读摘要，不要借此宣称已校验全部产物。

### 可选命令或选项：逐项说明后果

| 选择 | 实际后果 | 适用提醒 |
|---|---|---|
| `convert … --no-standalone` | 只交付资源包，不另写独立 KPP | 新手只想导入整包时可选；包内仍含预设 |
| `convert … --no-bundle` | 只写独立 KPP，不生成资源包 | 需走独立预设导入路径；同名旧文件可能被覆盖 |
| 同时使用两个 `--no-*` | 两种输出都关掉，程序报错 | 不是“试运行/只检查”模式，不要这样测试 |
| `info ".\input\我的笔刷.abr"` | 只读显示版本、区段与采样笔尖概况 | 不生成 Krita 预设；退出码 2 表示无采样笔尖，不等于计算笔刷一定不能转换 |
| `extract … -o ".\output\tips-01"` | 写出采样笔尖 PNG 与信息 JSON，不转换参数 | 不是转换必做步骤；可能没有采样笔尖可提取 |
| `extract … --contact-sheet` | 在提取结果外再写一张笔尖总览图 | 仅便于看形状，不能当作完整笔触对照或 KPP |

表中的省略号表示沿用前面的输入/输出参数，**不是要输入的字符**。可先用相应子命令的 `--help` 查完整格式。

<a id="outputs"></a>
## 四、输出在哪，哪些保护已经实现

| 输出 | 在所选输出目录中的位置 | 当前边界 |
|---|---|---|
| 资源包 | 形如 `源名_v版本_内容短哈希.bundle`，以完成摘要为准 | 同内容可复用不重写，同名不同内容会改名保留旧文件；写出后回读检查 |
| 独立预设 | `kpp/` 子目录内，每支一个 `.kpp` | **仍为直接写入，可能覆盖同名旧预设**；资源包防覆盖不等于它也受保护 |

短哈希是内容指纹，不是“已发布”凭证。当前源码中的版本字段仍可能保留已发布版本号，**候选产物不能仅凭文件名认成正式版**；区分来源目录、代码提交与获取渠道。

发生转换失败时，独立预设目录可能已有部分文件；当前没有整批回滚承诺。保留原始错误与该次输出现场，不把已有文件当作整批成功，不在旧目录反复重试覆盖证据；换新目录重新转换。

<a id="import-krita"></a>
## 五、导入 Krita 并核对来源

**只导入本工具生成的资源包或预设；不要把原始 ABR 直接导入 Krita。** 原始 ABR 直读库与转换产物是两套来源，名称相同也不表示效果相同。

### 路线 A：导入资源包（推荐）

1. 先确认转换成功并找到完成摘要所列的 `.bundle`。
2. 在 Krita 的“设置 → 管理资源”相关入口使用**资源包导入**功能，选择该文件。这里沿用既有中文记录；具体按钮名随界面可能不同，**精确菜单路径待核对**。找不到入口时保留实际界面信息再询问，不猜测点选，也不因此重建缓存。
3. 回到笔刷预设列表，核对对应名称与缩略图，并确认不是选中了同名的原始 ABR 直读预设。不要以“必须自动出现来源标签/分组”作为当前导入成功条件。
4. 用有代表性的笔刷检查实际笔触，必要时正常退出并重新启动后复看。**本轮这些真实效果与重启持久性待回填**；文件校验成功不能代替这一步。

### 路线 B：独立 KPP（可选）

只有需要逐个管理预设时才走此路。先在 Krita 中确认**实际资源目录**，正常退出 Krita 后，将本次输出的 `kpp/` 内预设复制到该资源目录的 `paintoppresets/`，再启动 Krita。
Windows 常见默认位置为 `%APPDATA%\krita\paintoppresets`，但自定义/便携配置可能不同，不把默认位置当作实测路径。

**后果**：独立文件需要自行管理；复制时遇同名项先备份并停止覆盖确认，别覆盖自己改过的笔刷。此路线不承诺原生标签自动关联，也不需要再导入原始 ABR。不要为了“两种都试”把同一批包与散装预设混装；找不到预设先看[不可见/纹理像丢了](<troubleshooting.md#invisible-texture>)。

### 更新已有产物（需要时才做）

先正常退出 Krita，备份要替换的旧产物，再换成本次转换文件后重新启动；不要在运行中直接覆盖已加载的资源包。保留两版便于回退，但同名预设混装可能干扰判断，应一次只核对一个来源。无需为每次更新重建缓存。

<a id="tradeoffs"></a>
## 六、转换取舍：先知道哪些不能再调

烘焙（bake）是把调整结果写进像素，外观处理不等于保留原编辑能力。

| 适用范围 | 当前处理 | 代价与选择 |
|---|---|---|
| 已发布 v1.5.0：计算笔刷（computed brush，只有参数、无内置位图） | 按 PS 硬度剖面生成位图笔尖 | Krita 中 fade/硬度不能再按原方式调；显示尺寸按实际足印，不等于 PS 标称直径 |
| 已发布 v1.5.0：纹理缩放大于 100% | 预放大后内嵌，作为既定像素使用 | 体积可能增大；原缩放/相位的编辑能力受限 |
| 未发布候选：纹理亮度越界命中区 | 亮度/对比度/反相预烘焙 | 这些 Krita 控件不再对应 PS 原语义，再调会叠加；不是正式版下载包已经具备的变化 |
| 未映射参数 | 提示后继续时不保留其完整作用 | 接受近似后才继续；需要原效果时保留原始 ABR，不将转换结果称为完全等价 |

目前没有逐支关闭以上烘焙的生产开关，旧公式回退开关也已删除。请勿照历史文章设置 `BRUSHCONVERTER_TEXTURE_FORMULA=legacy` 期待恢复功能。
详细参数、已知残差（residual）与证据分级只查[映射参考](<parameter-mapping.md>)，版本差异只查[版本说明](<../releases/RELEASE_NOTES.md>)。

<a id="source-run"></a>
## 八、从源码运行（可选，不是 exe 用户的必做步骤）

需要完整源码及已配置好依赖的 Python **3.12 或以上**；先在项目根目录的新 PowerShell 窗口中指定并核验自己的解释器，不使用未经核验的 PATH 默认 Python：

```powershell
# 必须把占位文字换成实际解释器路径；这里不会自动安装或修改环境。
$PY = '填写你的 Python 3.12 或以上版本的 python.exe 完整路径'
& $PY -B -c "import sys; print(sys.executable); print(sys.version); assert sys.version_info >= (3, 12)"
if ($LASTEXITCODE -ne 0) { throw '解释器核验失败，停止。' }
& $PY -B cli.py convert --help
```

确认环境后可用 `& $PY -B cli.py convert "你的输入.abr" -o "新的输出目录"`；需要源码 GUI 时用 `& $PY -B cli.py gui`。本轮真实 GUI 仍待人工，不在此宣称启动实测。依赖或运行出错先留原始输出，不在错误解释器里反复安装；维护环境、构建与测试见[开发指南](<developer-guide.md>)，诊断日志的目录隔离见[可选只读诊断](<troubleshooting.md#readonly-diagnosis>)。
