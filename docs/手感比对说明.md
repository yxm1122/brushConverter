## 1. 怎么跑

```bash
cd <REPO>
# 1) 一支笔 × 4 档位：渲染 PNG + 逐档曲线 + 合并进 feel/manifest.json
python tools/krita_render_pressure.py \
    --preset "converted/kpp/003_大怪兽-圆头虚_用数位板.kpp" \
    --pressure-profile 0.2,0.5,0.8,1.0 --stroke-length 120 \
    --out-dir tests/baselines/feel --curve-out-dir tests/baselines/feel

# 2) 从任意一张图提曲线（默认重采样 64 点）
python tools/feel_curve.py --image tests/baselines/feel/feel__xxx__p1.00__s200x200.png --out /tmp/curve.json

# 3) 两条曲线比对（退出码 0=合格，1=不合格）
python tools/feel_compare.py --a /tmp/curve.json --b tests/baselines/feel/xxx__p1.00__curve.json
```

**同一时刻只允许一个 Krita GUI 渲染会话**：批量渲染/全量 pytest 不要与本脚本并发，
否则两个 Krita 会话互相干扰会改变像素（本项目在任务 06 已踩过一次，这里再强调）。

## 2. 曲线怎么提取（`feel_curve.extract_curves`）

- 读 RGBA PNG，按列（x 方向）统计；`ALPHA_THRESHOLD = 10`（0..255 尺度）：
  **Alpha ≤ 10 的像素视为抗锯齿/背景，不计入**，避免边缘半透明像素让宽度虚高且抖动；
- **宽度曲线**：每列 Alpha>10 的像素个数，单位 **像素（px）**；
- **不透明度曲线**：每列「Alpha>10 的笔迹像素」的 Alpha 均值 ÷ 255，单位 **0..1**。
  只对笔迹像素求均值，所以宽度变化不会稀释浓度；
- **positions**：0..1 的画布归一化横坐标（按整张画布宽度归一化，不是按笔迹包围盒），
  这样不同图能对齐比较；
- 默认**线性重采样到 64 点**（`--points` 可改）。

输出 JSON：`{"positions": [...], "width": [...], "opacity": [...], "meta": {...}}`，
`meta` 里写明单位（`width_unit: "px"`、`opacity_unit: "0..1"`）。

## 3. 阈值单位口径（必须记牢）

| 偏差 | 公式 | 单位 | 阈值 |
|---|---|---|---|
| `width_dev` | `max(|w_a-w_b| / max(w_b,1))` | 无量纲（0..1；×100 = 百分比） | **< 0.05（5%）** |
| `opacity_dev` | `max(|o_a-o_b|)` | **0..1 尺度** | **< 0.05（满量程 5%）** |

换算：`opacity_dev` 的 0.05 对应 0..255 尺度的 **12.75/255**。
任务书里「按 0..255 尺度则 <5/255≈2%」那句与本实现的 5% 满量程口径不同：
用户原始要求是「不透明度偏差 <5%」，本实现按 **5% 满量程** 落地（常量名 `OPACITY_DEV_THRESHOLD_01`
明确带 `_01` 后缀，避免与 0..255 混用）；若想改用更严的 5/255≈0.0196，传 `--opacity-threshold 0.0196`。

判定：两条偏差同时 `< 阈值` → **合格**；任一不达标 → **不合格**（输出里同时给 `width_dev_percent`、
`opacity_dev_0_255` 两个换算值，报告引用时不再手算）。

## 4. 基线（`tests/baselines/feel/`）

- 规模：**3 支笔 × 4 个压感档位 = 12 组**（003 圆头虚 / 004 圆头实 / 006 碳铅）；
- 每档：`feel__<笔刷名>__p<档位>__s200x200.png` + `<笔刷>__p<档位>__curve.json`；
- `manifest.json` 每项登记：`preset / brush / pressure / file / curve_file / size / stroke_length /
  alpha_nonzero / sha256 / max_width_px / mean_opacity_01 / pressure_injected / simulated`；
- 新增基线：对另一支笔跑第 1 节第 1 条命令即可，脚本会**按笔刷+档位合并**进清单（同键覆盖，其余保留）。

## 5. 「横向拉伸 10%」为什么能检出

`feel_compare.stretch_image_horizontally` 的做法是：把内容横向放大 1.10 倍，**再居中裁回原画布尺寸**。
如果只把画布变宽，笔迹占画布的比例不变，归一化曲线会完全重合、检不出来；裁回原尺寸后，
笔迹在同一坐标网格里变长，宽度曲线错位，`width_dev` 立刻超过阈值。实测：

```text
feel__大怪兽-圆头实_用数位板__p1.00__s200x200.png 横向拉伸 10% 后自比：
width_dev = 20.125（2012.50%），opacity_dev = 0.855，verdict = 不合格
```

## 6. 已知局限

1. **不是无头**：渲染走「真实 Krita GUI 进程 + 启动插件」路线（kritarunner 无头不可用，见任务 04 报告），
   需要交互式桌面会话；单档 11–13 秒，12 档基线约 2.3 分钟。
2. **只能串行**：同一时刻一个渲染会话，批量与 pytest 不要并发。
3. 曲线只量化「沿笔画方向（x）的宽度与浓度」，**不覆盖抖动、散布、纹理走向**；纹理笔的浓度会更抖。
4. 压感响应取决于笔刷预设自身的压力动态：不同预设的宽度/浓度变化幅度不同（碳铅明显更浓），
   本比对只保证「同笔刷跨压感档位」与「同笔刷基线自比」，不做跨笔刷绝对比较。
5. `width_dev` 的分母 `max(w_b,1)` 在笔迹边界（基线宽度 0）会放大相对偏差，
   这是任务书指定公式的固有特性：对边缘/长度差异敏感（正好用于抓形变），对亚像素平移也敏感。
6. 抗锯齿阈值固定 10（0..255）；若换渲染尺寸/笔刷需要重估。
