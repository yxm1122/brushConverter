## 一、结论：**可行**

问题：纹理缩放 >100% 的相对残差（文档口径 150%≈22.2%、200%≈32.4%）能不能靠「先把纹理 PNG 重采样到目标尺寸、Krita 里写 Scale=1.0」消掉？

**答：能，且 24/24 组全部落在像素级判据内（差异比例 0.00%、max_delta ≤1、相对残差 ≤0.34%）。**

根因不是「Krita 有上限」，也不是映射常数错了，而是**采样相位不同**：PS 的纹理缩放按**源对齐**双线性采样（目标像素 i ↔ 源坐标 i/k，图案周期延拓），Krita 现行路径是 Qt QImage::scaled(SmoothTransformation) 的**中心对齐**双线性。两者在 s>100% 时相位差 0.5×(1−1/k) 个源像素；高频真实纹理会把这点相位差放大到 90%+ 的像素超阈。预缩放路径先用 PS 同核把纹理缩放到目标尺寸，Krita 里 Scale=1.0 不再二次重采样，相位差消失。

边界（本结论不外推）：实测口径为 multiply、depth=100、亮度=0、对比度=0、invert=true、单 dab 全覆盖 100×100 画布；档位 150%/200%/300%/400%；纹理边长 64/100/256。50% 及以下不需要预缩放（既有数据 s50 已与 PS 0.00%/max1 一致），也未纳入本结论。

## 三、为什么 >100% 会偏：相位，不是上限

1. **真值可逆**：在 depth=100、multiply、invert=true、亮度/对比度为 0 时，PS 真值 Alpha 恰好等于「反相后的纹理掩码」——s=100 时与「纹理平铺取反」逐像素 0.00%、max 0。所以可以用真值反推 PS 的重采样算法。
2. **常见插值核全部对不上**：把纹理用最近邻/双线性/双三次/Lanczos（含全部整数相位）重采样后与 PS 真值比，差异比例 89%–94%、max 90–165 —— 说明问题不在「换一个插值核」。
3. **逐像素结构反推**：s=200 的 PS 掩码行序列是 tex0, mid(tex0,tex1), tex1, mid(tex1,tex2), …；s=150 严格按 i/1.5 线性插值，且图案边界按周期回绕 ⇒ PS = **源对齐双线性 + 周期图案**。该模型对 13 组 PS 真值（3 纹理 × 5 档）全部 0.00% / max≤1。
4. **Krita 侧反证**：用「中心对齐 / 角对齐 / 源对齐」三种映射分别模拟 Krita 现行渲染的掩码，只有**中心对齐**能复现实际 Krita 渲染（0.00%/max 2），另两种差 30%–95%。⇒ Krita = Qt 中心对齐双线性，PS = 源对齐；两者在 s>100 的相位差换算成画布像素为 0.5×(k−1) px（s200/300/400 = 0.5/1/1.5 px），足以把高频纹理的 90%+ 像素推离 2 灰阶以上。
5. **阶梯纹理为什么曾量到一致**：阶梯纹理是一维量化斜坡，对 0.5–1.5 px 相位差不敏感（本实验 raw 路径在阶梯上 0.00%/max≤2，与任务 125 一致），真实纹理才暴露。⇒ 「两侧语义一致」不等于「逐像素一致」，前者是 125 的语义层结论（仍成立），后者是本文补齐的相位层结论。

## 五、决策项（待使用者追认；本轮按推荐项执行）

**决策 1：预缩放落地范围**
- A（推荐）**只对 s>100 的缩放档启用预缩放**，100% 及以下保持原路径 —— 利：已达标档零风险、体积增量只落在放大档；弊：转换链多一条按 scale 的分支。
- B 全部缩放档统一预缩放（含 50%/100%）—— 利：路径统一；弊：已达标档也付体积/哈希代价，且 <100% 的 PS 核本轮未测。
- C 本轮不落地，只把结论交 132/137 —— 利：不改 src；弊：>100% 残差继续保留到 v1.5.0。

**决策 2：体积增量的接受度**
- A（推荐）**不设硬上限**，按内容照实涨（实测单预设 +0.8KB~+434KB）—— 利：与「不设上限」口径一致、不做无依据截断；弊：bundle 随含纹理预设数线性增长。
- B 设 40MB bundle 上限 —— 利：发布体积可控；弊：硬上限会逼出「哪些预设退化」的二次决策。
- C 只对 ≤200% 预缩放、>200% 保留现行路径 —— 利：体积增量显著减小（同样本 s200 +9.4KB vs s400 +48KB）；弊：s300/s400 的 42.6%/42.7% 相对残差继续保留。

**决策 3：预缩放的实现归属**
- A（推荐）**转换器内置纯 Python/numpy 源对齐周期双线性**（约 20 行、无新依赖、可复跑）—— 利：不依赖 PS 安装、与 PS 核 0.00% 命中；弊：v0.15 需要改 convert/preset_xml 的一段代码。
- B 转换时外调 Photoshop 做 Image Size 预缩放 —— 利：核完全同源；弊：转换机必须装 PS，且 Image Size 核是否等于纹理引擎核本轮未证。
- C 用现成图像库（Pillow）resize —— 利：代码最少；弊：Pillow 是中心对齐（=现行路径），实测真实纹理 90%+ 超阈，直接不可用。

**决策 4：预缩放后 Krita 字段语义的对外口径**
- A（推荐）**写死 Scale=1.0，并在预设名/说明文档注明「纹理已按 PS 缩放预烘焙，Krita 里改 Scale 不对应 PS 百分比」** —— 利：语义诚实、避免误调；弊：该字段在 Krita 里不可再编辑。
- B 同一纹理按档位派生多份资源、只有 >100% 档预缩放 —— 利：可编辑性只在需要档位丢失；弊：同纹理出现多份字节，体积与命名管理复杂。

## 六、人如何验收

1. **看结论与判据**：本报告 §二 的 prescale 行应全部 0.00% / max_delta ≤1；raw 行的 s150/s200 应为 90.03%/93.72%（相对残差 22.33%/32.35%，与 §10.4 的 22.2%/32.4% 对齐）。

       cd <REPO>
