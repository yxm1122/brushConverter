## 五、遗留与风险（含「本任务未做的事」）

1. **并发两套全量回归仍会挂 2 个 Krita 渲染用例**（test_krita_render.py::test_gui_render_is_200x200_with_nonzero_alpha、::test_two_runs_alpha_identical_within_tolerance）。实测：并发跑两次全量，其中一套 264 passed / 2 failed，两处都在 Krita 渲染。团队简报 §3 已写「Krita 渲染属共享单实例资源，必须先抢锁」——这不是产品回归，本任务未改 Krita 渲染代码，也未加锁（超出授权范围）。
2. **hash8 只有 32 bit**，理论存在前缀撞车。已由「不同内容 → 自动加后缀 + 警告」兜底，绝不静默覆盖；若使用者要求更强可扩到 16 位（需拍板，会改产物名口径）。
3. **旧版 stem.bundle 只提示、不迁移、不删除**：是否提供清理/迁移命令留待发布后决定。
4. **GUI 只做离屏验证**（QT_QPA_PLATFORM=offscreen + 捕获对话框文本），真实鼠标点击与在 Krita 内导入新 bundle 属人工验收，本报告不代填。
5. 未 commit / 未 add / 未 tag；未改 docs/优化提示词/执行进度.md、00-任务执行流程图.html。
6. tools/privacy_scan.py 的 PUBLISHED_TAG 仍是旧值（发布任务负责），本任务按指令未动。
7. 本任务的「产物名变更」会让使用者旧目录里同时存在新旧两种 .bundle；Krita 会两个都注册。若要「只保留一份」，需要人工清理旧文件（本工具不删用户文件）。
