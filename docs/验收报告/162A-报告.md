# 任务 162A 报告：增量隐私入口

> **English abstract**: Implement a real incremental privacy entry for brushConverter: an explicit baseline (`--since-baseline`) that scans only post-baseline worktree changes and new commits (author, committer, message, added lines, including lines deleted later), and a repeatable explicit candidate entry (`--artifact`) that inspects in-workspace ZIPs without extracting and registers binaries/images for manual review. The default no-argument scan remains the pre-release full gate over the worktree and all history. Baselines that cannot be proven are blocked with exit code 4 instead of silently falling back to HEAD-only.

## 〇、一句话结论与用户可见效果

**一句话**：把「日常增量」做成真正可用的独立入口，同时保留原来的发布前全量门：日常只扫基线之后的改动与新增提交，不能确认覆盖时直接阻塞（退出码 4），绝不偷偷改成只扫 HEAD。

**用户可见效果**：

1. `--help` 把 **日常增量**（`--since-baseline`，可叠加 `--artifact`）与 **发布前全量**（不带增量参数，供 186 候选冻结后集中执行）分组列出，并写明「日常增量不能替代发布门」。
2. 在合成历史里**新增后又删除**的敏感行仍会被抓到；非中性作者、提交者、提交信息同样会被抓到（测试见 §2.3）。
3. 非法/不存在/非祖先/无法确认引用覆盖的基线一律**非零退出（4）**，原 `--selftest`（13 条样本）与默认全量行为不退化。
4. 显式候选 `--artifact` 可重复，能把被 `.gitignore` 忽略的 ZIP 纳入只读扫描；ZIP 穿越、解压炸弹、超限条目会登记为 block，二进制/图片只写「待人工目检（不代表已通过）」。

## 三、实现说明（参数、判定与安全边界）

### 3.1 三种口径

| 口径 | 触发方式 | 扫什么 | 结论措辞 |
|---|---|---|---|
| 发布前全量（默认） | 不带任何增量参数 | 工作区受跟踪文件（可选未跟踪）+ `git log --all` 全部历史；保留覆盖清单门 | 「允许进入发布」/「不允许发布」 |
| 日常增量 | `--since-baseline REF` | 基线→工作树的新增/修改文件 + 未跟踪新文件；`REF..HEAD` 新增提交的元数据与新增行 | 「增量扫描未发现 block（不代表发布前全量已通过；186 仍需全量）」 |
| 仅显式候选 | 只给 `--artifact PATH` | 只扫给定文件/目录（允许被 `.gitignore` 忽略的 ZIP）；不扫工作区全量、不扫全部历史 | 同上（增量措辞） |

`--artifact` 可重复，也可与 `--since-baseline` 叠加；不能与 `--worktree-only`/`--history-only` 同用。相对候选路径按**当前命令目录**解析，解析后必须落在仓库根内。

关键代码位置：[privacy_scan.py](<tools/privacy_scan.py#L1804>) 的模式判定、[privacy_scan.py](<tools/privacy_scan.py#L2162>) 的新参数、[privacy_scan.py](<tools/privacy_scan.py#L1051>) 的报告措辞。

### 3.2 基线校验与退出码 4

[validate_baseline](<tools/privacy_scan.py#L1294>) 依次校验：

1. 基线能解析成提交；否则 block。
2. 仓库不是浅克隆；否则无法确认基线之前的历史，block。
3. 基线是 HEAD 的祖先（`git merge-base --is-ancestor`）；否则可能是改写或选错，block。
4. 基线在当前引用与 HEAD 的可达历史里；否则 block。
5. **引用集合**：基线之后不得存在「只在其它分支/tag/远端、可被 `--all` 扫到但不在 HEAD 历史里」的提交；存在则 block，要求先收敛引用或改用全量。

任何一项失败都抛 `BaselineBlocked`，主会话打印 `[基线阻塞]` 并以 **退出码 4** 结束（[privacy_scan.py](<tools/privacy_scan.py#L2273>)）；不会写 JSON、不会执行部分扫描、不会退化成只扫 HEAD。

**能力边界（如实登记）**：上述检查能发现「基线不可达/非祖先/其它引用有增量提交」。它不能证明基线**之前**的历史从未被改写（那不在增量范围内）；这种改写需由 186 的全量扫描与人工复核兜底。

### 3.3 工作区增量

`git diff --name-only --diff-filter=ACMRT <基线>`（含已提交与未提交的新增/修改；删除的文件不算）+ `git ls-files --others --exclude-standard`（未跟踪新文件）。逐文件按原规则扫描文本与文件名；二进制/图片走原 `scan_binaries` 人工清单；内部产物规则仍生效。**基线内未改动的文件不会被重扫**，测试用「基线里已有敏感行、之后没动」的文件证明这一点。

### 3.4 历史增量

`git log <基线>..<HEAD>`：逐提交扫作者、提交者、提交信息；`-p` 逐条新增行套原规则。因为敏感行在**引入它的提交**里是新增行，即使后续提交又删掉，增量仍会命中；测试用 3 个提交（基线 → 新增 → 删除）验证。已公开/未推送的分级沿用原规则，未降低规则级别，也不改写任何历史；已发布边界按 2026-11-24 裁决使用 `v1.5.0` tag（并保留 `origin/main` 作为第二来源）。

### 3.5 显式候选与归档安全

[scan_artifact_paths](<tools/privacy_scan.py#L1669>)、[scan_zip_artifact](<tools/privacy_scan.py#L1426>) 的口径：

| 风险 | 处理 |
|---|---|
| 路径越界/坏路径/`.git` | 整批拒绝，退出码 2，不扫「别的」 |
| 符号链接 | 候选本身拒绝；目录内符号链接跳过并 warn；ZIP 内符号链接 block |
| ZIP 穿越（`..`、绝对路径、盘符、反斜杠、NUL） | 条目判 block，**不读取、不解压** |
| 解压炸弹 | 条目压缩比 ≥100 且解压后 ≥1 MiB，或单条目 >8 MiB、累计 >64 MiB、条目数 >1000 → block |
| 文本读取上限 | 单文件/单条目最多读 1 MiB；超出即报「截断，剩余待人工」，不假装扫完 |
| 二进制/图片 | 只登记 `待人工目检（不代表已通过）`；不解压图片、不读像素内容 |
| 归档解压 | 全程内存读取 `zipfile` 条目，**从不调用 extract**，不写外部目录 |

限额常量在 [privacy_scan.py](<tools/privacy_scan.py#L1234>) 附近（`MAX_ARTIFACT_FILES`、`MAX_ARCHIVE_*`、`ZIP_BOMB_*`）。

### 3.6 默认全量未退化

不带增量参数时，`scan_kind` 仍是 `full`：工作区路径、`--all` 历史、内部产物、覆盖清单、block/warn 计数与「允许进入发布」措辞路径均保留；新增字段只是附加（`scan_mode`、`baseline`、`artifacts`、`worktree.mode/changed_files`）。合成仓库的 `test_default_full_scan_still_covers_all_history` 验证 `--all` 历史与覆盖清单门仍在；自检样本数 13/10 与改动前一致。

## 四、取舍与判定（为什么这样决定）

1. **阻塞而不是自动降级**：基线不满足覆盖条件时自动改扫 HEAD 会漏内容且让使用者误以为「检查过」。退出码 4 让问题显式暴露；要全量须由人明确改命令。
2. **增量不跑覆盖清单**：覆盖清单是「发布前全量必须证明扫过这些目录」的门；日常只动几个文件时它必然报 0 文件，属于假阻塞，因此在 incremental/artifact 模式关闭，保留在 full。
3. **artifact 单独使用不触发全量**：否则日常补扫一个 ZIP 会顺手跑 1047 个受跟踪文件与全部历史，违背「不触发全量充当日常检查」。只给 `--artifact` 就只扫候选。
4. **二进制只登记**：扫描器无法证明图片/二进制里没有截图、EXIF、路径；写「已通过」会造假。状态统一写「待人工目检（不代表已通过）」，留给 187。
5. **超限文本报 warn 而不是 block**：候选可能是大日志；报「截断」并保留人工项比直接放行或直接阻断更符合限额口径。ZIP 穿越/炸弹则必须 block，因为那是主动安全风险。
