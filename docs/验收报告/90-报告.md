## 四、关键设计取舍（为什么这么做）

### 4.1 先验收后发布，且发布不可撤回

把 `verify_all --archive` 与 `pytest -q` 都放在 tag/推送之前；只要有一条红就停在本地。skip 必须逐条说明——本版 skip = 0，所以没有「带 skip 发布」的豁免。

### 4.2 推送走 SSH over SOCKS5 而不是 HTTPS

本机 git 的 HTTPS 后端（Schannel）报 `SEC_E_NO_CREDENTIALS`，且原先的凭据助手指向已废弃的 `.workbuddy` 路径（`git push origin main` 实测失败原文：`fatal: could not read Username for 'https://github.com'`）。可用通路是「SSH + Python SOCKS5 桥接 ProxyCommand」，实测 `git ls-remote` / `push` 均成功。代价：多一个本地代理依赖。

### 4.3 Release 正文取自 `releases/RELEASE_NOTES.md`

保证网站上的发布说明与仓库内文件同一来源、同一内容，避免两处各写一套。

## 八、遗留问题

1. **打包体积小幅增长**：GUI +0.60%、CLI +0.84%，归因为 conda 环境里的 `pywin32`（任务 05 为 COM 试验安装）被 PyInstaller 收进两个包（多 2 个文件）。属可接受增量，未改 spec。
2. **Krita 侧仍无真正的「无头」渲染**：走的是「真实 GUI 进程 + PyKrita 启动插件」路线，需要桌面会话；批量渲染必须串行（同一时刻一个 Krita 实例）。
3. **PS↔Krita 整图逐像素比对仍不可达**（73%–100%）：本版只校准了纹理亮度/对比度语义（同引擎掩码空间 0.00%），模式/深度算子差异另属一项。
4. **结构性不可表达**：PS 对比度 >50 超 Krita 上限；`C=-50 且 |b|>127` 不可表达；Krita strength 上限 1.0 与 PS 深度 >83% 冲突（发布说明已写）。
5. **README 版本号**已更新为 v1.2.0；`docs/feasibility.md` 按任务 16 决策保留为历史文档。
6. 未做：v1.2.0 之后的双笔刷/颜色动态映射扩展（属下一轮规划）。
