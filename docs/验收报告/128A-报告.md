## 〇、一句话结论（三选一：**有条件可行**）

**结论 = 有条件可行**，且三个条件是分开的：

1. **hardMix 软边（F-2）**：常量偏置（Strength=1.0 + Brightness=+1/255）只在 **base≡1（满覆盖笔尖）** 成立：9 组实测 **0.00% / max 0**（复现 125）；**base<1 不成立**：mid（PS base 均值 0.89）偏置后 27.18/14.04/10.04%、soft（0.48）39.66/30.30/26.43%，全部超阈。逐像素预烘焙在**模型空间** 9/9 = 0.00%/max0，但**实测** 19.20–34.95%——残差来自「同一张采样笔尖位图在 PS 与 Krita 的落笔剖面不同」，平移 ±4px 搜索最优位移仍是 (0,0)，**不是对位问题**，是引擎差异 ⇒ 预烘焙无法在真实软边笔尖落地。
2. **textureBrightness 越界区（F-4）**：C=-50 且 |PS 亮度|>127 时，现行闭式解把 b_k clamp 到 ±1（原值 |b_k|=1.002…1.178），**8/12 组超阈（最大 61.12%/max 23）**；把 PS 真值掩码逐像素烘进 PNG + Krita 中性参数（B=0/C=1/Invert=false）**12/12 组 0.00%/max 0** ⇒ 预烘焙能修，**代价是纹理字段完全失去可编辑性**（PNG 即 PS 输出掩码）。
3. **10 个 UI 模式（d=100, b=50, c=50）**：把 PS 真值掩码预烘焙后，**9/10 模式 0.00%/max 0**（仅 subtract 99.49%——该模式算子按 1−mask 使用掩码，需要反向烘焙），说明「预烘焙本身不改变模式算子语义」；反面对照：**不预烘焙、只用现行闭式解**时 multiply / subtract / linearBurn / hardMix **4/10 超阈（最大 76.68%）**——这是**新发现的 b×C 交互区残差**，与越界区残差同源。
4. **F-3（PS minimumDepth 作用点）本轮未量测**：ABR 写入 textureDepthDynamics（bVTy=1 渐隐、fStp、minimumDepth=0/20/50）后 PS 侧 6 批 × 16 段笔迹**全部平坦**（三组 Mnm 像素完全相同、16 段 alpha 均值恒定），PS 没吃进纹理深度渐隐动态 ⇒ 按任务书 FAQ 登记「换方法」，不作结论。
5. 原任务书两个上限目标（C>50 / depth>83%）只做对照组：**C=80 multiply 现行 clamp 后 98.94%/max255 失败、linearHeight 0.00%**（与 125「k 原值直写可 0.00%」一致，残差在转换侧 clamp 不在 Krita）；**depth>83% 复用 125 真值（d25/d50/d100 六张 alpha_unique=1）→ 无像素可挣，不做预烘焙**。

## 二、F-2：hardMix 软边笔尖（主攻）

**假设**：「常量偏置（Strength=1.0 + Brightness=+1/255，符号随 Invert）能把 base<1 的 hardMix 也拉到 ≤2%；若不行，逐像素预烘焙是退路」。

**读法**
- 判据要求 ≤2% 且 max≤2。**只有 hard（base≡1）三档全指标达标**（②③均 0.00%/max0）。mid/soft 的 ②（常量偏置）**9 组中 6 组超阈**，max_delta 全部 255（二值算子边界错一位就是全差）；改善幅度也有限（mid d100 10.65%→10.04%，soft d60 29.86%→30.30% 甚至变差）。
- 边界集命中数（交接单要求的第二统计量）：hard 的边界集在 d60/d100 是 369/390 px，②把命中清到 **0**（这正是 125 的 +1/255 机制）；mid/soft 的边界集是连续曲线，②只清掉 34–118 px、留下 216/428 px（soft d100 命中 428 ≈ 全部边界像素）⇒ **单一常量无法覆盖连续边界集**。

## 三、F-3：PS minimumDepth 作用点 —— **未量测（换方法）**

**做法**：ABR 写 textureDepthDynamics = brVr{bVTy=1(渐隐), fStp=25, Mnm=minimumDepth}，minimumDepth 取 0/20/50（3 组）× 2 支笔尖（hard 64px 实心 / soft 64px 软边）× 重复 2 = 12 条 PS 笔迹 + 6 张无纹理参考；画布 1100×64、间距 100%、dab 间距=64px=纹理周期，每 dab 48×48 中心窗 alpha 均值 = 16 段。

**实测原文（PS）**：16 段均值**逐段相同**——
- hard：Mnm=0 → [104.91]×16；Mnm=20 → [104.91]×16；Mnm=50 → [104.91]×16
- soft：[49.08]×16（三组 Mnm 亦完全相同）；重复两次最大相对差 0.00–0.02%（≤5% 门槛，但**内容无变化**）

**结论**：**PS 没有把 ABR 里的纹理深度渐隐动态吃进去**（三组 minimumDepth 像素完全相同，fade 进度不随 dab 前进）⇒ 造不出压力/Fade ramp，F-3 的「参数地板 vs alpha 地板」二值判定**本轮未量测**，不许写任何一侧的结论。

## 七、代价（体积 / 哈希命名 / 反相与烘焙顺序）

1. **体积**：预烘焙纹理按画布尺寸烘（本实验 200×200 掩码 PNG 9493 B；F-2 二值 oracle 590 B；.kpp 内嵌后 f2 hard cur 14798 B → prebake 1981 B，f4 cal 14794 B → pre 11304 B）。**体积不是瓶颈**（同一画布尺寸下 ±几 KB）；若按笔尖位图尺寸烘 300×300 会到 ~20 KB/组合。
2. **哈希命名（一句可执行的话）**：预烘焙改变了纹理 PNG 字节 ⇒ 必须按**烘焙后字节**重新派生 Texture/Pattern/Name（现格式 tex_<sha256[:12]>.png）与 PatternMD5Sum，**否则 Krita 资源库会命中旧纹理缓存**（125 已实测同名/同 md5 会静默禁用或复用旧图案）。同理 .kpp 自己的内容哈希（bundle 的 hash8）会变 —— 旧 .kpp 必须重转。
3. **反相（Invert）与烘焙顺序**：PS 链实测顺序敏感——本次在 b×C 同时非零时发现闭式解与 PS 不符，说明「亮度→对比度→反相」的现行假设在交互区不成立。若预烘焙，**必须把反相也烘进 PNG 并把 Krita Invert=false**（否则 Krita 再反一次）；偏置符号仍随 Invert 翻转（125 已证）。
4. **可编辑性**：预烘焙后纹理字段（Brightness/Contrast/Invert/Depth）对结果只剩「二次叠加」意义，用户在 Krita 侧无法再调回原图 —— 这是本方案最贵的代价。

## 八、对本轮（132 合表）最关键的一条警告

> **textureBrightness 的「0.00%」只在「亮度与对比度不同时非零」的口径下成立；b×C 交互区是未登记的残差，本轮 10 模式里 4/10 超阈（最大 76.68%/max255）、越界区 8/12 超阈（最大 61.12%/max23）。**

## 十、决策项（2–4 选项 + 一句利弊 + 推荐第一；**待使用者追认；本轮按推荐项执行**）

1. **hardMix 软边是否允许「按 base 分档下发」**（推荐：**不允许，按现状登记**——满覆盖笔尖用参数级偏置 0.00%，base<1 维持 1.03% 残差登记）。
   - 备选 A：只对 base≡1 的笔尖下发偏置（利：0.00% 白捡；弊：需要在转换期判定笔尖是否满覆盖，硬边笔尖边缘 base<1 也会踩线）。
   - 备选 B：全部笔尖都不下发偏置（利：一致；弊：放弃满覆盖 0.00% 收益）。
2. **textureBrightness 越界区是否用预烘焙落地**（推荐：**不落地，只登记成本**——133/135 维持 clamp 并在矩阵 note 写「越界区 8/12 组 34.65–61.12%」）。
   - 备选 A：转换期检测越界后自动预烘焙（利：12/12 0.00%；弊：纹理字段失去可编辑性 + 纹理资源膨胀 + 旧 .kpp 必须重转）。
   - 备选 B：越界区直接拒绝/警告（利：不出错预设；弊：用户角度看是功能缺失）。
3. **b×C 交互区残差（本轮新发现）是否并入 135**（推荐：**并入**，作为 textureBrightness 的新回归组，先补 PS 真值再定修法）。
