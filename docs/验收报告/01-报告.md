## 五、遗留问题

1. **任务书写「三行摘要」，实际按 lead 口径做成单行契约**：任务书正文只给了一行格式，验收标准又写「三行摘要」。
   本任务按 lead 明确要求「摘要行一字不差」实现为**单行摘要 + 跳过明细**，理由见决策记录第 1 条。
   若后续任务确实要求三行块，只需改 build_summary() 一处，解析方仍以首行为准。
2. python -m pytest -m verify 与 python tools/verify_entry.py 会各打印一次同格式摘要（前者由 pytest 插件钩子打印，
   后者由汇总器打印），两处文字完全一致，不影响解析；若嫌重复可后续只保留一处。
3. 汇总器用 junit 报告计数，若 pytest 被外部中断（Ctrl-C），可能只拿到部分用例，此时按「pytest 异常退出」记为退出码 1。
4. junit 对 rootdir 之外的临时探针测试拿不到文件名（显示 ?），只影响临时探针展示，tests/ 下用例文件名正常。
5. 用例总数不是固定 63：并行任务会往 tests/ 加测试，全量入口会自动收集；台账引用数字时要写当次命令输出。
