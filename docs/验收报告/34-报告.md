### 3.3 掩码复刻（`tools/texture_mask.py`）与真机渲染的差：**软纹理分支缺失**

Mltp（唯一能同时算「工具复刻」与「真机」的模式）：

结论：`tools/texture_mask.py` 的 `blend()` **没有 `use_soft_texturing=true` 分支**（模块 docstring 自己写明

软纹理算子族 `out = dst + (op(dst,src) − dst)·s` 已用 8/8 张真机渲染反核（0.0000%、max ≤1）。

## 五、遗留与风险

1. **4 个饱和模式（Scrn/Ovrl/SftL/Lghn）没有可判数据**：不透明笔尖下「提亮族」在 PS 与 Krita 两侧都恒为 255。
   要判必须在**非饱和几何**（笔尖不透明度 <100%，或半透明底）重出两侧真值——会动任务 33 的口径，属新任务。
2. **`Drkn` 只能靠「按深度切算子」达标**（d<100→SUBTRACT、d=100→MULTIPLY），本批**没有**实施：
   它是算子切换而不是常数换算，且 PS 自己这两段的律不同（§3.2/模式-A §3.2），要不要落地需 lead 拍板。
3. **半透明边缘（base<1）未验证**：本批全部结论都建立在 base=1 的掩码几何上；真实笔刷的软边区域
   （PS 侧 Darken 可能是 `min(dst, dst−s·src)` 型夹取）没有真值，映射在边缘的正确性未知。
4. **`tools/texture_mask.py` 缺 soft-texturing 分支 + 只支持 5 个算子**（0/1/10/14/15）；
   `DARKEN(4)`/`OVERLAY(5)` 等直接抛 `NotImplementedError`。本批用真机候选规避，但下游任务若要用
   「复刻 vs 复刻」判定，必须先补这两个能力（§3.3 给了 8/8 反核用例）。
5. **观测到别批脚本的一个疑似 bug（只读发现，未改）**：`tests/baselines/mode-C/judge_c.py:130` 解析
   渲染文件名用 `stem.split("__")[1]`（会拿到 `"mode"` 而不是 `"<序号>_<模式>"`），
   与其 `kr_ref_paths` 的 `split("_",1)` 组合会抛 `ValueError`；本批脚本已改成 `parts[2]`。
   建议 37 合流时提醒 C 批核对。
6. **本任务未做的事**：没有重跑 PS/Krita 出图（沿用任务 33 基线）；没有改 `gui/` 文案（见 §六 决策 1）；
   没有 git commit（团队规则：由 lead 统一提交）。
