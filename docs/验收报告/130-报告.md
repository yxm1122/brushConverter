## 一、结论（三选一）

**可行。**

把 PS 的硬度径向剖面烘成正方形采样笔尖位图后，Krita 的 `png_brush` 能把 h=0/50/100 三档的 10–90% 过渡带复现到 **−0.90px（−1.14%）、+0.04px（+0.12%）、+0.50px**；现行路径（auto_brush + fade）同口径是 **−15.60px（−19.81%）、+7.33px（+22.63%）、−1.07px**。两档超阈全部消除，h100 仍一致。

**唯一硬前置（必须与结论一起读）**：Krita 的笔刷尺寸字段必须等于 **PS 实际足印**——h=0/50/100 分别是标称直径的 **1.45×/1.25×/1.02×**（标称 200px → 足印 290/250/204px）。这不是可选装饰：PS 的软边本来就伸出标称半径之外，而 Krita 采样笔尖的渲染足印 = 尺寸字段。若坚持尺寸字段保持 200，实测立刻退回 h0 −24.55px（−31.18%）、h50 −6.32px（−19.53%），判不可行。

## 三、代价（四条齐全）

1. **体积**：+8.6 KB/笔；500 笔 ≈ +4.3 MB（bundle 不再「零位图」）。
2. **生成耗时**：≈87 ms/笔（500 笔 ≈ +44 s），可忽略。
3. **产品语义变化（必须写进发布说明）**：笔刷类型从「计算笔刷（auto_brush，可见参数）」变为「采样笔刷（png_brush，位图）」后，**Krita 里 hfade/fade 不可再调**——硬度被烘进像素，预设编辑器里没有「硬度」可改项；改硬度只能回 Photoshop 重新转换。
4. **尺寸语义变化**：Krita 尺寸字段 = PS 实际足印（1.45/1.25/1.02× 于 h=0/50/100），与 PS 标称直径的显示值不再相等（200 → 290/250/204）；不改这一点则上一节 B200 的 FAIL 就是结果。

## 五、极性判定（独立验证；128a 的怀疑已收回）

**结论：Krita 5.3.3 的 L 模式内嵌 `png_brush` 位图是「深（小字节值）=墨、白（255）=透明」。**

证据（全部为本次渲出）：

| 探针 | 输入 | 输出 |
|---|---|---|
| P1 | 200×200 全 255（白） | 渲染 alpha 非零像素 = **0**（没有笔迹） |
| P2 | 200×200 全 0（黑） | 渲染 alpha 非零像素 = **40200**（≈200² 满墨） |
| P3 | 生产口径方形笔尖（中心 115、外圈 255） | 渲染中心 alpha=147、上边框 alpha=10（≈255−输入） |
| 逐半径 | B 组第一轮极性写反时的渲染图 | 半径方向恒定 **α_渲染 + 位图灰度 = 255** |

源码复核（只读）：`src/brush_converter/abr/samples.py` 先把 ABR 采样字节做 `255 − gray`（ABR 语义 255=墨/0=透明）；Krita 再把 PNG 反相一次 ⇒ **双重反相相消，现行转换链正确、无 bug**。项目文档里「png_brush 白=墨」是按中间蒙版语义写的措辞，不是 Krita 的实际读法（已在本报告登记，未改文档）。

**对本实验生成参数的影响**：新生成的采样笔尖必须存 **255 − α**；否则 Krita 渲出补集。本任务第一轮 B 组因此整体作废（B·h0 过渡带 1.60px、max_delta 255），改为 255−α 后重渲。反相寄存的附带好处：位图外围自然为 255 ⇒ 任务书要求的「正方形 + 边框 255」字面成立，且 `_square_tip` 补白逻辑未动。

## 七、决策项（待使用者追认；本轮按推荐项执行）

**决策 1：v0.15 是否按「采样笔尖 + 足印尺寸」落地？**
- **A（推荐）落地**：h0/h50 都由 −15.60/+7.33px 收敛到 −0.90/+0.04px。弊：类型变化 + 体积 +4.3MB/500 笔。
- B 只落地 h0（h50 留现状）。利：改动面小。弊：两支笔两套路径，维护成本翻倍。
- C 不落地、维持现状登记残差。利：零风险。弊：h0 的 19.8% 偏差永久留在矩阵。

**决策 2：接受 Krita 尺寸字段 = PS 实足印（1.45/1.25/1.02×）吗？**
- **A（推荐）接受**，发布说明写明「尺寸字段=足印，PS 显示值仅供参照」。利：两档都 ≤1px。弊：用户会看到 200→290 的滑块差。
- B 保持尺寸=标称 200。利：滑条与 PS 一致。弊：h0 退 −24.55px、h50 退 −6.32px，等于没修。
- C 只对 h0 放大 1.45×。利：折中。弊：h50 仍差 7.33px。

**决策 3：计算笔刷改采样后 fade 不可调，接受吗？**
- **A（推荐）接受**，README/发布说明写明「该笔在 Krita 里 fade 不可调，需回 PS 改后重转」。利：一次到位。弊：用户会问「为什么不能调硬度」。
- B 双轨（默认采样 + 保留计算笔刷开关）。利：不牺牲可调性。弊：两套产物、测试矩阵翻倍。
- C 只加提示不改类型。利：零成本。弊：不解决偏差。

**决策 4：生成的采样笔尖是否落盘进 bundle？**
- **A（推荐）落盘**：与「不设体积上限」口径一致、产物自包含。弊：下载变慢 +3–4.5MB/500 笔。
- B 只对 h<100 落盘。利：省 1/3 体积。弊：路径分叉。
- C 运行时不落盘。利：bundle 最小。弊：Krita 侧无机制，需改资源加载链，超出转换器职责。
