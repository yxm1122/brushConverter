## 五、遗留与风险

1. **`dyn-hits/` 不是本任务的产物**：`git status` 里的 `docs/数据/dyn-hits/hit-002.json`、`hit-003.json` 是 dyn30 写入的（任务书明确「不碰 dyn-hits/」，我全程只在 `%TEMP%\...\task31\work\` 与 Frida 内存里写数据）。验收时如果看到这两个文件，**不能算到 31 头上**。
2. **3 个未判定子项**：① H2 的 `+0x20`（静态对应 invertTexture）恒为 1，本实验从未设 invertTexture；② ABR 里 `linearHeight` 用的 4CC（`LghH` 被 PS 忽略，`stringID linearHeight` 的 interned id 是数字 `0x916`）未查样本；③ `Lght/Grdn/HdMxS` 判「读取失败」而不是「不存在」——PS 的模式候选集来自两张表，表里没有它们，但不排除另有入口。
3. **地址会随 PS 升级失效**：全部 `0x14…` 是 26.9.0.15 专用；`mode-ids.json` 里的 `runtime_id` 本身是**数据**（不含地址也可复用），但 `evidence` 串含地址 → 与 `candidates.json` 同样**只能留本地**，任务 39/90 脱敏时要么抽掉 `evidence` 里的地址、要么整文件不进公开仓库（见决策 2）。
4. **「JSX 设不了纹理混合模式」的旧担心被证伪**：上一轮未做切换实验，任务书 §五 留了这个预案。本轮做了 57 次 `putEnumerated(sid("textureBlendMode"), type, valueId)`，逐条结果是：
   - **45 次真的改变了模式**（`[rbx+4]` 从旧值变成期望值）且读回名正确；
   - **1 次**（`Hght` 4CC）值恰好等于上一步（height=40），**无法用值变化判别**，但读回名 `height` 正确 → 判接受；
   - **10 次被 PS 静默忽略**（模式停在 40，读回名仍是上一步的 `height`）：3 个反序 4CC 探针 + Lght×2 + Grdn×2 + HdMxS(str) + LghH + HdMx；
   - **1 次抛错**：`HdMxS` 用 charID 直接报错（`charIDToTypeID` 只接受 4 字符，是参数用法错误，不是能力缺失）。
   → 所以**本任务不需要人工手动切模式**，也不必改用预设集批量；这条限制从任务书 §五 的「待确认预案」降级为「已证伪」。
5. **本任务未做的事**：未下断点改内存（H2/H4 都是只读观测）；未做 PS 出图；未改 `mode-align.json`、`mapping.py`、`parameter-mapping.md`（见决策 1/3 与遗留 L-1/L-2）；未查 ABR 样本字节里的 `BlnM`。
