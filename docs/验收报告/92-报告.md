## 五、遗留问题（如实登记，不顺手修）

1. **ABR 直读冲突只能文档化，代码无法判定**：Krita 5.3 会把原始 `.abr` 当 Adobe Brush Library 直读，生成的同款笔刷与转换产物混在列表里，看起来像「纹理丢失」。转换器只能在 README FAQ 把「不要把 .abr 直接导入 Krita」列为第一检查项，**无法从代码侧检测或阻止**（读不到 Krita 的 resourcecache 使用意图）。
2. **`resourcecache.sqlite` 重建仍是可选项**：`integrity_check` 有轻微异常（Page 30779 never used + 两处索引条目数不符），但实测**不是**本缺陷的必要修复步骤；重建会丢自定义预设标签/分组（资源文件本身不丢）。取舍已写进 README FAQ 与 release notes。
3. **12 条纹理模式未判定不变**：U-1 像素消费端（谁把 texture brightness/contrast 变成像素）仍未定位；47 个模式中 24 个不可映射（16 结构性 / 8 无 PS 真值）。v1.3.1 未改映射表与纹理公式，故这批结论与 v1.3.0 完全相同，仍按「未判定/不可映射」如实记录，**没有清零**。
4. **流程改进（一句教训）**：本轮首轮隐私门的 23 条 block 全部来自「复现命令」把本机绝对路径原样抄进报告——**以后所有报告/文档的复现命令一律用占位符**（`<REPO>`、`<LOCAL_APP_DIR>`、`%USERPROFILE%`、`<TEMP>`），不要把可运行的本机路径当证据。本条只记流程，不再回头改他人历史文档。
5. **本任务未做的事**：未改任何 `src/`、`tests/`、`gui/` 代码；未改 `PUBLISHED_TAG` 常量；未动已发布 tag 与远端历史；未提交本报告与验收归档（按 lead 指示统一 commit）。
