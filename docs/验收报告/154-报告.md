## 二、根因证据

### 2-1 缺失 DLL = Git 自带 OpenSSL 3，且与 v1.4.0 包内条目逐位相同

| DLL | 字节 | sha256 | v1.4.0 GUI zip | v1.4.0 CLI zip | `<GIT_MINGW64_BIN>` 同名文件 |
|---|---:|---|---|---|---|
| `libcrypto-3-x64.dll` | 5,122,716 | `9c069dec902628c5e37f532a06f171c5b82333a3614e57db0d1429d70abc9892` | 存在，同 sha | 存在，同 sha | **同 sha** |
| `libssl-3-x64.dll` | 930,460 | `a9169d9b4350c934570c6912614dc76edadfae64469de802d5529b65f73f706c` | 存在，同 sha | 存在，同 sha | **同 sha** |

→ v1.4.0 包内这两个 DLL 的来源就是构建机 PATH 上的 Git for Windows OpenSSL 3，不是 conda 环境自带。

### 2-2 PATH 解析实验

用 PyInstaller 的依赖解析函数（`PyInstaller.depend.bindepend.resolve_library_path`）在 v1.4.0 worktree（`84f455d`）实测：

| 注入方式 | `resolve_library_path('libssl-3-x64.dll')` | `resolve_library_path('libcrypto-3-x64.dll')` |
|---|---|---|
| A：继承当前构建会话 PATH | `None` | `None` |
| B：Windows 风格前置 `<GIT_MINGW64_BIN>;` | `<GIT_MINGW64_BIN>\libssl-3-x64.dll` | `<GIT_MINGW64_BIN>\libcrypto-3-x64.dll` |
| C：POSIX 风格 `/c/.../mingw64/bin:` | `None` | `None` |

- 当前 PATH 只含 `%ProgramFiles%\Git\cmd`，不含 `mingw64\bin`，因此常态构建必然解析不到。
- POSIX 风格对 native Python 无效（本任务复测）：B 组必须走 Python `subprocess` 的 `env` 做 Windows 风格前置，bash 里 `PATH=/c/...` 不行。

## 五、结论与建议

### 5-1 结论

1. **N12 根因确定**：v1.4.0 构建会话 PATH 含 `<GIT_MINGW64_BIN>`，PyInstaller 将 Git 自带 OpenSSL 3 的 2 个 DLL 作为 `_ssl.pyd`/`_hashlib.pyd` 依赖收进 `_internal/`；v1.5.0 常态 PATH 无此目录，少 2 文件 / 6,053,176 B，另有 exe 源码增量 84,209 B，净差 5,968,967 B。
2. **不是 spec / 源码 / 包差异**：spec 两版逐字节未变；两包差异完全相同；公共文件 258/108 逐字节全等；v1.5.0 的 `dist/` 与已发布 zip 逐文件全等（构建现场可复算）。
3. **A/B 复现闭环**：同源码、同 spec、同 `<PY>`/PyInstaller，仅 PATH 单变量 → A 260/110、WARNING 6；B 262/112、WARNING 3；B 的两个 DLL sha256 与 Git 库、v1.4.0 包内条目三方一致；toc 明确指向 Git 路径。
4. **对产物功能无影响判定维持 140/141**：少收的 2 个 DLL 只是 conda `_ssl`/`_hashlib` 的可选依赖；`hashlib` 走内置 `_sha256` 回退，本工具不用 SSL/bz2/lzma/ctypes 路径（140 已用干净 PATH 复测功能通过）。**但这是环境敏感性，不是「等价构建」**：构建机 PATH 不同会改变产物文件数/体积。

### 5-2 可关闭「原因未定位」的措辞建议

1. **140 §8-2a**（6 条 WARNING）：建议在该条追加一句「已由任务 154 A/B 复现：6 条中 `libcrypto-3-x64.dll`×2 + `libssl-3-x64.dll`×1 只在构建会话 PATH 含 `<GIT_MINGW64_BIN>` 时出现（此时 2 个 Git OpenSSL DLL 被收进 `_internal/`，包增大 6,053,176 B）；常态 PATH 恒为 3 条（`liblzma.dll`/`LIBBZ2.dll`/`ffi.dll`），功能结论不变。」
2. **140 §8-2b**（体积与 115 记录不一致）：把「原因未定位（v1.4.0 打包现场在本机不可复现，spec 收集规则未变）」替换为「原因已由任务 154 定位：PATH 差异致 2 个 Git OpenSSL DLL 收录/未收录（6,053,176 B），叠加 exe 源码增量 84,209 B，净差 5,968,967 B；zip 差 2,298,564 / 2,300,277 B 逐项闭合；A/B 构建复现 260/110 ↔ 262/112、WARNING 6 ↔ 3 已闭环。」
3. **141 §七-2**：把「构建体积差异…原因未定位」改为「已由任务 154 定位并 A/B 复现闭环（PATH 环境敏感性，非代码问题）；不再作为开放问题，登记为『构建机 PATH 敏感』（developer-guide 新坑 #36）」。
4. 若 140/141 报告正文本轮不重写，可在本报告 §五 登记为勘误引用，后续发版时同步。

### 5-3 developer-guide 加坑建议（§7.4 打包层面，新增第 36 条）

> 36. **PyInstaller 的二进制依赖解析受构建会话 PATH 影响，包体积可差约 6 MB**。若 PATH 含 `<GIT_MINGW64_BIN>`（Git for Windows 自带 OpenSSL 3），`_ssl.pyd`/`_hashlib.pyd` 的依赖 `libcrypto-3-x64.dll`（5,122,716 B）+ `libssl-3-x64.dll`（930,460 B）会被收进 `_internal/`：目录 +2 文件 / +6,053,176 B（zip 约 +2.3 MB），构建日志少 3 条 `Library not found` WARNING；PATH 不含时相反。**POSIX 风格 PATH（`/c/...`）对 native Python 无效**，须 Windows 风格注入。发布前用 `resolve_library_path('libssl-3-x64.dll')` 自检，并在发布记录登记构建机 PATH 快照；不要用两版文件数/字节差反推代码变化。

### 5-4 流程建议

1. 打包脚本记录构建环境快照（PATH、Python、PyInstaller 版本）到构建日志。
2. 发布前对产物做规模断言：GUI 260 文件 / 155,699,283 B、CLI 110 / 57,872,465 B（v1.5.0 基线），偏差即说明构建环境漂移。
3. 构建脚本可不依赖会话 PATH：如需稳定产物，可在打包命令上显式设置干净 PATH（或反之固定收录 Git DLL，二选一并记录）。

## 七、遗留与边界
