## 四、取舍与判定（为什么这样决定）

1. **为什么公开侧几乎不迁移**：公开目录里，参数矩阵/数据/INDEX 是生成物与机器引用，研究报告/验收报告/截图是证据链，README/RELEASE_NOTES 是对外入口且不在 164 白名单。强行搬家会先破坏回归与证据链，再破坏索引校验——与「归档不得破坏工具或证据链」直接冲突。结论：公开侧只列 1 份零引用孤儿（A1），其余按「原址留存 + 逻辑归档」处理。
2. **为什么不重生成 INDEX**：重生成会把未跟踪的预写 187 报告纳入公开索引（本轮实测 114→115）。宁可让检查项红着并写清原因，也不制造「未授权公开」。
3. **为什么本任务没有业务提交**：两份白名单产物都在 docs/工作流程/，该目录整目录被 .gitignore 忽略（第 67 行，git check-ignore 命中）。铁律要求「不用 git add -f」，因此**没有可提交的业务文件**；强行提交等于用 -f 绕过忽略规则。
4. **为什么把 gitignored 迁移标为高风险**：内部规划目录的移动不产生 git 历史，回退只能靠迁移记录 + 备份。清单已要求 164 先备份到 .tmp/164/backup/ 并逐条留记录。
5. **为什么不替使用者决定**：K1–K4 都涉及「要不要扩白名单 / 要不要批准整族迁移」，属产品与范围决策，只登记不执行。
