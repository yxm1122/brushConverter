## 一、任务结论

**部分完成（完整产物未能复现故障；失败层已定位到「使用者侧 bundle 文件不完整/缺失 + 资源库 cache 损坏」，而非转换代码）。**
在隔离 profile（干净沙箱 + 使用者真实 profile 只读副本）里，完整 v1.3.0 bundle 的「bundle 注册 → 19 预设可见 → 内嵌纹理侧载 → 纹理参与渲染 → 同名覆盖后重启」五层全部正常；
使用者真实 resourcecache.sqlite 的 integrity_check 报损坏，且 10:41 快照中完全没有我们 bundle 的任何记录。
本轮还复现了两种**等价症状**（E3/E5）：bundle 文件被删 → Krita 静默删掉整包 19 个预设（笔刷不可见）；bundle 被截断 → 预设仍可见可画但内嵌纹理侧载静默失败（纹理丢失，Alpha 8844→4672）。
结论：完整产物无缺陷；使用者现场最可能是其磁盘上的 .bundle 文件不完整或被移除。

## 四、复现命令（别人可照抄重跑）

前置：Krita 5.3.3 在 <LOCAL_APP_DIR>\Krita (x64)；脚本在 %TEMP%\brushconverter-team\bugrepro\。

1) 干净沙箱 + v1.3.0 bundle（注册层 + 落笔）：
   python run_gui.py --label B-paint --reset --sandbox %TEMP%\krita-sandbox\gui ^
     --bundle "D:\Document\test\brushConverter-v1.3.0-win64\brushConverter\converted\海怪笔刷-详情展示的勾线笔套装组18_test.bundle" ^
     --timeout 150 ^
     --job "006_大怪兽-碳铅_用数位板.kpp|runs/B-paint/stroke_006.png|120|100|100"

2) 覆盖场景：先放 v1.2.0 同名 bundle 跑一轮，再 --bundle 传 v1.3.0 同名文件（覆盖）跑一轮，对比 cache 与侧载纹理名。

3) 使用者 profile 副本：把 %APPDATA%\krita 只读复制到 %TEMP%\krita-sandbox\E\res，然后：
   python run_gui.py --label E1-profile --sandbox %TEMP%\krita-sandbox\E --job "006_…kpp|…png|120|100|100"

4) 隔离必须做对（三个坑，详见研究报告第二节）：
   - 不要用 APPDATA/LOCALAPPDATA 环境变量（Qt 走 KnownFolder）；
   - 不要用 --resource-location（PyKrita 插件会静默不加载）；
   - 正确做法：临时改真实 kritarc 的 ResourceDirectory=沙箱目录 + 插件临时装真实 %APPDATA%\krita\pykrita，跑完按字节还原（脚本已实现并核对 sha256）。

## 五、遗留与风险（含本任务未做的事）

1. **完整产物未复现**：在干净沙箱、真实 profile 副本里都没有观察到「纹理全部丢失/笔刷彻底不可见」；只有产物文件缺失/截断时才复现出等价症状。
2. **未做**：使用者现场取证（Manage Resources 截图、覆盖动作还原、重建 cache 后是否恢复）；也没有拿到使用者磁盘上那个 .bundle 的完整性与 sha256（本组不能动其真实目录）。
3. **风险**：本组所有 GUI 实验临时改过真实 kritarc 与真实 pykrita 目录（均字节级还原并核对）；真实 resourcecache.sqlite 未改动（mtime/size 全程不变）。
4. **未能验证**：使用者 cache 损坏的成因（是异常退出、磁盘问题还是 Krita 写坏），以及损坏与其「纹理丢失」感受之间的因果。
