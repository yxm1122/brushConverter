## 四、必答项

### 4.1 缩放到底准不准？不准的话是哪一类？

**缩小（50%）准；放大（150%/200%）部分准，且随倍数单调变差。** 判据三条，全部指向**重采样差异**：

1. **不是「机制错（1/scale vs scale）」**：幅度比 `mean|R_ps|/mean|R_k|` = **1.019（150%）/ 1.054（200%）**。
   若 PS 按 1/scale、Krita 按 scale，该比值应落在 ~0.67 或 ~2.25 量级；同号率 0.929/0.898、r=0.974/0.946
   也说明两边的响应方向一致，只是幅度略有系统偏差。
2. **不是「取整/量化」**：S=50% 时 max|ΔR|=**1**（这就是纯量化/取整的量级）；S=150/200 时 max|ΔR| 跳到
   **54–56（d60）/ 91–93（d100）**，量级差 50 倍以上，量化解释不了。
3. **是「重采样差异」**：相对残差 `mean|ΔR|/mean|R_ps|` 在 S=150 恒为 **22.2% / 22.3% / 22.3%**、
   在 S=200 恒为 **32.4% / 32.4% / 32.4%**（对应 d10/d60/d100），**与深度无关**；而 S=50 时仅 **0.8%**。
   若误差出在深度/强度映射，它应表现为与深度相关的近似常量偏移；实测是「恒定百分比 × 图案变化幅度」，
   即误差出在「被缩放后的图案本身」。残差与 PS 局部梯度正相关（0.370–0.400 @150%、0.276–0.286 @200%），
   且 `align_translate` 对 S=150/200 也给出 dx=dy=0（无整体相位错位）→ 是**局部插值核不同**：
   Krita 走 Qt `SmoothTransformation`，PS 走自己的缩放算法；缩小方向两者近似一致（0.8%/max 1），放大方向分离。

### 4.2 深度到底准不准？从哪个 depth 超阈？

- **multiply：准，没有任何深度超阈。** d10/d60 的 mean\|ΔR\|=0.00、max=0、r=1.0000，逐像素完全相同；
  d100 是基准点（R≡0 属定义）。前提是保留 `UseSoftTexturing=true`：关掉后 d10/d60 立刻变成 229/102。
- **linearHeight：不准，且不是「从某个 depth 开始」而是 d>0 起就存在。**
  偏差 = **2q**，随 q=round(2.55d) 线性增长：d10 时 **2×26=52**（实测 max 恰为 52、mean 43.31），
  远超「不准」阈 25；d≥60 时两侧同时饱和成 255，把偏差推到不可观测区间（所以只有 d10 可判读）。
- **量化不是原因**：PS `q=round(2.55d)` 与 Krita `strength=round(d/100×255)` 在 d=10（26）、d=60（153）上**完全相同**；
  量化阶差最大只带来 **2 灰度级**（修法验证里 max=2），与 52 差两个数量级。
- **根因**：高度系公式权重 `PS W=12`（`ps_mask: HEIGHT_WEIGHT=12`）vs `Krita W=10`（`texture_mask: 10·s`），
  归一化后 `PS=12q−u`、`Krita=10q−u`，差 2q。语义层 64×64 独立复核同样得 43.17/52，确认是公式常数差。

### 4.3 最小改动与预期收益

| 目标 | 最小改动 | 预期收益 |
|---|---|---|
| linearHeight / height 深度 | 转换链高度系 `Texture/Strength/Value`：`depth/100` → `min(1.0, 1.2×depth/100)`（即 `q'=min(255, round(1.2q))`） | d10：mean\|Δ\| **43.31 → 1.39**，超阈像素 **95.36% → 0.00%**，max 52 → **2**；d60/d100 不变（本就饱和）；multiply 不动 |
| multiply 深度/缩放 | **不改**（现状已 0.00）；必须保留 `UseSoftTexturing=true` | 删掉即退回 229/102 常量偏差 |
| 150%/200% 缩放 | 转换侧无可用常数；如需更准只能改重采样口径（按预设自身 scale 预缩放内嵌图案并把 Pattern/Scale 写 1.0） | 未验证；需先用 PS 采样核定标，且会改纹理像素字节，本次不做 |

## 七、决策记录（lead 代为决策）

| 决策点 | 选项 | 选择 | 一句话理由 |
|---|---|---|---|
| 2×2 主口径用 conv 还是 raw | conv / raw / 两者并列 | **conv 为主，raw 作对照** | conv 是用户实际拿到的预设；raw 用于隔离「换算贡献」，两者在缩放表里响应曲线完全相同，raw 只在深度表提供「软纹理承重」证据 |
| d100 的 2×2 表全 0 怎么处理 | 直接报全 0 / 补 d<100 行 / 换基准深度 | **保留规定行 + 补 d10/d60 行并标注** | 规定行必须交；但 s=1 使引擎差数学上消失，只报全 0 会得出「引擎本来就一致」的错误结论 |
| linearHeight d100 全 0 算什么 | 算「准」/ 标注不可判读 | **标注不可判读** | 两侧都饱和成 255，四格全 0 没有信息量，不能当「准」 |
| 深度基准 | 与 d100 比 / 与 d10 比 / 与无纹理参考比 | **与 d100 比** | multiply 在 d100 是恒等变换、是唯一无衰减锚点；linearHeight 的 d100 饱和但仍在两侧同值，作基准可保持口径一致，且已标注「单点」 |
| 缩放判读是否用 texture_mask 预测 | 用 / 不用 | **不用** | Krita 在 scale≠100 走 Qt 平滑重采样，预测器不覆盖（Krita 侧报告 §9 已定位为预测器限制），必须图像↔图像比 |
| linearHeight d10 的缩放判档 | 记「部分准确」/ 记「受污染」 | **记「部分（受污染）」并在表中注明** | 它的残差里混着 W=12/10 的深度偏差，不能单独归因于缩放；如实标注比给一个假结论更可靠 |
| 缩放修法 | 给常数修法 / 判为无解 | **判为转换侧无解，只给未验证的可选口径** | 重采样发生在 Krita 内部，转换链没有对应参数；预缩放内嵌图案会改纹理字节且未定标 |
