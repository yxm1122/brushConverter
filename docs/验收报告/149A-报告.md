## 一、根因与改动位置

### 1.1 根因（A 级：源码链 + 148 实测）

Krita 把同一个曲线选项下**所有加法型传感器**的值求和，再乘 `RotationValue`（=`m_strengthValue`）参与模 2 环绕：

```text
research/KisCurveOption.cpp:112-114
    if (s->isAdditive()) {
        components.additive += valueFromCurve;      // fuzzy 与 fuzzystroke 都走这里
        components.hasAdditive = true;
    }
research/KisCurveOption.cpp:61-70
    rotationLikeValue = wrapValue(2*offset + constant*(scalingPartCoeff*realScalingPart + realAdditivePart), -1.0, 1.0)
```

- `fuzzy`（每 dab 随机）与 `fuzzystroke`（每笔划一次随机）**都是** `isAdditive()==true` ⇒ 两个 [−1,1] 相加 ⇒ 加法分量范围 [−2,2] ⇒ 随机跨度 **2×360°×R**。
- PS 的 `angleDynamics` 是**逐 dab** 随机，没有「整笔同随机」这一层 ⇒ 正确跨度 **360°×R**。
- 148 实测（A 级，`.tmp/random/148/`）：带双源的现产物 j=25 角半跨度 136.20° vs PS 92.51°（**+38.20%**，超判据）；只留 fuzzy 的候选 87.26°/174.11°/174.11° ⇒ −5.84%/−2.77%/−1.95%，三点 PASS。

## 四、影响面（旧 .kpp / 发布口径）

1. **所有 `angleDynamics.jitter>0` 的旧 `.kpp` 必须重转**（发布说明必须写）。
2. **j<50**：旋转抖动随机幅度**减半**（旧产物跨度 2×360°×R，新产物 360°×R = PS 口径）。这是本次修法的**目标修复**：旧产物在 j<50 时抖动幅度约为 PS 的 2 倍。
3. **j≥50**：两侧都铺满整圈（跨度饱和），**视觉等价**；但随机源个数已变、随机序列不同 ⇒ 按「随机幅度口径变化」登记（渲染结果不会与旧 .kpp 逐像素相同，属随机档预期）。实测 R̄ 0.004–0.045（新）vs 0.039–0.041（旧），分布形状同级。
4. **bVTy=6/7/8 且 jitter>0**（控制源 + 随机抖动）：加法随机分量同样减半（同机制、同 RotationValue 缩放）。148 只在 R=0（§4.2）与 R=1（§五 反例 20–40° 噪声）两端测过，**本轮未单独实机重测**；下一轮/人工抽验口径见 §八 遗留 2。
5. **不受影响**：jitter=0 的旋转（`RotationValue=0`，随机分量恒 0）；jitter=0 且无控制源的「旋转关闭」分支；bVTy=2（压感旋转）路径；散布档（÷200）与纹理/尺寸/不透明度等其它动态；`.kpp` 的资源名/哈希（本改动不涉及纹理字节）。
6. **回退方式**：只有 `git revert` 本任务提交（改回双随机源 = 恢复 j<50 幅度翻倍的旧行为）；无运行时开关。
