### 3. 【重要】发现的打包缺陷与修复（阻断发布级）

**现象**：用未改动的 spec 打出来的 CLI，`convert` 必然崩溃（GUI 的转换路径同理）：

```
$ dist/brushconverter-cli/brushconverter-cli.exe convert "tests/海怪…18支.abr" -o dist/_selftest_131/out/run1
Traceback (most recent call last):
  File "xml\etree\ElementTree.py", line 1515, in __init__
  File "pyimod02_importers.py", line 457, in exec_module
  File "xml\parsers\expat.py", line 4, in <module>
ImportError: DLL load failed while importing pyexpat: 找不到指定的模块。
  …
  File "brush_converter\convert.py", line 292, in count_real_textures
  File "brush_converter\convert.py", line 263, in kpp_has_real_texture
  File "xml\etree\ElementTree.py", line 1520, in __init__
ImportError: No module named expat; use SimpleXMLTreeBuilder instead
[PYI-19944:ERROR] Failed to execute script 'cli' due to unhandled exception!
```

**根因**（构建日志原文）：`WARNING: Library not found: could not resolve 'libexpat.dll', dependency of '…\envs\brushConverter\DLLs\pyexpat.pyd'.`
——v1.3.1 的 `convert.py` 新增了 `xml.etree.ElementTree` 用法（输出校验/真实纹理计数），
而 `pyexpat.pyd` 依赖的 `libexpat.dll` 在 conda 环境里位于 `Library\bin`，不在 PyInstaller 的二进制解析路径上，
于是 `pyexpat.pyd` 被收进包、它的依赖 DLL 没被收 → 打包后 `import pyexpat` 失败。
（v1.3.0 没这个问题，因为那时 `convert` 不走 ElementTree。）

**验证性实验**（只往 dist 里补 DLL，不改仓库）：把 `Library\bin\libexpat.dll` 复制进 `_internal\` 后，
同一条 `convert` 立刻成功并输出 §三-4 的完整三行 → 确认唯一缺失就是它。

**两种修法的取舍**：

| 方案 | 结果 | 取舍 |
|---|---|---|
| A. 构建时把 `Library\bin` 加进 `PATH` | 能修好，但 PyInstaller 顺带多收了 6 个 DLL（`LIBBZ2.dll`、`ffi.dll`、`libcrypto-3-x64.dll`、`libssl-3-x64.dll`、`liblzma.dll`、`libexpat.dll`），包体 **+9.3 MB** | 不写仓库，但不可复现、包体虚胖，**未采用** |
| B.（采用）两个 spec 里按 `sys.prefix` 派生路径显式收集 `libexpat.dll` | 只多 **1 个文件**（281,416 B），其余文件集与 v1.3.0 逐项相同 | 改构建配置（不改业务代码），可复现、可解释，**采用** |

spec 里的改动（两个 spec 完全相同的一段，CLI/GUI 各一处）：

```python
# v1.3.1 打包修复：convert.py 新增 xml.etree.ElementTree 的运行时用法（输出校验/真实纹理计数），
# xml.parsers.expat 依赖 pyexpat.pyd，后者又依赖 libexpat.dll。该 DLL 在 conda 环境里位于
# Library/bin，不在 PyInstaller 的默认二进制解析路径上（旧构建日志会警告
# "Library not found: could not resolve 'libexpat.dll'"），结果是打包后 convert 直接抛
# ImportError: DLL load failed while importing pyexpat。这里按 sys.prefix 派生路径显式收集，
# 不写死本机绝对路径；找不到时退化为空列表（与旧行为一致，不会让构建失败）。
import sys as _sys
from pathlib import Path as _Path

_EXPAT_DLL_CANDIDATES = [
    _Path(_sys.prefix) / "Library" / "bin" / "libexpat.dll",
    _Path(_sys.prefix) / "DLLs" / "libexpat.dll",
]
binaries = [(str(p), ".") for p in _EXPAT_DLL_CANDIDATES if p.is_file()]
```

修复后构建：`CLI_EXIT=0 CLI_SECS=26`、`GUI_EXIT=0 GUI_SECS=89`，
`dist/…/_internal/libexpat.dll` 281,416 B 两包都在，构建日志里 `libexpat` 警告 0 条。
