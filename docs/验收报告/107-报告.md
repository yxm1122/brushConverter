## 2. 逐参数

### 2.A 散布（scatter）：**试了确定性拟合 → 实测不达标 → 回退，降级「需校准」**

**证据（106）**：增量口径 `band_height(v)-band_height(0)`，PS 63 / 274 px，Krita 38 / 134 px
（相对误差 39.7% / 51.1%）；当前换算 `ScatterValue=jitter/400`。
命令：`python tools/measure_deviation.py --param scatter --values 0,100,300 --analyze`（数字取自 `results_scatter.json`）。

**为什么线性系数不可能同时对**：100% 点需把 `ScatterValue` 放大约 ×1.6（0.25→0.39~0.43），
300% 点需 ×2.2~2.3（0.75→1.65~1.73）——偏差随散布量增大，属响应形状差异
（PS 增量 63→274 是 3× jitter 换 4.35× 增量，超线性；Krita 带高近似线性）。

**做了什么**：
1. 读 Krita 源码确认机制：`research/KisScatterOption.cpp:36` 偏移 =
   `U(−1,1)·diameter·sensorValue`（线性、均匀），所以 Krita 侧带高应 ≈ `100+158·s`。
2. 渲染 13 张探针（`ScatterValue` 0.25/0.32/0.40/0.75/1.2/1.4/1.5×3/1.6/2.0/2.5/3.0），
   斜率 129–183，确认线性量级；同时发现**同一配置两次复现差很大**（1.5 档三次：338/374/324；
   0.25 档三次：138/142/129）。
3. 按 `s = G(j)/158`（`G(j)=0.4883j+0.0014167j²`）反解出确定性二次式
   `s = 0.34·j′ + 0.07·j′²`（j′=jitter/100），在 `preset_xml.build_preset_xml` 里实现并复测：
   **100% 增量 71 / 66（目标 63，+12.7% / +4.8%）；300% 增量 275 / 197（目标 274，+0.4% / −28.1%）**。
4. 300% 同一配置两次差 78px（297↔375）→ 该统计量（约 10 个笔尖的极值 + 每次会话随机种子）
   复现性 ±7–13%，**2% 判据在这种噪声下无法证明**。按任务口径回退。

**回退后代码**：`src/brush_converter/kpp/preset_xml.py:484-487` 仍是 `scatter_amount/400`，
只加了三行结论注释（行为零变化；`results_scatter.json` 与 106 逐字节一致）。

**残差与原因（写入 `docs/parameter-mapping.md` §10.3）**：
- 100%：39.7%；300%：51.1%（Krita 恒偏小，笔迹更集中）。
- 修不掉的原因两条：① PS 响应超线性 vs Krita 线性（形状差，不是系数差）；
  ② 判据用的 `band_height` 是极值统计，复现性就有 ±7–13%，≤2% 不可证。
- 下轮建议：换分布型统计量（Alpha 加权行标准差 + 多次重复平均）或固定随机种子，再谈系数。

### 2.B 间距（spacing）：**已改：采样笔尖 spacing × 短边/长边**

**证据（106 §4）**：Krita/PS 步长比 ≈ 笔尖长宽比——非方形 1.253/1.281/1.325（长宽比 1.280）、
方形 1.013–1.020（1.024）、计算笔刷 0.982–1.000（1.000）。PS 对非方形笔尖的间距基准是
**渲染后短边**（143/183×112=87.5，与 PS 实测 8.78/43.72 吻合到 0.3%），而补白让 Krita 的基准变成
正方形边长（=长边 112）。→ 只改「尺寸/间距换算」这一层，补白不动。

**改了什么**：
- `src/brush_converter/mapping.py:126` 新增字段 `BrushPreset.spacing_basis`（默认 1.0）；
- `src/brush_converter/mapping.py:267-275` 在 `map_presets` 里由原始笔尖宽高算
  `spacing_basis = min(w,h)/max(w,h)`（严格正方形=1；近方形按实际比值，如 84/86=0.977；计算笔刷=1）；
- `src/brush_converter/convert.py:428-442` `_sampled_brush_def()` 写 XML 时乘上该比值；
- `src/brush_converter/convert.py:341` 只加一行注释说明补偿位置（`_square_tip` 调用本身未动）；
- 计算笔刷走 `_computed_brush_def()`，`spacing` 原样，无补偿。

**改前/改后（同一批 PS 真值图，同一命令，`--skip-ps --force` 只重渲 Krita 侧 9 张）**：

命令：`python tools/measure_deviation.py --param spacing --values 10,50,100 --skip-ps --force`

**结论**：8 个可判读点里 7 点 ≤2%，非方形两点从 25–28% 降到 0.1–0.2%（10 倍以上改善）。
脚本参数级仍判「真偏」（1 点超阈），逐点数字见 `docs/数据/偏差/results_spacing.json`。
Krita 侧实际装入的预设回读（`manifest.json` 的 `krita_readback.spacing`）：
nonsquare 0.0781421 / 0.39071 / **0.781421**（=10/50/100% × 143/183）、
square 0.0976744 / 0.488372 / 0.976744（×84/86）、computed 0.1 / 0.5 / 1（未补偿）。

**残差（3.53%）原因**：PS 侧 100% 点自身偏离短边模型——按短边应 87.5px，PS 实测 84.51px
（−3.4%，该点只有约 3.6 个周期，106 §4.2 已标注为少周期估计偏差）；Krita 改后恒为
112×143/183 = 87.49px。10%/50% 两点吻合到 0.2% 说明换算关系本身对，**再调系数只会把

根因是补白给笔尖加了墨色边，按铁律 17 不许改。即：**间距已对齐，笔迹仍偏大**。

### 2.C 硬度（hardness）：**不改，降级「需校准」**

**证据（106 §3.4）**：过渡宽 PS/Krita：h0 78.75/63.15（+15.60px）、h50 32.38/39.71（−7.33px）、
h100 1.88/0.81（Δ1.07px，≤2px 一致）。

**做了什么**：读 Krita `hfade` 语义（实心区占半径比例，fade∈[0,1]）+ 两次探针实测：

| 探针 | Krita 过渡宽 | 对照 PS |
|---|---|---|
| `fade=0.59`（两次复现完全相同） | 33.14px | h50：32.38px → 2.35% |
| `fade=0.60` | **32.39px** | h50：32.38px → **0.03%** |
| `fade=0`（106 实测，Krita 最软档） | **63.15px** | h0：78.75px → **+15.60px（19.8%）** |

**结论**：
- h50 **可以单点修**（`fade≈1.2×Hrdn/100` 即 0.60 → 32.39px）；
- h0 **结构性不可达**：`fade=0` 已是最软档，Krita 过渡宽上限 63.15px < PS 78.75px。
  要再宽必须改直径（尺寸，106 判不偏、禁改）或加 `Sharpness/softness`（会同时影响所有硬度档，
  且属新机制无证据）。
- 因此「同时满足 0/50/100」不可能，按任务口径**回退不改**（不用单点经验系数掩盖 h0 的结构性差异），
  代码 `src/brush_converter/kpp/preset_xml.py:192` 仍是 `fade = hardness/100`，
  `tests/test_mapping.py` 不受影响；新增用例把 0/0.5/1 三个值钉死。

**残差（写入 `docs/parameter-mapping.md` §10.2）**：h0 +15.60px（19.8%）、h50 −7.33px（22.6%）、
h100 一致。根因分层（106 已给）：h0 主要是「PS 软边伸出标称直径、Krita 停在半径」的尺寸基准差，
h50 是曲线差。下轮若修，必须同时解决软边尺寸基准。
