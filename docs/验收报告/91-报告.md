## 四、关键设计取舍（为什么这么做）

### 4.1 先验收后发布，且发布不可撤回

发布一次就对外可见，回退只能再发一版。所以三道门槛（全量验收 / 隐私门 / 全量回归）全过才允许 `git tag`。本次确实按此执行：隐私门第一次复核 `block=6` 时**没有**打 tag/推送，改完重扫到 `block=0` 才继续。

### 4.2 本轮不做功能开关（使用者裁决）

直接改默认，风险由「每批改前/改后各跑一次全量回归 + 留数字」补偿；回退手段是 `git revert` 到 `85aae49`（v1.2.1）。三批模式转正的改前/改后回归数字见 34/35/36 报告。

### 4.3 人工项不代填

界面类验证（双击 exe、Krita 里导入、目检截图）一律由使用者执行，AI 只给动作与期望结果。

### 4.4 隐私门首次挡下发布（如实登记）

`40-报告.md` 的「复现命令」段曾原样抄入两条本机变量（Python 安装目录、Temp 目录），隐私门判定 `block=6`（工作区 3 + 未推送历史 3）。处置：就地把两行改成 `<LOCAL_APP_DIR>` / `%USERPROFILE%` 占位符，`git commit --amend` 改写未推送 tip，重扫 `block=0`。**没有**为了过门而删除真实数据或牺牲可复现性。
