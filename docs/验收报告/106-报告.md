## 三、测量脚本改动与已修 bug（只动测量工具）

`tools/measure_deviation.py` 前一位成员已搭好框架（命令行/PS_JSX/Krita 生成段沿用），本次改动：

| # | 问题（实测证据） | 修法 |
|---|---|---|
| 1 | 步长估计器在多数点失效：搜索窗 `[0.25D,2.2D]` 把 10% 间距的真周期（0.1D）挡在窗外；未去趋势的 FFT 主峰被笔划两端包络抢走（computed 10% 报 1280px）；平滑包络的自相关在 1/2、1/4 周期上有同级假峰（computed 50% 报 50.5px、Krita square 10% 报 15.18px） | 改为「扇贝极值 + Hann 窗细网格直接 DFT」双估计 × 4 路信号（mass/cnt8/cnt64/cnt160）共 9–12 路投票，5% 聚类取中位；搜索窗 `[0.5,2.5]×标称步长`；新增「轮廓调制 ≥0.5%」门（Krita 计算笔刷 10% 的轮廓调制仅 0.22%，旧实现会把它伪报成 48.2px） |
| 2 | 尺寸测宽只看笔划正中一列：间距=100% 时中列正好落在相邻笔迹切点，Krita size=20 实测中列 alpha 全 0 → 宽度记 0（旧输出 `Krita宽=0 误差=0.00%` 假一致） | 改为逐列 50% 宽度（含亚像素），取 ≥0.95×最大值列的中位数（=笔尖渲染直径）；并给尺寸加「绝对差 ≤2px 亦算一致」判据（与项目口径一致，记录在报告 §3.3） |
| 3 | 硬度过渡宽扫不到硬边：`cross()` 扫描上界停在包围盒边缘，硬边的 90%/10% 落差正好在 `x1+1` → h=100 两侧都返回 None（旧输出 `None/None`） | 扫描上界越过包围盒 2px；h=100 现在两侧 1.88px / 0.81px |
| 4 | `--analyze` 会覆盖 manifest 里上一次真实出图的 PS 回读字段（48 条目 `ps_readback` 一度清零） | 改为「新条目缺字段时继承旧条目」，并把 Krita 预设回读改为从 `kpp/*.kpp` 直接解析（不再依赖渲染时的瞬态变量） |
| 5 | 隐私门：manifest 的 `cmd` 带本机 Python 绝对路径、`ps.exe`/`krita.exe` 带盘符；`results_*.json` 的 `ps_file`/`kt_file` 是绝对路径 | `cmd` 改成 `python tools/measure_deviation.py …`；可执行文件只留文件名；分析结果里的图路径改成仓库相对路径 |
