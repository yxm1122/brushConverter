## 六、决策项（需使用者追认；本轮按推荐项执行）

### 决策 1：散布已判「可行」全量程落地，不存在「区间外提示」——是否仍要在 UI 加说明？

1. **（推荐）不加提示**。利：129 判「可行」（0/5 超、最大 0.21%），全量程 0–1000% 都被 ÷200 覆盖，没有区间外可提示；旧产物差异只会体现在「旧 .kpp 的散布小一半」→ 用发布说明的「旧 .kpp 必须重转」覆盖。弊：用户若拿着旧 .kpp 对比 PS 仍会觉得散布小，需要看发布说明。
2. 在 GUI 加一句「散布换算已更新，请重转旧预设」。利：用户不容易踩旧产物；弊：新提示要改 `gui/i18n.py`（137 统一改），且与「不留开关」无关但增加 UI 噪音。

### 决策 2：散布/旋转用「闭式 + 单个常数」而不是 LUT——接受吗？

1. **（推荐）接受闭式、不引入 LUT**。利：0 表行、0 维护成本，129 已证明 ÷200 单参数就过判据（再拟合只多 0.22% 无收益）；单元测试钉死 5 个点即可。弊：以后若发现非线性（例如 PS 高量程截尾），需要重新开实验而不是改表。
2. 引入 LUT（j→s 查表）。利：将来非线性时只改表；弊：任务书要求写清段数/定义域/越界且加测试，本轮没有拟合证据支撑任何表行，属于无证据的复杂度。

### 决策 3：bVTy 1=渐隐 / 3=倾斜 / 4=转轮 本轮未映射（Krita 有同名传感器但语义不同）——继续这样处理？

1. **（推荐）维持「None + 告警」**。利：不把「丢效果」伪装成「错效果」；126 只给到 ⚠️，4 还需硬件实机；F-7 一并复测后（40–60 分钟）再决定是否做映射。弊：这 3 个控制源的旋转动态在 Krita 里仍然丢失（有告警）。
2. 直接映射到 fade/ytilt/tangentialpressure。利：至少「有动态」；弊：语义不等价、4 未实机确认，可能产生用户看不出原因的怪旋转，且违背「未量测不落地」。
3. 只映射 1→fade（唯一有近似语义的）。利：比全不映射多救一个；弊：PS 用 fStp 步数、Krita fade 距离/时间，需标定 fStp→fade 参数，属新实验。

### 决策 4：bVTy 7=速度 / 8=旋转 是新增映射，但 42MB 样本里 0 次出现、未实渲——保留吗？

1. **（推荐）保留**。利：修正「7 被静默错当 drawingangle」「8 被静默丢弃」两个真错；XML 合 `krita_caps.json` A 级 id 全集与 `KisKritaSensorPack` 读取逻辑，单测固定。弊：无 ABR 样本、未实机，若某 Krita 版本对 speed/rotation 另加参数（fade 距离之类）需补测。
2. 改为 None + 告警（保守）。利：不引入未实机路径；弊：等于承认「知道怎么映射但不做」，且 8 继续丢弃。
