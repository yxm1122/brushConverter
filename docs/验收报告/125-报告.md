## 一、结论速览（六参数）

| 参数 | 结论（一句话） | 置信度 |
|---|---|---|
| 纹理亮度 | PS 侧原值透传无上限；Krita 掩码管线读取无上限，作用顺序是「减亮度 → 乘对比度 → 截断 → 反相」；现行 calibrated 闭式解无需改动 | **A** |
| 纹理对比度 | **C>50 可以精确表达**：写 `Contrast=4.0`（对应 C=75）、`1e6`（对应 C=100）后，Krita 渲染与 PS 真值 **0.00% / max 0**（四档 C=0/50/75/100 全部如此）。上限只存在于「Krita UI 滑块 0..2」与「转换器自己写的 `min(2.0,k)`」 | **A** |
| 纹理深度 | PS 语义 = 8bit 量化深度进模式算子权重（高度系权重 12×q）；PS 侧只有 [0,100] 的 clamp。**depth>83% 的「强度封顶」在像素上不可观测**：PS 高度系在深度约 17% 起就全饱和（实测 d=25/50/100 的六张 PS 真值 alpha 唯一值均为 1） | A（饱和实测）/ B（「封顶无像素后果」依赖拟合式与饱和实测两点） |
| 最小深度 | Krita 侧作用点确定：**强度参数空间的曲线 0 端点**，而且曲线是**乘性**的（强度 = 属性值 × 曲线值；实测：同曲线下只改属性值 0.72→1.0，alpha 均值比 0.7226）。由此发现**现行换算多乘了一次深度**：曲线 0 端点应写「比值」而不是「绝对值」，否则低压力端被额外按深度打折（深度 50% 时差 2 倍、10% 时差 10 倍、100% 时无误差）。**PS 侧作用点仍未定**（参数地板 vs alpha 地板）→ 五项拟合交接单 | Krita **A**（源码）+**B**（乘性实测）／PS **C** |
| 纹理缩放 | **>200% 也不是上限**：PS 读回接受并执行 200/300/400%；Krita 掩码管线读取无上限，写 3.0/4.0 同样执行。两侧语义一致（都是「图案位图按倍率重采样后平铺」，阶梯纹理逐段对齐，max 差 ≤2）。200% 的 32.4% 残差来自**重采样相位/核**，与上限无关 | **A** |
| 模式（hardMix 边界） | PS 的实色混合在满覆盖笔尖上**恒 255 且与深度完全无关**（d=0/10/60/100 四张 PS 真值逐像素相同）；Krita 的算子把强度乘在笔尖 alpha 上，深度<100% 时偏离极大（实测 d10 差 95.33%、d60 差 52.44%、d100 差 1.03%）。**可绕开且不需要预烘焙**：强度固定 1.0 + 亮度偏置 +0.004 → 三个深度全部 **0.00% / max 0** | **A** |

## 二、三个结构性上限：归哪一侧

| 上限 | 归属 | 关键数字（可复跑） | v0.14 预烘焙 |
|---|---|---|---|
| 对比度 > 50 | **两侧都不是**：是 Krita UI 滑块 + 转换器自设 clamp | C=75（Contrast 4.0）、C=100（Contrast 1e6）两组 vs PS 真值均 **0.00% / max 0**；PS 自身 C=50→75→100 像素差异 49.82% / 25.56%（单调未截断） | **不值得**：改映射（删除 clamp）即可 |
| 深度 > 83% | **Krita 侧**（强度参数域 [0,1] 的收边），**但无像素后果** | PS 高度/线性高度真值在 d=25/50/100 共 6 张 `alpha_unique=1`（全 255）；理论全饱和阈值约 d≈16.7%；可分辨窗口只需强度 ≤0.2 | **不值得**：没有像素可挣 |
| 缩放 > 200% | **两侧都不是**：PS 定义域到 1000%、Krita 读取无上限；残差是重采样实现差 | PS 200% vs 300% 差 92.0%、300% vs 400% 差 83.0%；Krita 300% vs 400% 差 84.0%；阶梯纹理两侧 200/300/400% 均 **0.00%（max ≤2）** | **值得，但变量要改**：应做「按 PS 相位预缩放图案 + Krita scale=1.0」，不是「突破 200%」 |

**一句话**：三个「结构性上限」里，**只有深度那一条真的在 Krita 侧，且它不影响任何像素**；另外两条都是 UI/转换器自身的收边，属于「可修」而不是「结构性」。

## 三、hardMix 边界（1.03% / max 255）的定性与绕开

1. **PS 侧语义**：满覆盖笔尖时实色混合**恒为 255，与深度无关**（4 张阶梯纹理 + 3 张真实纹理，任意两张 0.00%/max 0）。这解释了为什么 PS 真值在该模式下是「不可判读的饱和图」。
2. **Krita 侧语义**：算子形式是 `mask + alpha×强度 > 1 ? 1 : 0`（严格大于）。阶梯纹理实测阈值逐点吻合：强度 0.6 时阈值落在灰度 102→104 之间（灰度 102 给 0），强度 1.0 时灰度 0 给 0、灰度 2 给 255。
3. **两种修法，代价不同**：

| 修法 | 效果（真实纹理，vs PS 真值） | 代价 |
|---|---|---|
| 现状（强度 = 深度/100） | d10 **95.33%**、d60 **52.44%**、d100 **1.03%** | — |
| 强度固定 1.0 | 三个深度均 **1.03%（103 px）** | 参数级，一行改动 |
| 强度固定 1.0 + 亮度偏置 +0.004 | 三个深度均 **0.00% / max 0** | 需要偏置符号随「反相」翻转；只在满覆盖笔尖口径验证过 |
| 预烘焙最终掩码 + 恒等算子 | 理论可全消 | 纹理字段在 Krita 里失去可编辑性；软边笔尖仍是逐像素烘焙 |

**结论**：hardMix 的 1.03% **可以绕开**，最省的做法是「强度固定 1.0 + 1/255 亮度偏置」；量产 A/B 与软边笔刷影响交 128A。

## 五、哪些结论是 B / C（如实标注）

- **B**：「depth>83% 的强度封顶无像素后果」——由「PS 高度系公式 12×q−u」+「d≥25 全饱和实测」两条推得，缺一条「d 在 17–25 之间的饱和点实测」。
- **B**：Krita 强度参数域为 [0,1]（源码显示强度会按选项声明域收边，但本轮未直接读到「纹理强度选项声明域 = (0,1)」那一行原文）。
- **B**：「Krita 纹理强度 = 属性值 × 曲线值（乘性）」——2 张单点实验（同曲线、压力 0.5、属性值 0.72 vs 1.0，均值比 0.7226）＋源码原文；依赖假设「曲线 `0,0.36;1,1` 在压力 0.5 处取 0.68」（线性插值）。
- **C**：PS 侧「最小深度」的作用点归属（参数地板 vs alpha 地板）。已写交接单，不作为终点。

## 六、决策项（每题独立，推荐项在第一个）

### 决策 1：纹理对比度的转换侧上限（`min(2.0, k)`）怎么处置？

1. **（推荐）删掉转换侧的 `min(2.0,k)`，k 原值直写** —— 利：C 最高可到 100 都能精确表达（本轮实测 0.00%/max 0），覆盖面直接变大；弊：预设里出现 >2.0 的对比度值，用户若在 Krita 笔刷设置里拖滑块会被 UI 夹回 2（需在发布说明里写明「不要用 UI 再编辑这两个滑块」）。
2. 保留 `min(2.0,k)`，把 C>50 登记为「Krita UI 上限」结构性残差 —— 利：不引入「UI 会夹回」的隐性坑；弊：明明可精确表达却登记为结构性，白丢覆盖。
3. 保留 clamp，但对 C>50 的笔在转换时给一条警告 —— 利：两边折中；弊：警告不能改善像素，只是知情。

**待使用者追认；本轮按推荐项执行（报告结论按选项 1 写）。**

### 决策 2：纹理深度 >83% 怎么登记？

1. **（推荐）登记为「Krita 参数域上限、像素无后果」，v0.14 不为它做预烘焙** —— 利：省掉一次注定拿不到改善的实验（PS 自身在 d≈17 就全饱和）；弊：「深度可以到 100%」这句在参数层不严格成立，需要在矩阵 note 里写清。
2. 照旧做 128A 的深度预烘焙 A/B —— 利：把「无后果」变成实测结论；弊：预计 2 小时只为证明一件 PS 自己都不支持的事。
3. 把高度系的映射从「强度 ×1.2」改成「改用非 Photoshop 高度算子（12/13 号）」—— 利：可能从根上对上 12:10 权重；弊：属新映射，需重新全量校准，超本轮范围。

**待使用者追认；本轮按推荐项执行。**

### 决策 3：hardMix 边界怎么处置？

1. **（推荐）按「强度固定 1.0」下发；亮度 +1/255 偏置作为 128A 的 A/B 变量** —— 利：把「取决于材料的 95%/52%/1.03%」变成「恒定的 1.03%」，再进一步可到 0.00%；弊：偏置是模式专属写法，需在 128A 验证软边笔刷不被它弄坏。
2. 只登记 1.03% 残差（保持现状）—— 利：零风险；弊：d<100 的真实偏差（95%/52%）被「1.03%」这个数掩盖，矩阵会低估问题。
3. 直接上「强度 1.0 + 偏置」全套 —— 利：本轮实测已 0.00%/max 0；弊：只验证过满覆盖笔尖，软边笔刷未验，风险未评估。

**待使用者追认；本轮按推荐项执行。**

### 决策 4：128A 的预烘焙实验变量怎么定？

1. **（推荐）改成「按 PS 相位预缩放图案 + Krita `scale=1.0`」** —— 利：直接对准真正的原因（重采样相位/核），200% 的 32.4% 才有希望降下来；弊：需要先确定 PS 的重采样核（本轮只证明了「相位差约 1 行」）。
2. 继续做「突破 200%/300% 的预烘焙」 —— 利：沿用原计划；弊：本轮已证明上限不存在，做出来也无法改善任何已入库的 50%/100% 达标点。
3. 放弃预烘焙，把 scale≠100% 登记为残差 —— 利：不再投入；弊：200% 的 32.4% 会长期留在矩阵里。

**待使用者追认；本轮按推荐项执行。**

### 决策 5（本轮新增）：最小深度的曲线换算要不要改？

1. **（推荐）改成「比值」写法：`commonCurve = 0, s_m/s_d;1,1;`**（`s_d` 为深度算出的强度、`s_m` 为最小深度算出的强度）—— 利：与「按深度线性抬地板」精确等价（证明见本地报告 §2.4），低压力端不再被二次打折；弊：需要一次全量回归确认没把 depth=100 的笔弄坏（那里本来无误差）。
2. 保持现状（绝对值写法）—— 利：零改动、零回归风险；弊：接了纹理深度动态的笔刷在低压力端明显偏淡，属静默错。
3. 只在 `depth<100` 的笔刷上改用比值 —— 利：改动面最小；弊：两套写法并存，后续维护容易再错。

**待使用者追认；本轮按推荐项执行。**

## 七、对 126 合表的关键提示（两条）

**第二条（次关键，属转换侧 bug）**：最小深度的曲线 0 端点写成了绝对值、而 Krita 是乘性 ⇒ 低压力端的「最小深度」被额外按深度打折（深度 50% 差 2 倍、10% 差 10 倍）。凡接了「纹理深度动态」的笔刷都受影响，需要在 v0.14 的映射批次里改成比值（详见本地报告 §2.4/§7）。

**`mode-table.json` 的 hardMix 行与本任务实测冲突**：该行写「转换侧无参数可修」，但本轮实测证明「强度固定 1.0」能把 d10/d60 的 95.33%/52.44% 拉回 1.03%，再加 1/255 亮度偏置可到 0.00%/max 0；且该行的 `diff_ratio=1.03%` 只是 d100 口径。合表时请把 hardMix 的 note 改为「边界残差（满覆盖口径 1.03%）+ 参数级可修（待 128A 软边 A/B）」，**verdict 本身不在本任务权限内，未改**。

## 八、人工验收怎么做（给使用者）

1. **对比度**：用任意带纹理的笔刷，PS 里把「纹理 > 对比度」设到 75 或 100，转换后在 Krita 里落笔；预期与 PS 观感一致（本轮机器判据 0.00%/max 0）。注意**不要**打开 Krita「笔刷设置」去拖对比度滑块（会被夹回 2）。
2. **深度**：把「纹理 > 深度」从 30 拖到 100，PS 与 Krita 都应**越深越接近全不透明**（这是饱和，不是丢参数）；预期在 25% 以上两边都已经是满 alpha。
3. **缩放**：把「纹理 > 缩放」设 300% 转换；Krita 里纹理应比 100% 大三倍（本轮两侧都执行），但图案边缘的锐利度会与 PS 略有差别（重采样差，非失败）。
4. **实色混合（hardMix）**：PS 里该模式在实心笔刷上本来就「几乎全不透明」；若 Krita 侧出现「黑块/空洞」，那是本报告 §三 的边界现象，请记录截图与笔刷名交回。
