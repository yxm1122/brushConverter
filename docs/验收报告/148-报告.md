## 一 口径：角度抖动的正式统计量（先定义，再在已知图上校验）

### 1.1 主统计量与算法

单 dab 的模板匹配角 θ（mod 360°，见 §1.2 算法）：

    δ = ((θ − β + 180) mod 360) − 180      # β = 该侧该档的旋转基线（见 §1.3）
    a_θ = ( q97.5(δ) − q2.5(δ) ) / 2 / 0.95   [度]      # 主统计量：角半跨度
    σ_θ = a_θ / √3                            # 等效角标准差（均匀分布）
    交叉校验：R̄（圆均值合成长度）、MAD（|δ| 中位数）、极差、D_KS（对整圈均匀的 KS 距离）

- 选 **a_θ** 而不是极差：均匀分布 [−a,a] 的 95% 质量区间宽 = 1.9a，除以 1.9 还原半宽，与任务 129/132 的散布档 a/D **同构**；
  极差在 n=40 时抽样方差太大（136 §4.2 A2 已登记），分位差估计量的相对标准误 ≈2·sqrt(q(1−q)/n)/1.9 ≈2.1%（n=121）、
  本任务每档 n=450（15×15 网格 × 2 次独立渲染）→ ≈1.1%，实测两样本复现 0–2.03%（§1.3 V3）。
- 理论值：a_θ = min(180°, 3.6°×j)（124 B 级：跨度 ≈7.2°/1%，j≈50 饱和成整圈）。

### 1.2 模板匹配求角（算法定义）

笔尖用**旋转非对称**采样笔尖（`tools/make_test_abr.make_asym_tip`：圆盘 + 左窄右宽楔形缺口 + 两个偏角不同的圆洞），
避免 124 遇到的两类失效（椭圆 mod 180 不可区分、近圆笔尖自检就散）。每个 dab：

1. 以网格期望中心为初值，窗口内按 alpha 加权求质心，切 128×128 补丁；
2. 模板 = j=0 图全部 dab 补丁的均值（同侧自建，PS/Krita 各一套）；
3. 粗搜 5°（向量化 NCC：n×72 矩阵乘）→ 在最优角 ±4° 内按 1° 精搜；
4. 输出 θ 与 NCC；NCC 只用于质量记录（F-6 未丢样本，ncc_min 0.855–1.000）。

### 1.3 已知图校验（`.tmp/random/148/validate.json`，模板取自真实 PS j=0 图）

| 校验 | 做法 | 结果 | 判定 |
|---|---|---|---|
| V1 唯一匹配 | 模板自相关：除 0° 邻域（±10°）外最大 NCC | NCC(0°)=1.0000；NCC(180°)=**0.0221**；±10° 外最大 **0.6841**（@11°） | 360° 唯一峰，无 180°/镜像歧义 |
| V2 已知角恢复 | 把模板按已知角旋转 + ±1px 位置抖动后喂回匹配器（7 个角 × 4 个补丁） | 最大角误差 **1.0°**；NCC ≥0.926 | 角度量测链有效 |
| V3 已知分布恢复 | 按 U(−a,a) 的已知角合成 225 个 dab（含 0.8px 高斯模糊），跑「补丁提取→匹配→a_θ」链，两组独立样本 | 对**同图经验真值**偏差 +2.04%/+0.24%/+0.24%（a=30/90/180）；两样本相对差 **0.00%/2.03%/1.68%** | 偏差 ≤2.04%、复现 ≤2.03%（均 ≤ 5% 判据） |

> V3 对**理论** a 的偏差是 +3.6%/+3.3%/+3.2%（含合成样本自身的抽样偏差，见 `validate.json` 的 `bias_pct`），
> 报告一律用「对同图经验真值」的偏差作为估计量偏差，避免把抽样噪声算进系统误差。

### 1.4 两侧基线 β 必须分开（本轮实测新增）

- **PS**：角度抖动围绕笔刷基准角（本夹具 Angl=0），β_PS = 0°（j=0 自检 225/450 dab 角度全 0、NCC=1.0000）。
- **Krita**：**只要旋转动态被启用**，中性点对应 **180°**（`KisRotationOption` 的 `value=1−value` 约定链，见
  `docs/研究报告/静态-形状颜色.md` §3.5.1 ③）。实测 `RotationValue=0.25` 的 dab 角度集中在 139°..221°（中心 180°、跨度 90°）。
  → β_Krita(j>0)=180°，j=0（动态关闭）=0°。
- 不区分基线会把「180° 偏移」当成整圈散布（第一版就得到 a_θ≈186° 的假饱和）；本报告所有 Krita 数值均按 β=180° 折算。

### 3.3 根因与修法候选（fuzzy + fuzzystroke 双加法源）

**根因链**（A 级：源码链 + 实测）：

1. `.kpp` 的 `RotationSensor` 里同时有 `fuzzy` 与 `fuzzystroke`，两者都是**加法型**（`KisCurveOption.cpp`：`if (s->isAdditive()) components.additive += valueFromCurve`），
   每个都给出 [−1,1]；叠加后 value 范围 [−2,2] 再按模 2 环绕 ⇒ **跨度 = 2×360°×R**，而 PS 是 360°×R（=7.2°×j）。
2. 实测（同构装置，只改传感器构成，`.tmp/random/probe_rot/` + `fix_candidate.json`，每档 225 dab）：

| 装置 | 档 | Krita a_θ(°) | 理论 360°×R | PS a_θ(°) | 相对差 |
|---|---|---:|---:|---:|---:|
| 只留 fuzzy | R=0.25（j=12.5） | **43.16** | 45.0 | —（未测） | −4.09% vs 理论 |
| 只留 fuzzy | R=0.50（j=25） | **87.26** | 90.0 | 92.51 | **−5.84% → PASS** |
| 只留 fuzzy | R=1.00（j=50） | **174.11** | 180.0 | 179.00 | **−2.77% → PASS** |
| 只留 fuzzy | R=1.00（j=100） | **174.11** | 180.0 | 177.54 | **−1.95% → PASS** |
| fuzzy+fuzzystroke（现产物） | R=0.50（j=25） | 149.58 | 180（饱和） | 92.51 | **+47.14% → FAIL** |

3. 结论：**现映射（134-2 的 `R=min(1,j/50)` 本身没错）错在多带了一个加法随机源**；去掉 `fuzzystroke` 即可让 j<50 与 PS 对齐。
   PS 的 `angleDynamics` 是**逐 dab** 随机、没有「整笔同随机」这一层，`fuzzystroke` 属于 Krita 独有效果，不应出现在这一档。

### 3.4 判据结论（F-6）

- **现映射**：j=50/100 达标（−1.88%/+2.05%，复现 ≤1.17%）；**j=25 不达标（+38.20%）** ⇒ 现产物在 j<50 的旋转抖动**幅度约为 PS 的 2 倍**（提前饱和）。
- **修法候选**：只留 fuzzy ⇒ 三点全部达标（−5.84%/−2.77%/−1.95%，复现 ≤2.03%）；
  修法只需改 `src/brush_converter/kpp/preset_xml.py` 的 `_fuzzy_random_sensor()`（本轮不改 src/，交 156/157 与下一轮）。
- 影响面：所有带 `angleDynamics.jitter>0` 的 `.kpp` 在 j<50 时旋转幅度偏大；j≥50 不受影响（两侧都饱和）。旧 `.kpp` 需重转。

### 4.3 F-7 结论

- **PS 语义 A 级定死**：5 = 整笔固定在**初始段方向**（不是基准角 0°：VH 形状整笔 90°、DD 整笔 45°）；6 = 逐段跟随**当前**笔划方向。
- **Krita 承载**：6→drawingangle **等价成立**（拐角角差 ±90.0°，与 PS 同）；5 无承载（结构性登记不变）。
- 124/126 的 C 级推断「5=整笔固定、6=逐点变化」被实测证实，并补上「5 的固定值是**初始段方向**」这一此前未定的细节。

## 六 副产物（登记给 150/156/157，不属本任务结论）

1. **Krita 旋转基线 = 180°**：旋转动态启用后，中性 `RotationValue=0` 对应 180°（`KisRotationOption` `value=1−value`）。
   对**非对称笔尖**这是可见的 180° 朝向差；对椭圆（mod 180）不可见。→ 若后续做「非对称笔刷的旋转承载」，必须折算 180°。
2. **椭圆计算笔刷的 dab 步长基准两侧不同**（实测）：
   - PS：步长 = Spcn% × **短边**（Rndn/100·D）。实测 Spcn=150% ⇒ 29.9px（=1.5×19.9），与笔划方向无关（水平/垂直段都 160px @Spcn=800%）。
   - Krita：步长 = spacing × **笔尖在笔划方向上的投影**。实测同一张图水平段 160px、垂直段 32px（spacing=1.6）。
   ⇒ 用单一 spacing 常量无法同时对齐两种朝向的 dab 密度；转换器现有「计算笔刷 spacing=Spcn/100 直写」在斜向段会偏（PS 30px vs Krita 150px，5 倍）。
   本任务为让两侧在水平段同密度，PS 取 Spcn=800%、Krita .kpp 写 spacing=1.6（=800%×0.2）。**该条属 B4（椭圆 spacing 基准）**，交 150/156 复核。
3. **PS 的 angleDynamics 随机是确定性序列**（两次独立会话像素完全相同）→ 后续同类实验可用「一次渲染」省时；但不得据此推断 Krita 也确定。
