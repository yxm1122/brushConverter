## 一、结论

1. `kritarunner.exe` 能把 Krita 内核拉起来：`Krita.instance()` 非空、`createDocument` 成功、资源库读到 137 个预设（退出码 0）。
2. 但**无法建立画布视图**：`Window.addView()` 必崩，进程退出码 `-1073741819`（= `0xC0000005` 访问违例），
   probe4 / probe7 / probe11 三次独立尝试 100% 复现；`openWindow()` 返回的窗口 `show()` 同样崩。
3. Krita 的落笔接口 `Node.paintLine()` 在源码里硬依赖「当前主窗口 → 当前视图」
   （`libs/libkis/PaintingResources.cpp`：`KisPart::instance()->currentMainwindow()->activeView()`），
   而 kritarunner 里 `windows=0 / activeWindow=None`，实测调用即访问违例（probe8）。
4. 附带硬约束：**没有「按 .kpp 文件路径加载预设」的 Python API**（`Resource` 只能来自资源库）；
   实测 137 个预设中匹配本项目转换产物的数量 = **0**。
5. **路线 A（追加实验）证明 GUI 会话里 `addView`/`paintLine` 完全可用**：真实 Krita 进程 + 临时启动插件，
   透明画布落笔 → PNG，单支 11–14 秒，**Alpha 非零像素 3348（落笔前为 0）**；配置临时改动已实测还原。
   证据见 [研究报告 §九](../研究报告/krita-runner-可行性.md)。

## 七、路线 A 追加实验（摘要）

- 做法：临时装 PyKrita 启动插件 + 临时改 kritarc（启用插件、`sessionOnStartup=2`）+
  临时复制 `.kpp` 进 `paintoppresets` → 启动 `krita.com --nosplash` → 插件等主窗口 →
  `addView` → 透明画布 → `setCurrentBrushPreset` → `paintLine` → `projection()` 存 PNG → 关文档退出 → `finally` 还原。
- 结果：**成功**；单支 10.995 s，PNG 200×200，Alpha 非零 3348；批量 6 支 6/6 成功（首轮）。
- 原始日志与清理核对见 [研究报告 §九](../研究报告/krita-runner-可行性.md)。
