## 一、任务结论

✅ **完成（范围内）**。散布域的**散布子对象**（预设对象 +0xd8，0x50 字节）与传递域的**四个动态子结构**（prVr / opVr / mxVr / wtVr，各 0x14 字节）**全部定位到偏移、类型与 clamp**，每个字段都有指令地址级证据；三条经验值**逐条**给了 成立 / 不成立 / 无法判定 与证据；末尾有 8 条可直接交给 v0.3 的待验清单（函数 + 要读的偏移）。

三条经验值的结论：

| 经验值 | 结论 | 一句话证据 |
|---|---|---|
| ScatterValue = jitter/400 | **不成立（作为 PS 内部关系）**；作为跨引擎标定 **无法判定** | PS 链路 5 个函数里没有任何 400 / 0.0025 / 2.5 运算，jitter 换算只有乘 100 除 100 恒等（0x141a93f7e / 0x141a93f82）；jitter 是 0..1000 百分数、Krita ScatterValue 是 0..5，全量程线性应为 ÷200 |
| PressureScatter 只是散布启用开关 | **成立**（限定：压感在 bVTy，不在启用位） | useScatter 在 +0x00，且键缺失时由（散布量非 0）或（count 大于 1）推出（0x141a93272–0x141a93286）；控制源是 scatterDynamics.bVTy（+0x24） |
| bVTy 0=关 / 2=压力 / 6=初始方向 | **0 成立、2 成立、6 不成立（6=Direction 笔迹方向，初始方向=5）** | 9 条 BrushDynamics 名串（0x1486749e8…0x148674b30）＋ 0x141fac800 里 9 个 cmp / mov 赋值（0x141fac9aa–0x141faca19） |

另外回答了任务书 ④ 的两问：
- **散布与间距**：静态支持**分别作用**（独立键 / 独立槽位 / 独立 clamp / 链路无合成），但**消费端未定位**，只能算结构层结论；
- **压感曲线**：**.rdata 里没有 256 点等距表（0 命中）**；1024 点递增数列的 3 处命中是同一段且**无代码引用**；子结构里也没有曲线 / LUT 指针，倾向**解析式**，但求值点未定位，判 **无法判定**。

## 五、遗留与风险（含本任务未做的事）

1. **消费端全空白（最大风险）**：研究报告 §6「散布与间距分别作用」与 §7「倾向解析式」都只是**结构层**结论。**未定位**画刷引擎里摆 stamp 的代码（尝试过绝对位移机器码扫描，583–14,216 条/键，全是栈访问噪声）。**风险**：v0.4 若把「分别作用」当已证实行为直接实现，前提未验证。**规避**：研究报告 §9 的 V4 / V5 两条硬件写断点即可闭环（x64dbg 第二轮已确认可用）。
2. **dynamics 子结构 +0x0c（jitter 的 clamp 上界）找不到赋值点**（U1）：读写两侧都不写它。**副作用**：jitter 的有效上限只能靠动态读，静态给不出「散射量上限是 1000 还是 100」。V2 一条断点可解。
3. **Opct / flow 基值只到描述符 double 一级**（U2）：传递域的「不透明度 / 流量基准值」**没有**落到内存偏移，报告如实写未定位，**没有**为凑表把它写进主表。下游若要做「PS 不透明度 → Krita Opacity」，这条必须补（需 Ghidra 伪代码做跨函数数据流）。
4. **scatter 与 scatterDynamics.jitter 同槽位**（研究报告 §3.2）：这是**参数层面**的实质发现，与任务 24 的 I-3（同一参数两行）同类。**本任务未改矩阵**——docs/参数矩阵.json 属任务 23 / 29 的写入范围，登记给汇合复核。
5. **新键 brVr 未进 ps_keys.json**：125 条清单里没有它。是否补由任务 29 决定，本任务只登记。
6. **「bVTy 就取这 9 个枚举值」是高置信推断而非硬证据**：枚举表本身是硬证据（两处函数 + 9 条名串 + 用 0..8 索引该表的指令），但「bVTy 读出来后送进这张表」的那一条数据流指令未定位（U3）。缓解：ABR 实测 bVTy 取值 0/2/5/6 全落在 0..8，且 2 与 6 与枚举一致。
