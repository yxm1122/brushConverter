# 验证体系使用说明（验证入口与隔离）

> 说明：本机路径以 `<LOCAL_APP_DIR>`、`<REPO>` 占位。先核验本次解释器与工作区，不把旧任务的路径或用例数当运行环境。
>
> 回归、参数级、像素级等测试共享pytest入口；[三层验收](<全量验收说明.md>)另按参数/像素/手感选择。本文解释选择与摘要契约，隔离准备以[开发指南](<developer-guide.md#maintenance-checks>)为准。

## 1. 最短用法

**先隔离，后运行。** 按开发指南§9.1核验Python3.12+并设置 `$PY`、全新工作区 `$RUN`、TEMP/TMP及缓存/配置。下例依赖这些变量；路径未核验、工作区不是全新目录、或运行超出本次授权时停止。

`python -m pytest -q` **不是“只跑旧回归5个文件”**：默认收集完整测试目录，轻量插件给所有用例补verify标记，其中包含GUI/集成测试和可能启动Krita真实渲染的用例。`-m verify` 同样不保证无GUI/应用副作用。只想跑合成检查时应明确指定安全测试文件，不从绿灯推断已经做全量或人工验收。

```powershell
# 定向合成检查示例，不启动Krita/PS；磁盘夹具只用全新工作区.tmp。
& $PY -B tools/verify_entry.py tests/test_full_verify.py --basetemp (Join-Path $RUN 'pytest') -o ('cache_dir=' + (Join-Path $RUN 'pytest-cache'))
```

需要真正全量时，先确认允许GUI/应用副作用与串行运行，再去掉示例中的定向文件参数；保留basetemp/cache参数及全部环境隔离。直接用pytest也必须带相同隔离，不能只运行未隔离的全量命令。三层工具的子进程配置及写操作边界见[全量验收说明](<全量验收说明.md#1-怎么跑>)。

摘要格式固定（字段顺序、文字与全角竖线不可改）：

```text
通过 N 项 ｜ 失败 M 项 ｜ 跳过 K 项
```

有跳过时追加 **（含跳过，未全验）**，并逐条列出“文件名::用例名 — 跳过原因”。摘要可按格式匹配，但**不承诺位于整个进程的最后一行**；不同入口可能随后打印明细、环境或输出路径。

## 2. 三种退出码

下表是 `tools/verify_entry.py` 及三层汇总器的**包装入口**口径；直接pytest的原始退出码还应查其自身输出，不能混为一套。

| 退出码 | 含义 | 见到它该做什么 |
|---|---|---|
| 0 | 选中用例通过；可能有跳过 | 看跳过明细；有跳过仍未全验 |
| 1 | 有失败或包装器判定pytest异常 | 先读原始失败/错误，核代码、环境和独立期望，不能抄当前产物改绿 |
| 2 | 无法取得有效收集/统计结果 | 核pytest配置、选中路径、标记及原始报错 |

**跳过K永远不计入通过N。**

## 3. 仓库根只有一个 pytest 配置文件

- `pytest.ini` 注册verify / verify_params / verify_pixels，默认testpaths为tests。
- `addopts = -p tools.verify_entry` 加载轻量汇总插件，给**所有收集到的用例**补verify标记；不是只选择某几个历史回归文件，也不是跳过GUI的隔离开关。
- 插件不掩盖跳过；`-p` 的含义是加载插件，不等于 `-p no:cacheprovider` 之类禁用选项。测试数随代码/数据变化，以当次收集为准。

## 4. 跳过为什么发生、怎么补

| 触发条件 | 摘要里的原因 | 补法 |
|---|---|---|
| 自备商用ABR样本不在 | 缺少测试样本.abr | 按原测试要求在指定位置提供有权使用的只读样本；跳过项数以当次收集为准 |
| 参数比对源ABR不在 | 缺少测试用.abr | 提供约定源文件，不能用当前输出倒造输入 |
| 基准图或目标应用不可用 | 具体缺端原因 | 核来源与运行授权后补齐；不要用别的图顶替，也不据此擅自安装或启动应用 |

商用素材只读，不改、不删、不提交。隔离环境和自备素材缺失时的绿不是交付依据。

## 5. 命令细节（排查用）

- 看跳过原因时用 `-rs`；参数/像素选择为 `-m verify_params` / `-m verify_pixels`，仍保留第1节全部隔离。
- 汇总器把额外参数透传pytest：可显式给测试文件、basetemp与cache_dir；选择少量用例后的摘要只代表这些用例。
- 修改运行范围前先查相关测试是否写固定路径、启动GUI或子进程。不能证明只读/隔离时停止，不用“参数级”之名推断没有副作用。

## 6. 新增比对怎么挂到 verify 标记上

1. 新测试文件命名为 `test_*.py`；磁盘夹具只进全新工作区 `.tmp`，真实样本/基准只读。
2. 显式verify标记更清楚；verify_params / verify_pixels可叠加，未显式写verify时插件也会自动补。
3. 新标记先注册，不为凑通过降低阈值或屏蔽跳过。
4. 用第1节隔离方式先定向跑新增测试；全量由有授权的主会话串行执行并如实记录。

## 7. 参数级比对怎么用（任务 02）

先按第1节完成环境隔离，再明确选择：

```powershell
& $PY -B -m pytest -m verify_params -q -s --basetemp (Join-Path $RUN 'pytest') -o ('cache_dir=' + (Join-Path $RUN 'pytest-cache'))
```

原始golden比对会先将约定ABR转成临时KPP，再按独立期望表逐字段核验；它只是参数层的一部分，不把当时“6支×28字段”当所有现行测试的规模。

**独立期望**：[参数期望表](<../tests/golden/params_expected.json>)中各支核spacing/angle_deg/scale/size，适用时核散布/轴向等；每项保留来源与手算公式。禁止从当前产物反抄期望。

新增比对先读源ABR值，按[参数参考](<parameter-mapping.md>)手算，把算式及适用条件连同期望保存，再用隔离测试验证。spacing容差为±0.001；原golden数值默认1e-3，布尔/枚举严格相等；其它定向用例按各自独立判据，不静默统一放宽。

失败信息包含笔刷名、字段、期望、实际、差值；先调查差异，不将失败一律归为可接受残差。

## 8. 像素级比对怎么用（任务 03）

同样先隔离，再明确选择：

```powershell
& $PY -B -m pytest -m verify_pixels -q -s --basetemp (Join-Path $RUN 'pytest') -o ('cache_dir=' + (Join-Path $RUN 'pytest-cache'))
```

[imgdiff.py](<../tools/imgdiff.py>) 的 `diff_alpha(a,b,tol=2)` 返回尺寸、差异像素、比例和最大差值。差异点为Alpha差值>tol，分母为全部像素 `width*height`；尺寸不同报错，不自动缩放。

`passes(result)` 默认差异比例≤2%，但这是工具默认值，不替代各跨引擎/几何/随机专项判据。PS纹理历史PNG的信息在Alpha，相关测试不比较RGB；不把这一口径推广到所有素材。

新增图先按[命名规范](<基准库命名规范.md>)确认来源/标识/模式/参数与独立期望，在获准的新任务目录验证。清单来源为ps/krita/handmade/feel四源；新增真实基准和清单合并是单独写入事项，见[合并边界](<全量验收说明.md#5-清单合并feel--顶层-manifest>)，不能借加测试无条件回写。

实测参考：4×3与2×5图比对报尺寸不一致；原“改3像素、差异比例3/4096”只作工具算式示例，不当本次重跑证据。

## 9. 已知边界

- 摘要只统计实际选中的用例；verify标记不保证无GUI/应用或文件写入。
- 缺样本、缺端、跳过与未授权真实操作都如实登记，不用机器解析代替人工效果验收。
- 历史验收报告是一份一次性结果，不维护旧数字；本页命令与当前实现对齐也不表示历史报告需要回写。
