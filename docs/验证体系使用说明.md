# 验证体系使用说明（brushConverter v1.2.0）

> 说明：本文档里的本机实测路径已占位化（`<LOCAL_APP_DIR>` = 本机软件安装目录，`<REPO>` = 仓库根），复现时请改成你自己的安装路径与仓库路径。

> 三层验证：回归（现有测试）→ 参数级（.kpp 字段）→ 像素级（Alpha 差异）。
> 本文件是唯一入口说明，命令与口径都以这里为准。

## 1. 最短用法

\`\`\`bash
# 全量验证 + 固定格式摘要（推荐入口）
"<LOCAL_APP_DIR>/anaconda3/envs/brushConverter/python.exe" tools/verify_entry.py

# 只让 pytest 跑全量验证（pytest 输出末尾也会打一行同格式摘要）
"<LOCAL_APP_DIR>/anaconda3/envs/brushConverter/python.exe" -m pytest -m verify

# 只跑回归基线（现有 5 个测试文件）
"<LOCAL_APP_DIR>/anaconda3/envs/brushConverter/python.exe" -m pytest -q
\`\`\`

摘要行固定为（字段顺序与文字不可改，后续任务按它解析）：

\`\`\`
通过 N 项 ｜ 失败 M 项 ｜ 跳过 K 项
\`\`\`

有跳过时行末追加 **（含跳过，未全验）**，随后逐条列出「文件名::用例名 — 跳过原因原文」。

## 2. 三种退出码

| 退出码 | 含义 | 见到它该做什么 |
|---|---|---|
| \`0\` | 全部通过；或全部通过但有跳过（摘要带「（含跳过，未全验）」） | 看摘要末尾有没有跳过提示；有就按第 4 节补样本 |
| \`1\` | 有失败（含用例报错 / pytest 异常中断） | 看「失败明细」与 pytest 输出尾部，修代码或修期望值 |
| \`2\` | 一次都没收集到用例（标记没注册、路径写错、收集阶段就炸了） | 先确认 pytest.ini 在、verify 标记已注册，再单独跑 pytest 看报错 |

**跳过 K 永远不算进通过 N。**

## 3. 仓库根只有一个 pytest 配置文件

- \`pytest.ini\`：注册 \`verify\` / \`verify_params\` / \`verify_pixels\`，\`testpaths = tests\`。
- \`addopts = -p tools.verify_entry\` 把汇总器当轻量插件加载，由它的收集钩子给**所有用例**自动补
  \`verify\` 标记——现有测试文件一行都不用改。这里的 \`-p\` 是加载插件，不是 \`-p no:cacheprovider\` 那类屏蔽。

## 4. 跳过为什么发生、怎么补

| 触发条件 | 摘要里的原因 | 补法 |
|---|---|---|
| \`tests/海怪笔刷-详情展示的勾线笔套装组18支.abr\` 不在 | 「缺少测试样本 .abr（请自备到 tests/ 目录）」 | 放回 \`tests/\`（22 项会跳） |
| \`tests/测试用.abr\` 不在 | 「缺少测试用.abr」 | 放回 \`tests/\`（1 项会跳） |
| \`research/krita结果/...\` 基准图不在 | 「缺少基准图 ...」 | 项目自带该图；缺了从版本库恢复，不要用别的图顶替 |

样本是 42MB 商用素材，**只读**：不改、不删、不提交进 git。

## 5. 命令细节（排查用）

- 看跳过原因原文：\`python -m pytest -m verify -q -rs\`
- 只看参数级 / 像素级：\`-m verify_params -q\` / \`-m verify_pixels -q\`
- 汇总器参数原样透传给 pytest：\`python tools/verify_entry.py tests/test_mapping.py\`

## 6. 新增比对怎么挂到 verify 标记上

1. 新测试文件放 \`tests/\`，文件名 \`test_*.py\`；
2. 文件顶部写 \`pytestmark = pytest.mark.verify\`（专用标记 \`verify_params\`/\`verify_pixels\` 可叠加；
   不写也会被插件自动补，但显式写更清楚）；
3. 新标记先在 \`pytest.ini\` 的 \`markers =\` 段注册，禁止未注册标记；
4. 跑 \`python tools/verify_entry.py\` 确认 N 增加且没有意外跳过。

## 7. 参数级比对怎么用（任务 02）

\`\`\`bash
"<LOCAL_APP_DIR>/anaconda3/envs/brushConverter/python.exe" -m pytest -m verify_params -q -s
\`\`\`

先把 \`tests/测试用.abr\` 真实转成临时 \`.kpp\`，再逐字段核对期望值表；\`-s\` 显示规模行
「参数级比对规模：6 支笔刷 × 28 个字段（容差 0.001）」。

**期望值表**：\`tests/golden/params_expected.json\`。每支笔刷必核 \`spacing\`/\`angle_deg\`/\`scale\`/\`size\`，
有散布的另记 \`scatter_value\`/\`scatter_use_curve\`/\`axis_x\`/\`axis_y\`；每条必须带 \`_source\`
（\`参数表公式\` 或 \`手工核对：<文件名>\`）与 \`_source_detail\`（逐字段算式）。
**禁止**把当前产物抄进期望表——那样比对永远不会变红。

**加一支新笔刷**：① 读 ABR 源值（\`Brsh.Dmtr\`/\`Brsh.Spcn\`/\`Brsh.Angl\`/笔尖宽高/\`scatterDynamics.jitter\`/\`bVTy\`/\`bothAxes\`）；
② 按 \`docs/parameter-mapping.md\` 第 1、5 节公式手算；③ 连算式写进 JSON；④ 跑一遍确认通过且字段数增加。

**容差**：\`spacing\` ±0.001（任务书要求）；其余数值统一 1e-3（XML 用 \`%g\` 最多 6 位有效数字）；
布尔/枚举严格相等。定义在 \`tools/kpp_params.py\` 的 \`DEFAULT_TOL\`。

**失败信息**（五项齐全，一次列完）：\`[笔刷名] 字段 spacing 期望 0.05 实际 0.18（差 0.13）\`
，顺序是「笔刷名 / 字段 / 期望 / 实际 / 差值」。

## 8. 像素级比对怎么用（任务 03）

\`\`\`bash
"<LOCAL_APP_DIR>/anaconda3/envs/brushConverter/python.exe" -m pytest -m verify_pixels -q -s
\`\`\`

核心：\`tools/imgdiff.py\` 的 \`diff_alpha(path_a, path_b, tol=2)\`，返回 \`width\`/\`height\`/\`diff_pixels\`/
\`diff_ratio\`/\`max_delta\`。差异点 = Alpha 差值 > tol 的像素；\`diff_ratio = diff_pixels/(width*height)\`，
**分母是全部像素**，不是非零像素数。尺寸不同直接 \`ValueError\`（异常里带两个尺寸，本版不缩放）。
判据：\`passes(result)\` 默认**差异比例 ≤ 2% 视为通过**（\`DEFAULT_RATIO_THRESHOLD = 0.02\`）。

**只看 Alpha 的原因**：PS 纹理导出 PNG 的 RGB 全黑，纹理信息在 Alpha；本版不比 RGB。

**加一张新基准图**：① 产出 RGBA PNG，按 \`docs/基准库命名规范.md\` 命名
\`<来源>__<笔刷或参数标识>__<模式>__<关键参数>.png\`；② 放进 \`tests/baselines/ps|krita|handmade/\`；
③ 在该子目录 manifest 登记（顶层 manifest 由任务 09/15 合并）；④ 加「与自身比差异 0」的用例；
⑤ 单张 ≤ 2MB，超了按命名规范第 4 节放本机、manifest 记路径与哈希。

实测参考：改 3 个像素 → \`差异 3 像素、比例 3/4096 = 0.000732、最大差值 215\`；
尺寸不同 → \`ValueError: 尺寸不一致：A=4x3, B=2x5\`。

## 9. 已知边界

- 摘要只统计 \`-m verify\` 选中的用例；\`-m "not verify"\` 之类过滤不在入口范围内。
- 结论只代表「这次跑的结果」；样本缺失时的绿必须按第 4 节补证据，不能当交付依据。
