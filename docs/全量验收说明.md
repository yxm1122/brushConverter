# 全量验收说明（任务 15 · verify_all）

> 说明：本文档里的本机实测路径已占位化（`<LOCAL_APP_DIR>` = 本机软件安装目录，`<REPO>` = 仓库根），复现时请改成你自己的安装路径与仓库路径。
>
> 工具：[verify_all.py](<../tools/verify_all.py>)。依次跑「参数层 → 像素层 → 手感层」（**严格串行**），打印总表与固定格式摘要，并支持归档和显式清单写入。它不是全部 pytest 的替代，也不是纯只读命令。

## 1. 怎么跑

先按[开发指南的工作区隔离规范](<developer-guide.md#maintenance-checks>)核验 Python 3.12+，在全新工作区目录设置 $PY、$RUN、TEMP/TMP、缓存与配置；不能证明隔离或没有本次运行授权时停止。以下 PowerShell 片段依赖上述设置，不能单独复制到未隔离环境执行。

```powershell
# pytest 子进程继承该配置；路径加引号以支持空格。
$env:PYTEST_ADDOPTS = '--basetemp="{0}" -o cache_dir="{1}"' -f (Join-Path $RUN 'pytest'), (Join-Path $RUN 'pytest-cache')
# 仅在本次允许三层测试及版本探测时运行；0=通过/可含跳过，1=失败/异常，2=未收集。
& $PY -B tools/verify_all.py
# 可选：只把本次结构化结果写入本任务目录，单层超时默认900秒。
& $PY -B tools/verify_all.py --json (Join-Path $RUN 'verify.json') --timeout 600
```

- `--archive` 会**新增**时间戳验收报告，只有明确获准写该目录时才用；不会维护、改写已有一次性报告。本次文档修复不运行归档。
- `--selftest-failure` 会在 `tempfile` 解析出的目录创建并清理合成失败用例；只有已核实 TEMP/TMP 落在全新工作区时才能运行。
- **不要把 `--merge-manifest` 当作例行验证开关**：它是写操作，目标默认是真实顶层清单；先在副本验证，再取得对真实清单的明确应用授权，见第5节。
- 发版前的三层结果须记录通过/失败/跳过；退出0但有跳过仍是“含跳过，未全验”，不能仅看“失败0”放行。

## 2. 三层分别跑什么

| 层 | 实际选择 | 发布前快照用例数 | 关键指标列 |
|---|---|---|---|
| 参数层 | `pytest -m verify_params` | 192 | 用例数与通过数 |
| 像素层 | `pytest -m verify_pixels` | 34 | 用例数与通过数 |
| 手感层 | `pytest tests/test_feel_curve.py` | 9 | feel 基线条数、自比 max dev、压感是否真实注入 |

上表是 **2026-11-27 v1.6.0 发布前验收快照（合计235）**，不是硬编码的未来“当前总数”，也不是本次修复重跑结果；新增测试后以当次收集与摘要为准。手感层直接读 feel 清单及曲线做自比；缺基线如实 skip，不算通过。完整 pytest 范围及应用副作用见[验证入口说明](<验证体系使用说明.md>)。

## 3. 输出格式（脚本可解析）

总览部分的顺序是：表格 → 失败明细 → 跳过明细 → 分隔线 → **固定格式摘要行**。主流程随后继续打印运行环境，以及可选的归档、合并、JSON路径，**摘要不保证是整个进程的最后一行**。解析器应匹配格式，不要使用“只取末行”的假设。

摘要复用 [verify_entry.py](<../tools/verify_entry.py>) 的 `build_summary` 契约：

```text
通过 N 项 ｜ 失败 M 项 ｜ 跳过 K 项
```

“｜”是 U+FF5C 全角竖线；有跳过时追加“（含跳过，未全验）”，**跳过不计入通过**。指定 `--json` 可读取结构化 `summary` 字段，文件也属于显式写入。

| 退出码 | 含义 |
|---|---|
| 0 | 选中用例通过；可能含跳过，须看摘要 |
| 1 | 任一层失败，或 pytest 异常/超时 |
| 2 | 三层一条用例都没收集到（标记/路径配置坏了） |

## 4. 归档文件

- `--archive` 在验收报告的归档子目录新增 `verify-<YYYYMMDD-HHMMSS>.md`；同秒重名加 `-2`、`-3`，不覆盖历史。归档位置是工具固定输出，须先核写入权限及任务范围。
- 头部记录时间、命令、退出码、摘要；主体四节为总览、失败、跳过、运行环境。
- 环境三项自动采集：Python、Krita版本进程探测、Photoshop文件版本；无法采集写“未检测到”。**版本探测本身也可能启动子进程**，不等于整条命令无应用/环境副作用。
- 一次性历史报告保留原始数据，不因当前规则变化而回写旧报告。

## 5. 清单合并（feel → 顶层 manifest）

**显式写操作，默认不执行。** CLI 的 `--merge-manifest` 会在本次测试后处理真实顶层清单，并不是 dry-run，也不会因为“无新增”就跳过所有结构检查。不要为检查文档、验证通过或修复统计而无条件运行它。

安全顺序：

1. 在全新 `.tmp` 任务目录准备完整副本，保留顶层清单、feel子清单及其PNG的相对布局，记录原件摘要；不要让副本路径指向真实基准。
2. 先跑[合成回归](<../tests/test_full_verify.py>)。需要检查具体副本时，使用函数的两个显式路径参数，**不省略参数**：

```powershell
# $COPY 必须指向本任务隔离副本，且其两个manifest和相关PNG已经准备好。
& $PY -B -c 'import json,sys; from tools.verify_all import merge_feel_manifest; print(json.dumps(merge_feel_manifest(sys.argv[1],sys.argv[2]),ensure_ascii=False))' (Join-Path $COPY 'manifest.json') (Join-Path $COPY 'feel/manifest.json')
```

3. 检查新增/迁移数量、逐项差异、四源计数与旧条目保留；重复调用应 `changed=false`，副本字节和mtime均不变。
4. 只有明确授权**应用到真实清单**后，才使用默认目标的CLI开关；预先保留原件并复核输出。它不代替素材许可、隐私门或发布批准。

现行规则：

- 合并键是顶层 `file` 相对路径。已有项不重复添加；新增项为 `source=feel`，固定11字段，`alpha_nonzero` 从实际PNG测量，不抄子清单登记值。
- 正式来源为 **ps / krita / handmade / feel**。`counts.total` 等于四源分项之和；`sources` 各来源数量按**实际顶层条目**计数，不拿整个feel子清单长度冒充已合并数。
- 旧三源合并结果只把 `file` 前缀为 `feel/` 且 `source=krita` 的条目迁移为feel；不移动PNG，不改其它字段，不重排条目，也不重写旧 `merge_history`。未知来源报错，不静默漏计后写出。
- 新增、迁移或当前统计修复才写文件并追加一条本次历史；四源内容/统计已一致时完全不写，时间戳、历史、字节和mtime均保持不变。
- 发布前现状快照为 **341 = 298(ps) + 29(krita) + 2(handmade) + 12(feel)**；修复工具不意味着重新生成真实清单。回归用例使用相同规模的合成副本，是否运行及结果须另记，不能从用例存在推断通过。

任务15早期曾把 `feel/` 条目归作krita，与目录前缀及组装检查冲突。当时“失败2项、跳过1项”仅是该阶段记录，**不是现行待办或预期失败数**。后续已经采用feel正式来源的四源方案；现行顶层清单及组装检查按四源对账，旧三源 `--merge-manifest` 实现本次也已适配。

历史报告保持原文，不回填“通过”或改写当时数字；旧合并结果需迁移时仅在副本测试、明确授权应用后处理，规则见第5节。

## 7. 失败时先看哪一层

先看摘要失败/跳过，再看明细定位用例；单层复跑也须继承第1节的解释器、临时目录、basetemp和cache隔离，且不得与其它pytest并发。

```powershell
& $PY -B -m pytest -m verify_params -v
& $PY -B -m pytest -m verify_pixels -v
& $PY -B -m pytest tests/test_feel_curve.py -v
```

## 8. 并发约束（重要）

- 三层严格串行，同一时刻一个pytest；不要同时再启动全量或其它测试。
- 真正启动Krita GUI渲染的独立用例不在三层选择内，但完整pytest可能包含它们。应用/渲染须单独授权并串行，不能因文档给了命令就启动。
- 手感层只读基线图与曲线JSON；主流程仍会自动采集环境，见第4节。

## 9. 人工验收步骤

1. 核验工作区隔离与运行范围后，检查三层总表、可解析摘要及环境；不要假定摘要是末行。
2. 若本次获准新增归档，再启用 `--archive`，检查新文件名不覆盖旧记录。
3. 若需失败路径自检，在隔离临时目录中启用 `--selftest-failure`，检查失败明细和非零退出。
4. 合并幂等性只先在全新合成/复制目录验证；真实清单应用是独立写操作。本次不改任何真实基准或历史报告。
